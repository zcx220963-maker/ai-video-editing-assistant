## 0. 一句话结论

图形科普片这条链**整体换成 Remotion**：模型逐镜交 React/TSX 代码，由新增的 `creation-remotion` 容器逐帧渲染成镜粒度切片；旧声明式链（22 种卡型、七种内置图示、四族画笔、theme/overlay 两栏、字段级 pointer）**全部删除**；跨镜一致性从"共用模板的结构保证"改由**母版 Composition + 七道闸**事后拦回（迁移当时是五道，§12 加闸⑥、2026-10-11 加闸⑦）。口播链与母带层一行不动。

新链买到的是**表达上限**（模型能画出任何形状，不再受我预先写好的卡型限制），代价是旧链那种"点中元素改一个数值"的可编辑性。
**§12 把这条代价补回来**：镜头代码把可改的东西声明成 `fields` 并从 props 读，母版回读它们实际生效的取值与画面盒，于是编辑粒度重新落到"字段"而不是"整段代码"。闸因此从五道变六道（新增**闸⑥ 字段级对账**），再到七道（新增**闸⑦ 整片风格配额与文案两半**）。

## 1. 触发点与决策链（把推翻过的东西留档，免得下次重新吵一遍）

### 1.1 触发

用户发来一段 6 分 21 秒的解读片（`微信视频2026-10-10_095655_736.mp4`，1920×1080，含音轨）。逐帧读下来它讲的是"Opus 5.5 做视频"的技术底座，结论页自己写了分工：

| 组件 | 负责 |
| --- | --- |
| **Remotion** | 总体时间线（make videos programmatically） |
| **SVG + Rough.js** | 2D 动画（含 `values`/`keyTimes` 关键帧、抖动重描、斜纹填充） |
| **Three.js** | 3D（立体几何四棱锥、波面、带材质光照的写实场景） |

即"模型写代码 + 真浏览器逐帧执行"。用户问能否借鉴以完成"完整实现"，并选定：**A+B+C+D 全做，且按视频整套换成 Remotion**。

### 1.3 被推翻的建议（保留理由，别当成没发生过）

1. 我先推荐**双轨并存**（新链默认、旧链留作确定性档）。用户问："为什么要保留旧的，全部移到新的不行吗"。
2. 我复核后**撤回确定性这条理由**：lint 禁随机与时钟 + lockfile 锁版本 + CI 复渲比哈希，已把确定性做到接近结构保证，为它留一整条旧链不成立。
3. 当时真正在保的只剩两件事：**跨镜一致性**（20 镜共用一套模板，天然像一部片；逐镜自由写代码后，字号/留白/字幕位置每镜重新决定，且这种漂移单镜抽帧看不出来）与**失败半径**（旧链失败模式被模板收敛成"过闸或带镜号退回"；代码链的失败模式是"不报错，就是难看"）。
4. 这两件**都能在链内补回**，不必靠保留旧链：补法即下面的 §4 母版 + §3 闸⑤。用户据此选定 **甲：全移 + 母版 + lint 强制包裹，旧链删**。

## 2. 架构

```
creation-app (Python, 镜像不变 2.62 GB)
   ├─ plan_motion → shots[i] = {code, text, highlight, source, fields, texture}
   ├─ 闸⑦ 整片风格配额 / 闸② 帧预算 / 出处闸 ──（计划层，烧像素之前）
   ├─ 闸① lint ─────────────────────────────▶  creation-remotion  POST /lint
   ├─ 逐镜渲染 ─────────────────────────────▶  POST /render-shot
   │     └─ 切片留在该容器自己的 /out，Python 侧 GET /artifact/{cache_key} 取回本地
   │        （闸③ 要对本机这份字节 ffprobe，带声切片要在本机 mux TTS 音轨）
   │        本地按 cache_key 存 MinIO：motion-shots/{会话}/{镜头键}/{文件}
   ├─ 闸③ 帧账回读 / 闸⑥ 字段对账 / 闸④ 画面两半（Python 侧，读切片与回读表）
   ├─ 质感滤镜（§13：缓存命中与新鲜切片都要过，按镜各跑一趟）
   └─ 母带层：拼接 → BGM → 闪避 → 音画同步硬闸 → 入库 → 级联回收
      闸⑤ 跨镜一致性在拼接之前判（红一次省掉母带那一趟编码）
```

### 2.1 `creation-remotion` 容器

- 与 `creation-editor` **完全同构**：独立镜像 `creation-remotion:latest`、compose 里 `profiles: ["app"]`、healthcheck、Python 侧只多一个 HTTP client。
- 基础：Debian + Node 20 + **`npm ci`（锁 lockfile，不是 `npm install`）**。
  lockfile 进 cache_key（§5），因为换依赖版本等于换像素。
- 预装依赖（= import 白名单的物理边界）。**下面是 `remotion/package.json` 与 `code_spec.IMPORT_WHITELIST` 的当前真值，不是设计时的估计**：
  `react` 19.2.0、`react-dom` 19.2.0、`remotion` / `@remotion/bundler` / `@remotion/renderer` / `@remotion/three` / `@remotion/paths` / `@remotion/shapes` 4.0.534、`three` 0.186.1、`@react-three/fiber` 9.8.1、`roughjs` 4.6.6、`katex` 0.19.0，加上两个别名 `@dg/film`、`@dg/tokens`（母版与 token，webpack alias 指到 `src/`）。
  > **设计时这两处写错了，留档**：① `@remotion/sequence` **这个包不存在**——`<Sequence>` 是 `remotion` 核心的导出，照清单 import 会在打包期炸；② `@remotion/cli` 与 `@remotion/eslint-plugin` 实际没装（服务端不需要 CLI，闸① 用 ESLint 9 扁平配置 + `@typescript-eslint/parser` 自写规则，不依赖 remotion 插件）。
  > 名单漂过的两种红法各不同：Python 这侧少了，模型写出来被闸退回；容器那侧多了，闸放行一个镜像里没装的包，报错发生在 lint 通过**之后**的打包期，模型拿到的是一句解析失败。所以 `tests/test_code_spec.py` 第 ⑤ 节拿正则把 `lint-rules.mjs` 的 `ALLOWED_IMPORTS` 抠出来与 `IMPORT_WHITELIST` **逐项比相等**。
- 浏览器：`Config.setBrowserExecutable()` 指向镜像内系统 Chromium，**不让 Remotion 构建期再下一份 headless shell**（省体积 + 免构建期外网下载）。
- WebGL：无 GPU，走软件渲染。`chromiumOptions.gl` 的可用档（`swangle` / `angle` / `noop`）**P1 阶段实测确定，不预设**；实测数据进 §9.7 的性能表。
- 字体：只用镜像内已有的 Noto CJK 家族。外链字体在闸①里是禁项——离线渲染时它会**静默回落**成默认字族，用户在界面上选的字体和画面上出现的不是一回事（旧链 `THEME_FONTS` 早就为这个写过一条注释）。
- 故障域：Remotion OOM / 崩渲染只影响图形链；口播链、母带层、素材库、登录不受波及。

### 2.2 HTTP 契约（四个口，真源是 `remotion/server.mjs`）

| 口 | 入 | 出 |
| --- | --- | --- |
| `GET /healthz` | — | `{ok, node, remotion, chromium, gl, master_hash, lockfile_hash}` |
| `POST /lint` | `{code}` | `{ok, errors:[{rule, line, column, msg}]}`，**恒 200** |
| `POST /render-shot` | `{code, cache_key, input_props:{fps, durationInFrames, aspect, width, height, text, highlight[], words[], subtitleMode, fields}}` | `{ok, cache_key, artifact, bytes, composition, probed, timings, tokens, warnings}`；失败走非 200 |
| `GET /artifact/{key}` | — | 切片字节（`video/mp4`） |

> **对设计稿的两处订正，如实记账**：
> 1. 设计时写的是三个口，实现多了 `GET /artifact/{key}`——产物先落在渲染容器自己的 `/out`，由 Python 侧按 cache_key 取。
> 2. **「字节不过 Python 的手」这条没成立，是被推翻的那一种**：切片由该容器直接 publish 到 MinIO 的原设想，败在两件事都必须在字节这一侧做——闸③ 的 `ffprobe` 要对**本机这份文件**读数（容器说 90 帧、本机只有 87 帧的现场只有本地探测拿得到），而带声切片要把本机 TTS 出来的音轨 mux 进去（旁白在 Python 侧生成，容器根本没见过它）。于是链路改成 `render-shot` → `GET /artifact` → 本地 mux → `_ObjectShotCache` 发布，代价是**一趟 HTTP 下载**（一镜几 MB），换来的是闸③ 与混音都落在同一份字节上。
>    级联回收**仍然天然覆盖**，但覆盖的理由换了：切片与代表帧走 `motion-shots/{会话}/{镜头键}/{文件}` 这个对象前缀，`session_gc` 按会话前缀清，与新链无关。

## 3. 八道闸

删掉旧链时，旧链上有五道东西是真在干活的，逐道给替身；不允许"只是没了"。

| 旧链那道 | 新链替身 |
| --- | --- |
| 卡型白名单 + visual 死键闸（写错键出空壳） | 闸① lint（含强制包裹母版，§12 后再加三条字段规则） |
| 分镜空壳闸（visual 没内容不许出片） | 闸④ 画面两半（按像素判空 + 按包围盒判"小气"，比旧链更严） |
| 版式模板天然统一 | 闸⑤ 跨镜一致性（按母版回读表判） |
| 镜头长度归真实语音时长 | 闸② 帧预算（外部注入时长） |
| 字段级 pointer + 元素命中表（点中元素改一个值） | 闸⑥ 字段级对账（§12：声明的字段必须在画面上真生效） |
| 版式配额（旧链那套"每镜至少一个画面主体"，#90 之后只记账不拦截） | 闸⑦ 整片风格配额 + 纯文字镜占比（**这一道回到硬拦**，理由是它在渲染前判，红一次只花一次重规划） |
| （旧链不需要） | 闸③ 渲完回读对账 |
| （旧链不需要：卡由模板排，撞不出叠字） | 闸⑧ 版面回读（画面是模型现写的，排版没有模板兜底，**只记账不拦截**，§15） |

**闸① lint（渲染前，秒级，带镜号退回）**
实现走 ESLint 扁平配置的 `no-restricted-syntax` + `no-restricted-globals` + `no-restricted-imports`，配 `@remotion/eslint-plugin`，**不需要自研规则**。禁项：

- `Math.random`（必须用 Remotion 的种子确定版 `random(seed)`）
- `Date.now` / `new Date()` / `performance.now`
- `setTimeout` / `setInterval` / `requestAnimationFrame` **用于驱动时长或动画进度**（时刻只能来自 `useCurrentFrame()`）
- `fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource`
- `fs` / `child_process` / `os` / `net` / `path` 等 Node 能力
- `eval` / `new Function`
- `localStorage` / `sessionStorage`
- 外链资源：`url(http…)` / `@import` / `<link>` / `<script src>`
- `import` 白名单外的任何包
- **顶层必须 import 并包裹 `<FilmLayout>`**（§4），不包就不给渲

报错形态：`{镜号, 规则名, 行号, 一句话}` 列表，原样退回模型。

**闸② 帧预算（渲染前）**
`duration_in_frames = round(真实语音时长 × fps)`，由 Python 侧从 TTS 实测时长算好、经 `input_props` 注入。沿用旧链口径：**有旁白时模型写的秒数只当下限参考，镜头长度归真实语音**。上限 `MAX_FRAMES_TOTAL = 4000` 保留，超了要求用户降 fps 或缩片子，**不静默砍**。

**闸③ 渲完回读对账（渲染后、进母带前）**
`ffprobe` 读切片实际帧数与时长，与分镜账比对，差 > 1 帧 → 该镜退回。**不静默截帧、不静默补帧**——与音画同步硬闸（#60）同一个脾气。

**闸④ 画面两半（渲染后，按像素，只量主体带）**
基准色取母版本帧的背景（`bg` token **回读**出来的实际色值，不是猜的 #fff；读不到当场抛，不降级）。判定量在**主体带**内：`_band_of()` 从母版回读的 token 里取 `bodyWidth`/`bodyHeight`/`gutter`/`topSafe`，**不在 Python 侧另算一套几何**——旧版 `film-layout@1` 没报这几个值时才退回整帧，且退回时话术改口说"整帧"不说"带内"。

**为什么必须只量主体带**：字幕带画在 `bottomSafe` 里，本来就在带外。横屏 1920×1080 上母版自绘的那一块字幕框约 1000×240 像素 ≈ 整帧 11%——**镜头代码一寸没画，光靠母版的字幕就能过 2% 这条线**。带内只有 1800×732，量带才量得到"这一镜自己画了东西没有"。

两半各判一件事，阈值都是 2026-10-11 用六支真渲（roughjs / three.js / KaTeX × 竖屏+横屏，同一套像素口径）定下来的：
- **空壳**：带内差异像素占比 `ratio < EMPTY_MIN_RATIO = 2%` **且** 内容包围盒跨度 `span < SPAN_MIN = 45%`（跨度按带短边算）才打回。两个条件缺一不可，因为**真画了的细线条本来就只占 1%~3% 像素**——手绘斜纹整镜像素占比实测 **0.99%**、公式字形 **1.54%**，而它们当年被判漏的那批横屏镜跨度只有 **9%~36%**。单看像素比会把画了东西的片子判成空，单看跨度会把铺满带的一行大字判成空。
- **小气**：`span < TIGHT_MIN = 30%` 无条件打回，**像素占比再够也不放**。这条管的是"东西画了，但挤在角落"——真渲分布里正常镜在 **52%~100%**（three.js 74%~100%、roughjs 52%~83%、KaTeX 68%~95%），30% 与它们之间隔着一条明显的沟。
- **不拦的第三档**：`span < FILL_TARGET = 60%` 只**记账**，出片回执上逐镜列成"逐镜提醒（不打回）"。60% 是审美线不是合同线，误伤的成本是整轮重烧。
- 取样三帧的位置是 **0.15 / 0.5 / 0.85**，**不是首/中/末**——第 0 帧正落在母版入场动画的起点，量它等于量"还没画完"。`ratio` 取三帧最小、`span` 取三帧最满那一帧（最满的都不到 30%，才是真小气）。
- 判据口径：整帧二值图落成 `rawvideo/gray` 字节，Python 自己数非零并扫行列包围盒。**既不缩到 1×1 求平均，也不抽行抽列采样**（采样会漏掉整列，把"铺开了"读成"小气"）；下面那条引用块里的"96px 网格"是回归夹具**画**出来的图形形状，不是量法。
- 两个读数（`empty_ratio`、`fill_span`）随逐镜账与回执带出来（非命中镜），阈值以后再调要有数据可调。
这条比旧链的空壳闸更严：旧链只能查"字段有没有写"，这条查"画面上到底有没有东西、东西铺开了没有"。旧链真机查出的静默缺陷 #102（`visual` 写了这张卡不认的键 → 出空画面且 `ok=True`）在新链由这道接管。

> **P2 真机踩到的三条 ffmpeg 口径，留档免得再踩**（都属于"退 0 但结果是错的"那一类）：
> 1. **底色必须写 `0xrrggbb`**。`color=c=#f6f1e4` 解析出来是 (241,241,241) 那块灰，不是母版底色——基准色本身就错，后面每个读数都不可信。
> 2. **判空不许缩到 1×1**。`scale=1:1:flags=area` 在 1920→1 这种极端比例下会把细碎的高亮像素抹成 0：真机 s02 那片 roughjs 斜纹圆逐字节数是 **4.26%**，1×1 那条路报 **0.00%**，一份画了东西的片子被判成空画面。正确口径是整帧二值图落成 `rawvideo/gray` 字节、自己数非零。回归用例 `tests/test_code_gates.py` 按真机形状（1080×1920 上间距 96px 的 1px 网格）同时跑新口径与旧口径，**把那条 0.00% 打在屏幕上**。
> 3. **取代表帧不能用 `-sseof -0.1`**。带声切片的视频流常比容器时长短一截（`-shortest` 按音频切），seek 目标落在最后一帧之后时 ffmpeg **退 0 且不写文件** → `frame.png` 静默缺失 → `cache.store` 读它抛 `FileNotFoundError`、被 `except` 吞成账上一句 `cache_stored` → **整条链的切片缓存永不命中**，"局部改只重烧受影响镜"悄悄退化成每镜重烧。改成按切片自己的帧数算 `-ss`，并且取不到就当场抛。

**闸⑤ 跨镜一致性（渲染后，按回读表）**
`<FilmLayout>` 把它**实际使用的** token（字号阶、字色、字幕带高度与位置、边距、安全区）写进渲染产物（`<meta name="dg-tokens">` 或等价物），`renderMedia` 的 `evaluate` 回调读回来，落进逐镜表。
**容差为 0**：这些值是母版的常量，不是每镜可调的近似量——同一 token 跨镜取值只要不完全相等就带镜号退回。之所以不给"差 1 像素算通过"这种容差：真出问题时那 1 像素正是我们要找的东西，容差只会把缺陷放过去。
**能力边界要写清**：闸⑤ 保证的是**数值一致**，管不了**审美一致**。

**闸⑥ 字段级对账（渲染后，按母版回读的字段表）**
这一道是为 §12 的字段通道配的，判的是**"声明的字段有没有真在画面上生效"**：
- **动态（这一道）**：母版在探针帧回读每个 `<F>` 的自报取值，Python 侧与当初注入的 `fields` 逐项比——`number` 容差 **0**、`color` 归一大小写与缩写后比、`text`/`bool`/`select` 严格相等。不一致带字段名与**两个值**打回，话术是「表单改了、画面没跟着改」。之所以敢给 0 容差：注入值和生效值之间没有换算，会不等只有"代码没读它"这一种原因。
- **缺盒不判红**：某个字段没量到 DOM 盒，如实记成 `no_geometry`，前端退化成"无空间命中"列表（口播链 T5 早就有这一档）。盒是给"点元素反查字段"用的，不是给改值用的——把缺盒判成红会逼模型给每个字段套一层 `<F>` 壳，那是为了过闸而画，不是画面需要。
- **静态那一半归闸①**（§12 加三条规则）：声明了却没读、读了却没声明、`<F name="x">` 的 `value` 表达式没引用 `fields.x`。这三条在渲染前就能判，不该等分钟级的重烧。

**闸⑥ 保证的是「声明过的字段真生效」，管不了「声明得够不够全」**：没进 `fields` 的形状照样只能改代码。这条边界在 §10。

**闸⑦ 整片风格配额（计划层，烧像素之前，一次都不花）**
判的是**整片**而不是单镜，读的是**代码字节里的 import**，不是模型自报的某一栏——自报会漂（写 `style: rough` 而代码里一个 `roughjs` 都没有），而这一道要拦的恰恰就是"说用了但其实没有"。
- **归类**：四条画法通道 `rough`(roughjs) / `three`(three + @react-three/fiber + @remotion/three) / `katex` / `vector`(@remotion/paths + @remotion/shapes)，按这个优先序取第一条命中；都没命中但代码真在画几何（裸 `<svg|path|rect|circle|…>` 或 `toPaths|shapeArc|E(` 那类标记）也算 `vector`；只有文字与色块的归 `text`。**`<div>` + `background` 是色块，色块不算画面主体**——"卡片+文字"正是这么写的。
- **三条硬判据（打回）**：① 通道种数不够——`CHANNEL_QUOTA = ((6, 2), (10, 3))`，≥6 镜至少 2 种、≥10 镜至少 3 种；② ≥6 镜却一条图形通道都没有（判据 ① 的特例，单列是因为退回理由要能指名"一镜图形都没画"，而不是笼统说"种类不够"）；③ 纯文字/色块镜超过**中间镜**的三分之一（`MAX_TEXT_ONLY_SHARE = 1/3`，首尾镜不计入分子也不计入分母）。
- **6 镜以下整道闸关掉**（`MIN_SHOTS_FOR_QUOTA = 6`）：三镜片要求两种通道，是逼模型给用不上的镜塞一个立方体。出片回执上这一档显示"未判"，**不显示"通过"**。
- **一条软判据（只提醒，不打回）**：文案里"机器认得出的具体项"占比低于 `CONCRETE_SHARE_TARGET = 40%` 时逐镜点名。词法只看得见数字、引号/书名号里的术语、拉丁缩写，看不见地名人名器物名——一条讲活字印刷的片子完全可以不写数字；把这条做成硬闸，误伤的就是那种纯专名文案，而误判的代价是一整轮重规划。所以它落在两处实在的地方：技能正文的「文案合同」（写之前就要求到）+ 确认卡与出片回执上的逐镜提醒（用户看得见，可以直接说"这几镜太空，重写"）。
- **为什么这一道允许硬拦**（与 #90 那条"旧链配额只记账"相反）：它在渲染前判，红一次只花一次分镜重做，不是几十分钟白烧；旧链那条挂在渲染之后，代价口径完全不同。
- 三处读同一份账：确认卡、出片回执、闸本身都调 `style_facts()` / `check_style_quota()`，不各算一遍。

**闸⑧ 版面回读（渲染后，探针帧上的真 DOM 盒；八道里唯一不设红的）**
这条链的画面是模型**现写**的：它排版时手里只有坐标，没有像素。旧链由模板排，撞不出"两个标签叠在一起"这种病；新链撞得出来，而抽帧不一定看得出（叠字在两镜之间可能只出现一次）。判据与口径见 §15。

> **出处闸不占编号**，但它现在也跑在计划层这一趟（#172 把它从旧链迁到代码链）：`source` 声称"查证过"而本会话检索账里没有对应行 → 分镜不入库、一帧不开始渲；账本整个不存在时整道放行（没检索过就不该有声称）。补丁口只对**本次改到的**镜复判——闸的职责是拦住新写上去的猜测冒充查证过的出处，不是替整片重审旧账。

## 4. 母版 Composition（`<FilmLayout>`）

新链里唯一有排版权的东西。

- **独占**：字幕带、安全区、页边距、字阶、配色 token、画幅适配（竖/横/方）。
- **镜头代码只能通过插槽填内容**（主体区、装饰层），拿不到字幕绘制权，也拿不到排版数值。
- `text` / `highlight` / `subtitle_mode` / `caption_size` / `aspect` 全部从 `input_props` 注入母版；镜头代码读不到就不可能各写各的。
  （**`texture` 原来也在这份名单里，现已移出**：它压根不进容器——母版不知道这一镜加了什么滤镜，质感是 Python 侧在切片缓存之后各跑的一趟 ffmpeg 滤镜，见 §13。）
- **字幕位置 20 镜不差一像素**，靠的是这个独占权，不是靠运气。
- 母版本身有版本号（内容哈希），进 cache_key（§5）：改一次母版 token 等于全片换像素，不进键就会命中旧母版渲出来的切片。

**起手模板（不是闸）**：原稿写的是"把旧链最常吃的六种版式——`title` / `archive` / `compare` / `flow` / `timeline` / `chart`——翻成六份可直接 import 的最小 `.tsx`"。

> **如实记账：六份版式没做，换成了另外两样东西**。
> 1. **一份骨架**：`remotion/src/user-shots/shot.tsx`。它同时是渲染落点（每次渲染前被 server 覆写）与起手模板，正文里逐条演示四件事——顶层必须包裹 `<FilmLayout>`（闸① 强制）、**只能画在 `useBody()` 报回来的那条带子里且坐标系已是设备像素**（旧链 12 镜全按 `1080×620` 猜高度，横屏母题被压成 9%）、时刻只从 `useCurrentFrame()` 拿、随机要用 `remotion` 的 `random(seed)` 而不是 `Math.random`。
> 2. **四条画法通道按题材点名**：`roughjs` / `three + @react-three/fiber` / `katex` / `@remotion/shapes` 或裸 SVG，写在技能正文「画面丰富度合同」那一节，并与闸⑦ 的 `STYLE_CHANNELS` 逐行比对（`tests/test_code_spec.py` 第 ⑦ 节）。
>
> **为什么这条替换成立**：六份版式买的是"结构天然统一"，而闸⑤ 已经在事后按母版回读数值拦一致性；真正没人替得了的是**画什么**（旧链那六种卡型恰恰是这次要拆掉的东西）。通道表给的是"这种题材该用哪种画法"，比六份固定版式更贴近这条链的卖点（模型自己决定形状）。
> **这条替换买走的**：形状层面仍然没有事前保证——两个模型写"时间轴"可以一个用 SVG 一个用 div 堆，数值一致而观感不一致。闸⑤ 管不了这一层，§10「审美一致性只有事后闸」那条因此继续挂着。

> **这条要如实记账**：示例是"可以抄"，不是"必须抄"。模型不抄也合法，那时一致性只剩闸⑤在事后拦。
>
> 原稿在这里还有一句"而闸⑤拦下来的返工是**重交一段代码**，不是旧链那种**改一个字段**——这是全移方案相对双轨唯一实打实的退步"。**这句已被 §12 订正**：字段通道把"改一个值"做了回来（在 `fields` 声明的范围之内）。
> 这里仍然成立的部分是：**起手模板不是闸**，模型不抄时跨镜一致性只有事后闸⑤，没有事前结构保证。

## 5. 分镜契约、缓存与账

### 5.1 新的 shot 结构（全部字段）

```
shots[i] = {
  code:      "<完整 .tsx，顶层包裹 <FilmLayout>>",   # 必填
  text:      "这一镜要说的一句话",                    # 进母版字幕带，不进镜头
  highlight: ["逐词点亮的词"],                        # 必须是 text 子串，≤4 个
  source:    {"标题": …, "链接": …},                  # 出处闸照旧：必须对得上本会话检索账
  min_duration_sec: 数值                              # 只当下限参考
  texture:    "" | "none" | 档名                      # §13 逐镜质感：空串=跟整片默认，
                                                     # "none"=这一镜明确不加（两个形状，不许合并）
  fields:    [ {name, type, label, value,            # §12 字段通道，可选
               min/max/step/unit | options} , … ]     # 有序：界面按这个顺序出表单
}
```

- 竖屏 `text` ≤ 60 字、横屏 ≤ 110 字、`highlight` ≤ 4 个、首尾各留一镜（开场/收尾呼吸镜）——这四条纪律原样搬。
- **`fields` 的三条纪律**：`name` 必须是合法 JS 标识符（`/^[A-Za-z_$][A-Za-z0-9_$]*$/`）且**不撞母版注入的保留键**（`text`/`highlight`/`words`/`fps`/`durationInFrames`/`width`/`height`/`aspect`/`subtitleMode`/`fields`）——撞了的结果是 `{fields: {"text": …}}` 这种在 props 里覆盖字幕带的键，画面少一行字而 lint 看不见；每镜**上限 12 个**（再多表单就成了一堵墙，模型也倾向于把不该开的东西都开出来）；`type` 只有 `number`/`color`/`text`/`bool`/`select` 五种，**没有第六种就不该有第六个控件**——前端控件的单一来源仍是补丁口吐出去的这份 schema（#127 那条纪律）。
- **删除的字段**：`card`、`visual`、`theme`、`overlay`、`duration_sec`（有旁白时本来就不该写）。
- 数值只给数字、单位写进 label 这条纪律，随内置图示一起消失；对数刻度的需要挪进 `chart` 起手模板里实现。

### 5.2 cache_key

```
cache_key = sha256(json.dumps({
    "code":   代码字节,
    "knobs":  该镜旋钮  SHOT_KNOBS = (text, highlight, min_duration_sec, fields),
    "film":   整片开关  FILM_KNOBS = (fps, aspect, narration, voice, rate, subtitle_mode),
    "master": 母版内容哈希,
    "deps":   lockfile 哈希,
}, sort_keys=True, ensure_ascii=False, default=str))[:16]
```

- **比设计稿多了四项，都是真换像素或真换声音字节的**：`narration`/`voice`/`rate` 改的是切片里的**声音字节**（切片自带音轨，命中即整段跳过、连 TTS 都不重发），`subtitle_mode` 改的是母版字幕带的画法。不进键的后果与旧链那条注释同族——"少算一个键就是拿旧片冒充新片"。
- **`fields` 进 knobs 是 §12 的关键**：改一个字段值 → 这一镜键变、只重烧这一镜，其余镜键一字不差。这也是"改字段不重过闸①"成立的前提——代码字节没动，lint 的结论就不该变。
- **`texture` 仍然不进键，但理由换了**（§13）：不是"挂在母带"，而是**缓存存的是加质感之前的像素**，滤镜在取到切片之后按镜各跑一趟。于是"整片换档"和"只换这一镜"都**0 镜重烧、画面照样变**——进了键就变成"换一档重烧全片"，那既不是用户要的，也不是必要的。
- 母版哈希与 lockfile 哈希**取 `/healthz` 现报的值**，Python 侧不重算文件哈希：两处各算一遍迟早不一致（换行符、编码、算哪几个文件），而键漂移的表现是**静默命中旧母版渲出的切片**——改了什么全片换像素、账上却看不出来。
- 五段身份缺一不可的理由同 §5.2 原稿：不进键就会命中"旧母版 / 旧依赖"渲出来的切片，改动账与逐镜比较全都看不出来（与昨天那个 `44` / `44.0` 键漂移 bug 同族）。**按字节算的键就按字节断言**（`tests/test_code_spec.py`）。

### 5.3 重烧口径

- 改一镜代码 → 只有那一镜 cache_key 变 → 只重烧那一镜。
- 改 `fields` 里的**一个值** → 同样只有那一镜变（`fields` 在 knobs 里），而且**不重过闸①**：代码字节没动，lint 的结论不可能变。取值超出声明的 `min`/`max` 一律打回，**不钳值**——钳了就是"界面填 120、画上是 80"，正是要消灭的那种静默。
- 换整片质感档（顶层 `texture`）→ **0 镜重烧**：它故意不进缓存键，滤镜跑在取到切片之后的那一趟（§13）。旧链"挂母带"那句口径已订正——**结论没变、理由换了**。
- 只换一镜（`shots[i].texture`）→ 同样 **0 镜重烧**，且**别的镜一档不动**：逐镜覆盖不进键，也不碰别人的切片。
- 改母版 token / 换依赖版本 → 全片重烧，这是**正确行为**，不是缺陷（像素确实变了）。
- **缓存里存的是加质感之前的像素**；界面上"这一镜加了什么"读逐镜账（`texture` / `texture_filter`）与时间线那一行，**不读缓存对象**——运行时事实挂在账上，不进缓存键的东西一旦写进缓存对象就会跨版本漂。代表帧在加完质感之后重取一次，所以界面看到的帧与成片一致。
- 逐镜账、证据分级（machine / frame / listening / eyeball）、未做的标 UNVERIFIED，全部照旧。

## 6. 前端与编辑面

- **保留**：时间线、轨道、框选、对比帧、刷新重放。它们只认"镜"这个粒度，与哪条链出画面无关。
- **右侧停靠栏按镜页签**：〈字段〉〈质感〉〈代码〉〈文案·出处〉（原稿写三类，§13 加了〈质感〉）。
  - 〈字段〉按补丁口吐出去的 `fields` schema **自动**出控件（`number` 带 min/max/step/单位、`color` 取色、`bool` 开关、`select` 下拉、`text` 单行），前端不认具体字段名——与 #127「补丁口把字段类型也发出去」是同一条纪律的延续。点中画面上的元素时，按闸⑥ 回读的 DOM 盒反查字段名并高亮那一行控件；某字段没量到盒就落进"无空间命中"列表（口播链 T5 那一档形态），**不许留空白**。
  - > 订正原稿那句"旧链那套字段表单随旧链一起删"：删掉的是 `theme` 七旋钮 / `overlay` 图层 / `visual` 结构体那三份**固定清单**，留下的是"**控件由 schema 单源驱动**"这台机器——它在新链上换了数据来源继续用，否则 §12 白写。
  - 〈代码〉是给模型和高级用户逃生用的：改了就走 `code` 指针 + 重过闸①。
- **patch 口白名单（§12 之后四条，§13 之后五条）**：`/shots/i/fields/{name}/value`（**不重过闸①**，代码字节没动；只做类型与 `min`/`max` 校验）、`/shots/i/code`（**必须重过闸① 才允许落盘**——否则改一行代码绕过 lint 等于闸① 不存在）、`/shots/i/text`、`/shots/i/source`、`/shots/i/texture`（§13：不重过闸①、一帧不重烧；取值必须是 `TEXTURES` 里的档名**或空串**——空串是"这一镜不表态、跟整片默认"，与 `"none"`（明确不加）是两个选项；超出取值打回，**不钳值**）。指针的转义与定位沿用旧链 `m_hit._segs` 那套 JSON pointer 口径，前端不用为新链认第二套规则。
- **〈质感〉一页**：档位枚举与人话标签都读命中表吐出去的 `controls.texture`，前端不自己列档名；这一镜"实际生效的那一档"读逐镜账，**不在前端重算一遍「镜头有就用、没有问整片」**——重算就是第二个真源，早晚和渲染侧不一致。
- **整片开关**（`aspect` / `fps` / `narration` / `voice` / `rate` / `subtitle_mode` / `texture`）**只在 `plan_motion` 的 `param_options` 出现一次**，渲染节点继承。旧链这条纪律原样搬（否则计划卡上同一组选项弹两遍）。`texture` 在这一层是**整片默认档**，逐镜 `shots[].texture` 覆盖它——两处都有，卡片要分开写（「质感（整片默认）：胶片，2 镜点名换过档」），否则用户改了逐镜那一档、回显还是整片那一档，等于把决定藏起来。
- **逐镜账上要能看出这一镜是哪条链烧的**——迁移期与之后排查问题都需要这一列。

## 10. 残留边界（做完也不销账）

- **确定性**从"结构保证"降级为"约定 + 实测"：靠 lockfile 锁版本、lint 禁随机与时钟、CI 里同一 cache_key 复渲比前/中/末三帧 sha256。任何一道被绕过，同输入同像素就不成立。
- **字段级 pointer 只在 `fields` 声明范围之内回来了**（订正原稿那句"永久消失"）：声明出来的旋钮退回"点一下改一个值"，**没声明的形状照样只能改代码或跟模型说一句**。这条边界的宽度取决于模型声明得够不够全，而"够不够全"没有客观判据——闸⑥ 只能保证"声明了的真生效"。
- **质感只有那五档**（§13）：`TEXTURES` 就是滤镜表的键集合，"这一镜要暗角/要褪色成sepia/要局部模糊"这类第五档之外的要求，这条通道给不了——它不是滤镜编辑器，只能改代码或走 `fields`。**逐镜 ≠ 任意**，这条要说在前头，免得界面被读成"每镜可调音"。
- **逐镜质感是运行时事实，只活在账上**（§13）：缓存对象里那份切片是**没加滤镜的**。任何绕过逐镜账、直接读缓存对象的代码（或人）都会拿到未加工的那一份，看起来"缓存坏了"其实读错了地方。新增任何"这一镜现在什么样"的读数都要问一句：它在账上还是在缓存里。
- **字段是模型自愿声明的**：某一镜一个 `fields` 都没交，那一镜的〈字段〉页签就是空的。界面要如实写"这一镜没交出可改的旋钮，要改画面请改代码或跟模型说"，**不许显示成加载失败或空白**——空白会被读成"坏了"，然后用户去点重试，白烧一镜。
- **回读的 DOM 盒是探针帧那一个时刻的几何**：动画中途元素在移动，而盒只量落定那一帧（与代表帧同一时刻）。所以"点元素反查字段"按落定态算，点在一个正飞过去的元素上可能不命中——这是盒与时刻的取舍，不是缺陷，界面上不承诺"任意时刻可点"。
- **审美一致性只有事后闸**（闸⑤ 管数值），没有事前模板；起手模板不是闸。
- **真 3D 是软件渲染的几何体**，不是视频里那种带材质光照的写实场景（f_030 那一档仍做不到）。耗时已实测（§9.7：每帧 120~202ms，远超 30fps 预算的 33ms）。**闸② 目前只有整片那条帧预算硬顶**（超了报"降 fps 或缩短片子"，不静默砍），**没有按通道单独给 3D 镜限 fps/限时长**——§9.7 那条"建议 3D 镜限到 15fps 或 60 帧"仍是建议，落地与否要看 §9 第 2 条那份完整样片真跑出来的耗时分布。
- **镜粒度编辑的浏览器真机验证依赖用户登录态**，我方只能到"渲染产物 + DOM 几何断言"这一级。
- **Remotion 授权**：源码可用但公司规模超过一定人数需公司授权（具体阈值实现前核一次官网）。本项目是个人作品集性质，但这条要写在这里，不要到面试时被问住。
- ~~构建期 npm 可达性未验证~~ **已验证**（P1-b 镜像烤成）：卡点不是 npm 而是**构建期那个注入代理对个别 `.deb` 稳定 502**，所以重烤走 `docker build -t creation-app:latest .` 而不是 `compose build`；运行期容器内无代理、npm 源直连 200。

### 12.1 两个优势的来源，是同一条链上的两个位置

旧链和新链的差别不是"强弱"，是**谁决定形状**：

| | 旧声明式链 | 新代码链 |
| --- | --- | --- |
| 形状从哪来 | 我预先写好的 22 卡 + 四族画笔 | 模型当场写 |
| 于是**表达上限** | 卡型之外没有东西 | 只要写得出来就能画 |
| 于是**可编辑性** | 形状是数据 → 改一个值就行，还能点中它 | 形状是代码 → 改画面＝改代码 |

也就是说旧链的字段级可编辑性**不是额外做的功能**，它是"形状被固定成数据"这一件事的副产品；代价就是形状被封死。所以"集成两者优点"不能靠把两条链并存（那只是把两个上限各拿一半，还多背一条链），要靠**在新链上把"可改的东西"重新变成数据**——模型仍然自由画形状，但把它认为值得让人调的那几个量声明成参数。

### 12.2 契约：`fields`

一镜多一栏可选的 `fields`（清单与三条纪律见 §5.1）。每项五到七个键：

```
{name: "radius", type: "number", label: "圆半径", value: 80,
 min: 20, max: 300, step: 5, unit: "px"}
```

- `type` 只有五种：`number`（带 `min/max/step/unit`）、`color`、`text`、`bool`、`select`（带 `options`）。
- `value` 是**这一镜当前的取值**，进缓存键（§5.2），也就是"画面的事实"的一部分。
- `label`/`unit` 是给前端表单的中文标签；**界面上不许露出 `name` 以外的机器名**。
- 没有 `fields` 的镜头完全合法（封面镜、收尾镜），只是那一镜的〈字段〉页签是空的（§10）。

### 12.3 代码侧怎么写：从 `fields` 读，用 `<F>` 标

```tsx
import { FilmLayout, F } from "@dg/film";

export const Shot = ({ fields }: any) => (
  <FilmLayout>
    <F name="radius" value={fields.radius}>
      <svg width={fields.radius * 2} height={fields.radius * 2}>
        {/* rough.generator() 出的 path，直径用 fields.radius 算 */}
      </svg>
    </F>
  </FilmLayout>
);
```

- 母版把 `inputProps.fields` 原样交给镜头组件；**镜头代码只读，不写**。
- `<F>` 是母版导出的标注组件：渲染成一个带 `data-dg-field` / `data-dg-value` 的容器，不改任何样式（`display: contents` 那一类不产生盒的写法要避开——必须能量出盒）。
- 三件事各有一道判：值没被读（闸① 静态）、读的不是声明的那个键（闸① 静态）、读了但自报值与注入值不一致（闸⑥ 动态）。

### 12.4 回读通道：探针帧那一个时刻

母版在**探针帧**（`durationInFrames - 2`，与代表帧同一时刻）扫 `document.querySelectorAll('[data-dg-field]')`，收集 `{name, value, box:{x,y,w,h}}`，走与 `DG_TOKENS` **同一条 console.log 通道**发出 `DG_FIELDS:<json>`，服务端 `onBrowserLog` 抓最后一次命中。

为什么不另开一次浏览器求几何：这条链每镜一次 bundle（实测 4.6~7.5s 固定成本），为量几个盒再开一趟等于**给每镜加一半渲染时间**；而 `onBrowserLog` 已经是公开口、闸⑤ 已经在这条路上跑。
盒坐标就是成片像素（Remotion 按 composition 尺寸 1:1 出帧），前端可以直接叠在预览上。

### 12.5 闸① 新增三条规则（渲染前，秒级）

| 规则 | 判什么 | 为什么要它 |
| --- | --- | --- |
| `dg/fields-declared-unused` | 声明了 `radius`，代码里却没出现 `fields.radius` | 不查就是"表单能改、画面不动"——用户会以为按钮坏了 |
| `dg/fields-undeclared-read` | 代码读了 `fields.bogus`，`fields` 里没声明 | 渲出来是 `undefined`：轻则 NaN 尺寸，重则整镜塌成空壳，而闸④ 只会说"画面是空的"，找不到原因 |
| `dg/field-mark-not-reading` | `<F name="x" value={...}>` 的 `value` 表达式没引用 `fields.x` | 自报值是假的，闸⑥ 的比对就成了走过场 |

这三条必须在渲染**前**判：它们都是"代码与清单不一致"，等分钟级的重烧回来再报，返工成本差了三个数量级。`/lint` 与 `/render-shot` 都接住声明的字段名清单。

### 12.6 闸⑥：自报值与注入值逐项对（渲染后）

见 §3 的闸⑥ 定义。补一句为什么动态还要查一遍——静态只能证明"代码里写了 `fields.radius`"，证明不了"那个值最后真流到画面上这个元素"（中间过了一次 `interpolate`、一次 clamp、一次 `Math.max(0, …)`）。**自报值取的是渲染那一刻 DOM 上的实际值**，比静态远；而它由 `<F>` 的 `value` 表达式给出，那条表达式又被 §12.5 第三条钉死必须引用 `fields.x`。两道合起来才是"改了真生效"。

### 12.7 patch 口与重烧

- `/shots/i/fields/{name}/value`：按声明的 `type` 校验、越界**打回不钳值**（§5.3）→ `spec` 出新版本（fork）→ 只有第 i 镜 cache_key 变 → 只重烧那一镜。**不重过闸①**：代码字节没动，lint 结论不可能变；重跑一次只是白等十秒。

## 13. 质感逐镜通道：滤镜从母带挪到"每一镜的那一趟"（2026-10-11，B6）

旧状态：质感是**整片一档**，五档滤镜串跑在母带那一趟（拼接之后的整片 ffmpeg）。用户提的要求是"多风格"，而风格在画面上是**逐镜**决定的——一镜片里"手绘的那两镜加胶片颗粒、公式那几镜保持干净"这件事，整片一档做不到。

### 13.1 契约：三个形状，两个不许合并

```
spec.texture            # 整片默认档：none | film | tv | glow | bleach
shots[i].texture        # 逐镜覆盖，三种形状：
    缺失 / ""           → 这一镜不表态，跟整片默认那一档
    "none"              → 这一镜明确不加，即使整片加了
    档名                → 这一镜就按这一档
```

**空串与 `"none"` 是两个选项，不是一个**。界面上它们并排摆在〈质感〉那一页里（第一格写"跟整片默认"，往后每格一档）。合并的后果不是显示问题：用户点了"跟整片默认"，补丁口按成员判 `TEXTURES` 把它打回（名单里本来就没有空串——它列的是"有滤镜链的档名"），于是"这一格点了没反应"。这条真在写用例时踩到过：`code_patch` 里那句注释已经声明空串合法，判据却写的是裸成员测试，**注释与代码各说各话**，用例把它抓住了。

判档只有一个真源：`code_spec.shot_texture(shot, film)`——渲染用它、逐镜账用它、`motion_plan` 的账行也用它。**前端不重算**「镜头有就用、没有问整片」，后端模块里也不许出现第二处 if：那两处早晚分叉，而分叉的表现是"账上写着胶片、画面上是干净的"。

### 13.2 执行：滤镜跑在**取到切片之后**，concat 之前

| 位置 | 做什么 |
| --- | --- |
| 缓存命中 | 取到切片 → **照样过 `_shot_texture`**（跳过它的话，命中的镜没质感、重烧的镜有，一场混出两种画风） |
| 缓存未命中 | 渲出切片 → **先把未加质感的切片与代表帧存进缓存** → 再过滤镜 |
| 母带层 | 只剩拼接、BGM、闪避——**这里再没有滤镜** |
| 代表帧 | 加完质感之后重取一次，界面看到的帧与成片一致 |

存进缓存的是**加质感之前的像素**，这是"换档 0 镜重烧"的全部理由：质感既不进 `SHOT_KNOBS` 也不进 `FILM_KNOBS`，整片换档、逐镜换档都不改任何一镜的键。

**这条通道买到的与花的代价，按事实记**：
- 买到——"只换这一镜的质感"成为局部改，且**一帧 Remotion 都不用重烧**（每帧 120~200ms 那一档成本一次都不花）。
- 花的——每一镜多一趟 ffmpeg 编码（`libx264 -preset veryfast -crf 20`，900s 超时）。这不构成新成本口径：`mediaops.concat` 本来就把每一帧重新编一遍，质感这一趟用的是同一族参数，代价形状与既有链路一致。
- 边界——**五档之外没有第六档**，`TEXTURES` 就是滤镜表的键集合（`none` 故意没有滤镜链，所以它不在 `TEXTURE_FILTERS` 里）。用例断言的是 `set(TEXTURE_FILTERS) == set(TEXTURES) - {"none"}` 且每条链非空，**不是** `sorted(...) == sorted(...)`——后者从一开始就红，因为两张表本来就差一个 `none`。
- 诚实——加档而滤镜串缺失时**宁可这一镜退回**，也不出"账上加了、画面没加"的片子（`_shot_texture` 里那条 raise）。

### 13.3 补丁口与账

- 第五条指针 `/shots/i/texture`：**不重过闸①**（代码字节没动）、**一帧不重烧**（不进键），只做取值校验——必须在 `TEXTURES` 或为空串，越界**打回不钳值**。
- 逐镜账带两个字段：`texture`（这一镜真正跑的档）与 `texture_filter`（真正喂给 ffmpeg 的那条串）。回执顶层的 `texture` 是**整片默认档**，逐镜分布走 `texture_by_shot`——两个值可以不同（一镜覆盖、或整片加而这一镜 `none`），卡片必须分开写：「质感（整片默认）：胶片，2 镜点名换过档」；整片不加而个别镜点了档时写「整片不加，2 镜自己点了档」。**"这一镜声明 `none` 而整片本来就是 `none`" 不算覆盖**——覆盖要有实际差别，否则每张确认卡都会虚报"有 N 镜换过档"。
- 时间线里那一行"质感"读的也是逐镜账（`rowOf(curSid).texture`），与账同源。
- 「改它不重烧」的预计重烧计数器把 `source` 与 `texture` 都算作不重烧字段——和昨天那个「局部改其实整片重烧」的 bug 同族，虚报一次就没人再信这个数。

## 14. 参数教程不进系统提示词，按链动态注入（2026-10-11，B3）

用户那条硬约束的原文是"有些参数等提示词不应该作为系统提示词，应该动态加载"。落成的机制：

- 代码镜的写法纪律、`fields` 怎么声明、五类指针怎么用、闸⑦ 那张通道表适合画什么——全写在 `backend/examples/skills/motion_explainer/SKILL.md` 正文里，**不在系统提示词里**。
- 服务端记着"哪个节点干活必须随身带哪份技能"：`agent_framework/plan/vocab.py::_IMPLICIT_SKILLS` 把 `plan_motion` / `render_motion_code` / `patch_motion_code` 三个节点都指向 `motion_explainer_skill`。为什么由服务端记而不是由卡面声明：真机实测模型交这张卡时 `skills_hint` 是空的——只靠卡面声明，整轮拿不到那份约束。
- **口播链的 `patch_video` 不挂技能**：它的 edits 是"命中表指针 + 值"，指针形状与可改字段白名单本来就在节点 `input_schema` 里，模型看得到，没有第二份需要随身带的字段字典。这条排除是设计的一部分，不是遗漏。
- 闸⑦ 的通道名与 SKILL.md「画面丰富度合同」那张表**逐行比对**（`tests/test_code_spec.py` 第 ⑦ 节）——正文改了名而契约没改，用例红。技能正文与代码之间的这条缝只有靠断言缝住。
- **schema 里的文字说明到不了模型**：`storyline_server/server.py::_signature_for` 只取 `type`，`description` 不上线。所以"给模型看的字段教程"必须走技能正文这条通道，别指望写在 JSON Schema 里就自动生效——这条是本轮查出来的事实，不是猜测。

## 15. 闸⑧ 版面回读：把「抽帧看得出来、生成时看不出来」的那三笔画质账接上（2026-10-11）

### 15.1 为什么必须有这一道

旧链的卡由模板排，两个标签叠在一起这种事结构上发生不了。新链的画面是模型**现写**的一段代码：它落笔时手里只有 `useBody()` 报回来的那条带子和一组坐标，**没有像素**——于是三类病只能出片之后由人眼发现，而发现一次代价是整镜重烧：

- **叠字**：两个文字盒压在一起，观众读到糊字。
- **被画面带切**：文字越过带子，母版按合同裁掉，观众读到半个字。
- **引线悬空**：标注线画好了，另一端指向空白——比没画更糟，它把视线带到什么都没有的地方。

母版是这一镜唯一**既有 DOM 又有真像素**的地方，所以判据放在母版里跑，判据本身是纯几何（盒与盒相交、端点离东西多远），不猜语义。

### 15.2 机制：探针帧上量盒，随字段回读一起出带

| 件 | 落点 |
| --- | --- |
| 扫描与出带 | `remotion/src/FilmLayout.tsx`：`useEffect` 在探针帧（`durationInFrames - FIELD_PROBE_TAIL`，与闸⑥ 同一帧）量画面带内的文字盒、图元盒、引线端点，`console.log` 出 `DG_LAYOUT:{…}` |
| 收集 | `remotion/server.mjs` 的 `onBrowserLog` 摘出该行，随响应回 `layout_used`，并在日志行加「版面=N 告警/扫 X 字 Y 线」；**三态各一句汇总**，措辞不在这里逐条写 |
| 记账 | `motion/code_render.py::summarize_layout()` 收成一镜一份稳定账（`status` / `findings` / `scanned` / `band` / `thresholds` / `frame` / `reason`），存进 `rec["layout"]` 并**加进 `META_FIELDS`** |
| 措辞单源 | `code_render.py::describe_layout()` 是本链唯一写这句中文的地方（节点、回执、缓存命中三条路径共用）；server.mjs 只搬结构化读数 |
| 上账与回执 | `nodes/motion_code_nodes.py` 汇总成 `layout_warnings` / `layout_unscanned`，证据行写「N/M 镜在探针帧真扫过」，`verified` 只在**全部扫过**时才真 |
| 模型侧 | `plan/support.py` 白名单收这两个键（不收就是假告警：账上有、模型看不见） |

### 15.3 四条口径，都是这轮定的

- **坐标是带内坐标**（画面带左上角 = (0,0)），不是成片像素。因为镜头代码写的就是这个系（`useBody().body.w/h` 是它的画布）；报成片像素的话模型还得自己减掉 gutter，减错方向就是另一处版面问题。闸⑥ 的字段盒用成片像素，那是 Python 侧归一化要点用的——**两个口径各有归口，不合并**。
- **阈值随读数一起回传**，单源是 `remotion/src/tokens.ts` 的 `LAYOUT_PROBE`。Python 侧不抄常量表，措辞里引的是这一次读数里的那份；读数没带阈值就写「判据 未知」，不填默认数字冒充。
- **`drawnBoxes` 只收画得出的叶子**（`<g>` 的盒是子元素外接盒，收进来等于把整组算成落点，dangling 这一路恒不响应——那是漏报到无用）。**引线自己必须从落点集合里剔掉**：线的端点天然落在自己的外接盒上，不剔就永远判不悬空。这条是本轮推演出来的 bug，两支 dangling 夹具报出 `{x:800,y:1300}` 才算钉住。
- **只记账不拦截**。八道里唯一不设红：几何猜的判据，刻意叠印与指向画面外的暗示都可能是合法设计，误报的代价是模型与用户开始无视整条通道。所以这一层的函数**不许抛**（跑它的时候像素已经烧完），畸形读数一律降级成状态而不是异常。

### 15.4 三态必须分开——「没有告警」有两种完全不同的意思

| 状态 | 触发 | 回执必须说 |
| --- | --- | --- |
| `missing` | 容器压根没回传版面行（多半是镜像里的母版比这条 Python 链旧） | 「这一镜的版面等于没扫过，不许当成扫过且干净」 |
| `unscanned` | 收到了行但 `scanned=null`（画面带 ref 没挂载，带内几何不可得），带 `reason` | 「这一帧没扫版面：<母版给的原因>」 |
| `scanned` | 真扫了 | 有 finding 逐条念；空表**才**是「扫过且干净」，不额外造话 |

`META_FIELDS` 加 `"layout"` 正是为了这条缝：命中缓存的镜若不还原它，就会被读成「没报问题」，而它其实是「上一次压根没扫」。老格式缓存（没有这个键）判成 miss 照实重烧——不拿旧口径冒充新读数，而这次母版哈希本来就变了，重烧不是额外代价。

### 15.5 阈值哪来的：夹具钉的，不是量出来的（如实记）

`overlap_ratio 0.4` / `clip_px 3` / `anchor = max(带短边×2%, 20px)` / `leader_min_px 40` / `max_findings 8` 这五个数**没有真机分布可依据**——这条链还没有成片级的版面统计。所以 0.4 不是"测出来的分界"，而是 `remotion/tests/layout-probe.mjs` 用夹具把它**钉住**的那条线：交叠比例 0.5 必须响、0.167 必须不响，`getScreenCTM` 的 `<g transform>` 映射必须对得上。将来跑出真分布再回来调，调的是那六个夹具的期望，不是随手改数字。

### 15.6 先证红再证绿（两趟都留了现场）

- **容器侧**：`tests/layout-probe.mjs` 六支各真渲一镜。把母版画面带 `<div>` 的 `ref={bodyRef}` 摘掉跑一趟 → 六支全报「版面没扫：画面带 ref 未挂载」；恢复 → ALL PASSED。
- **Python 侧**：`tests/test_code_layout.py` 50 条。加固前当场打出三处红（`findings` 是数字 → `TypeError`；`ratio` 是杂字 → `ValueError` 直接把跑红的用例中断；以及一条我自己写错口径的断言）。加固点是"畸形读数只降级成状态"，同一份输入重跑 → 50/50。

### 15.7 这一道管不到的地方（不销账）

- **只扫探针帧那一帧**。动效中途（尤其入场前）的叠字与悬空看不见——那一帧是"落定之后"的代表帧，与闸⑥/代表帧同一时刻，这是取舍不是遗漏。
- **不判语义**：两个标签压在一起如果那是刻意的重叠设计，它照样报；反过来"字压在线条上但没压别的字"不报（判据只认文字盒 × 文字盒、引线端点 × 全体）。
- **前端不显示版面告警**。这一道的产出是给模型重写那一镜的依据（改代码 → 复跑闸① → 只重烧受影响镜），不是给用户拖的编辑面；成片卡上叠红框、点告警跳到那一镜，现在都没做。
- **整片端到端的真机账还没跑**（§9 第 2 条那笔）：所以"闸⑧ 在实际片子里报出几条"这个数还不知道，现在知道的只有夹具会报。
