# 何时用这条通道（与常规剪辑的分界）

只有一条判据：**这条片子的画面是不是代码画得出来的（不需要现成影像）。**

- 用户随消息给了素材（要剪的影像/音频） → 走 default_editing_workflow_skill
  （load_media → … → plan_timeline → render_video）。
- 用户给的是一个**选题**（「讲讲活字印刷怎么来的」「用 60 秒解释什么是 RPC」），
  没有任何素材 → 走本通道：**plan_motion → render_motion_code**。
- 两条路是两个终点，不要混着排：一条片子只出一个成片通道。

# 流程

1. **查资料**：web_search / fetch_url，可以多轮。每条要点记下出处（标题 + 链接）。
   **会过期的数字（用户规模、使用时长、份额、价格、排名）先查「最新一期」再取数**——
   查到的报告先看数据期（出版年 ≠ 数据年），文案里写数据期（见「数据时效」一节）。
   **只查要写进文案的统计数字；历史年代、产品形态、机制类叙述不必逐条检索**——
   讲「什么时候出现、大概怎么运作」用常识就够，检索留给真正会过期的数。
   同一个关键词最多查一次：结果不理想就换说法、换来源，或者删掉这个数直接往下写；
   不要原样重查同一句——返回的是同一份结果，只会把分镜卡在原地。
2. **写分镜** plan_motion：每镜一句文案 + 一句 **`brief`**（这一镜画什么、怎么构图、
   怎么分几拍动）+ 高亮词 + 可选旋钮 + 出处；spec 顶层写一句 `style`（整片风格）。
   **`recurring_prop` 不是必填**：只有用户明确要求「同一件东西贯穿全片」时才写；
   用户没说就不写，让每一镜按自己的文案画（见「贯穿全片的同一主体」一节）。
   **`code` 可省**：不写就由系统按 brief、整片 style 与这一镜文案逐镜单独写代码
   （每镜一次短调用，自动过 lint）。你要自己写某几镜的 code 也可以，写了以你为准。
   写码前系统会先做一遍**美术导演**：把 `style` 拆成网格/色数/边缘/光/材质这几条可执行
   做法，并从每镜文案里圈出 2~4 个**实体**（人/物/地点/动作的结果，写进 `entities`），
   再把 brief 补成「这几件东西各在哪、谁前谁后、多大、光从哪来、字排哪」（`autofix_notes`
   会写改了哪几镜）。所以 `style` 尽量写具体；brief 可以粗，但至少要给一个方向。
3. **对账**：读返回里的 `estimated_sec`、`target_warnings`、`style_channels`、`style_warnings`，
   以及看图对照风格、预览版面那两段读数，有偏差就先改分镜。
4. **出片** render_motion_code：分钟级到十分钟级。返回 `status=queued/running` 时
   **继续调 render_status**（同 artifact_id）直到 done/failed。
5. **出片之后还要改** → 看下面「局部改」。

**被打回时怎么办（这条通道不会被熔断，别换通道）**：
- plan_motion / render_motion_code 的打回都是**带清单的改法**，按清单改了再交就是正路——
  这两个工具的校验打回**不算失败、不会被熔断**。**不要**因此改走 `render_web` 或别的出片通道：
  那条路出的是 HTML 幻灯片，丢了这条链的全部画面能力。
- **只改几镜就用 `shots_patch`**：只交那几镜（按 id 替换），不必把几十镜代码整份重交。
- **字色读不出（闸⑩）系统会自动修**；**一个字幕件都没摆的镜系统会补上**（`<CaptionText/>`
  或 `<CaptionLayer/>` 都算摆了）——回执的 `autofix_notes` 里写着改了哪镜。
  **整片写了片壳（`shell`）时这一条不适用**：字幕归壳，系统不再往镜头代码里补字幕件。

# 用户只给一句话时：默认导演方案

正常用户不会写提示词，他只会说「做个讲薄肌理论的视频」。**不要反问他一串风格问题**——
按下面这套默认决策自己补全，写进 spec。最多问**一个**真正影响成片、又无法从资料里
判断的问题（要不要配音、配乐用哪一首）。

## 默认决策

- **时长**：没指定就 3~4 分钟；20~28 镜，每镜 8~12 秒。
- **受众**：这个题材的普通好奇者，不是同行；术语第一次出现要用人话解释。
- **结构**：现象 → 机制（2~4 路解释）→ 为什么是此刻 → 收束。**不要停在「这是什么」。**
- **声音**：用户没说就带旁白；说了「只要字幕文字」就 `narration=false`。
- **字幕**：默认 `caption_style: "by_shot"`——字幕归这一镜的代码设计（位置/字号/描边/入场
  全由你定），母版不画、也不替你补。这是 2026-10-23 改的缺省：原先七档固定样式让所有片子的
  字幕长得一模一样。想回到「母版统一排」就写 `outlined`（白字黑边，深浅底都读得出来）。
  关键词照旧走 `highlight_style`。
- **配乐**：用户点名了某一首才配；没点名默认不配，不要自己从曲库里挑。

## 用户的明确要求怎么和这套默认叠加（优先级）

从高到低，逐条照办，不要把两层「融合」成四不像：

1. **产品底线（任何要求都不能覆盖）**：每帧由代码画、字幕排进构图、不联网/不引用外部图片。
   用户的要求与底线冲突时按底线做，并在交付时说明改成了什么。
2. **用户明确给的参数与禁忌 → 覆盖默认**：时长、画幅、帧率、配音开关、配乐曲目、
   受众、引用要求、「不要红色」「不要出现人」这类禁忌。用户说了 60 秒就不按默认 3~4 分钟；
   说了只要字幕就不加旁白；点了《We Never》就配那一首。**不要用默认值去稀释用户的明确要求。**
3. **用户的风格方向 → 在它之上加**：用户说「高级杂志风」「冷一点」「像某条片」时，
   把它当起点，自己补全媒介、笔触、光、构图、色彩与贯穿装置——是往上加，不是照单执行，
   也不是退回内部配方重开一套。
4. **用户没提到的维度 → 才用下面的默认决策与起手配方补空位**。只补空位，不覆盖已说的。

另一条边界：用户**明确否定**某样东西（「不要暖色」「不要读数表这种装置」）时，
它同时也是禁忌——换一套画法，不要把被否定的东西换个名字加回来。

## 内部起手：从这一镜的文案里长出来（不是一张配方表）

用户没给风格时，**不要从固定配方表里挑一套**。按选题与这一镜的文案自己起画法：
先想清文案里那件事物在现实里长什么样、光从哪来、这一镜的动线怎么走，
再定媒介（平涂 / 线稿 / 像素 / 厚涂 / 拼贴都行）、构图与色彩。
整片用一种语言，但每一镜画的是这一镜自己的东西；用户给了方向就在他的方向上继续加。

两条通用底线（任何画法都要满足）：

1. **每帧都是关键词的画像**：这一镜文案里能被画出来的那个东西，占住画面、有光有影。
   整帧只有字和色块＝这一镜没画。
2. **反 PPT**：卡片墙、九宫格、项目符号、干净的图表页、一排圆角色块——一条都不要。
   图表要长在场景里（粉笔线、纸面网格、玻璃反光、器械读数）。

贯穿装置**不是默认项**：只有用户要求「同一件东西在后面每一镜还在」时才写
`recurring_prop`。用户没要求就不写——每镜都是它自己的画面，不要为了「统一」硬塞一件
反复出现的东西。

# 这一镜画什么：你交 `brief`，代码由系统逐镜写

**分工是固定的：你交分镜，系统写代码。** 交付入口只有一个：`plan_motion`。你把每镜的
`brief` 交进去，系统按 brief 逐镜写码，顺手渲每镜一张静帧并做一轮
带图评审。分镜入库后调 `render_motion_code`，确认卡上就会带着这些静帧给用户看。

**不要在主对话里写 `shots/*.tsx` 草稿**：成片不读这些文件，写着写着就变成「手写全片
代码」，几十镜下来既慢又和系统写的那一版对不上。要改哪一镜，用 `shots_patch` 只交
那一镜的 `{id, brief}`；改过的镜会重写代码、重渲静帧，其余镜原样留着。

**你交的是 `brief`（可带 `entities`），代码由系统逐镜写。** 每一镜写一句画面描述，说清三件事：

1. **画什么**：这一镜文案点到的**每一件实体**（人/物/地点/动作的结果）——通常 2~4 件，
   不是只挑一件；它们要同处一个场景，有远近、遮挡、朝向；
2. **怎么构图**：主体占多大、其余实体各在哪、留白在哪、有没有一层底纹或参照物；
3. **怎么动**：分几拍、先出什么后出什么、最后一拍落在哪（铺满整镜，别后半截定格）。

也可以把这几件实体单独列进 `entities`（每个一个名词短语，≤5 个）；不列时系统会从文案
里圈。写 brief 时说清每件东西的**形状**（轮廓、部件、朝向），不必点名要调用哪个组件——
写代码那一步会按 brief 自己画。例：

> 左侧三分之二是一台冒烟的蒸汽机：圆柱形锅炉、上方一根细烟囱、右侧一个带辐条的飞轮；
> 右下角一个扛着煤袋的工人剪影，被机器的阴影罩住一半。烟从无到有先起，飞轮随后转起来，
> 工人最后一拍走到机器旁。

**例外**：系统逐镜写出来的某一镜确实画错了（比如写手两次都漏掉同一件实体），可以在
`shots_patch` 里给那一镜直接带 `code`（规则与下面完全一样），写了就以你为准。这是修
一镜的兜底口，不是交付方式——整片都自己写，等于绕开了逐镜写手、评审与预览。

下面是这套画面系统的全部能力，写 brief 与写 code 用的是同一份：

- `@dg/motion`：时间与缓动（`useT()` 整镜 0→1、`seg(t, t0, t1, E.standard)` 分段）；
- **裸 SVG / `<canvas>`**：不受任何组件限制，`<path>`、渐变、`<filter>`、`clipPath`、逐帧笔触都行；
- `@dg/lib/brush`：手绘笔刷与材质（`<BrushStroke/>` 可变宽度笔触、`<PaperTexture/>` 纸纹、`<Grain/>` 颗粒、`<LightPool/>` 光池、`<SoftShadow/>` 柔影、`<Vignette/>` 暗角、`<Wash/>` 水彩填充）；
- `@dg/lib/scene`：场景底板（`<Scene far mid near/>` 前中后三层、`<Horizon/>` 视平线、`<Particles/>` 浮尘）；
- `@dg/lib/walk`：走路的人的确定性步态（`<WalkingFigure/>`，剪影/平涂/受光/线稿四档）——可选参考件，不用也可以；
- `@dg/lib/draw/*`：简笔画零件（人、机器、建筑、齿轮、图表……）——**可选参考件**，不是必须；
- `@dg/film`：`<CaptionText/>`（字幕的字，位置由你给）、`<CaptionLayer/>`（整条预设，只在没有干净区域时用）、`resolveFilmStyle(getInputProps())`（整片底色/墨色/强调色）；
- `@dg/polish`：字体 `FONT`、字距 `tracking`、颗粒 `Grain`、暗角 `Vignette`；
- `@dg/tokens`、色板 `@dg/themes/palettes.json`。

每一镜都照这几条来（都是建议，不是打回条件）：

1. **风格是你的，不是照抄的**：把用户对画面风格的要求写成 spec 顶层的一句 `style`
   （会显示在计划卡上）。**这一句是起点，不是模板**——用户只给一点方向（「高级杂志风」）
   时，把媒介、笔触、光线、构图、配色、装饰自己补齐，可以从各种画法里各取一点，
   组合成这一片自己的语言；用户没提就完全自己定。整片每一镜照着同一套做，
   是「一种语言」，不是「一张设定卡」。
2. **字幕排进构图**：用 `<CaptionText/>` 套一个定位盒子，把这一镜的整句放在画面里最空的
   一带（与某个元素对齐），字色取 `film.ink`，字号由 `fitWidth` 求。**字幕是画面的一部分**，
   不是全片共用的底部一条；只有整屏都是画面、确实没有干净区域时才退回 `<CaptionLayer/>`
   （它占最底下 300px / 方屏 260px）。
3. **动作铺满这一镜**：时间轴按这一镜的比例写，最后一个动作结束在 80% 时长以后，
   至少三个先后拍点——别让后半截定格。
4. **每一帧都是关键词的画像**：先读这一镜的文案，圈出 1~2 个能被画出来的词
   （物件 / 人物 / 动作 / 关系），让它占住画面、给它光、给它影、给它动。
   整帧只有字和色块＝这一镜没画。零件库是可选的参考件，不是入场券；画法本身不限
   （见「画面从哪来」与「视觉手艺」）。
5. **镜数**：一镜 8~12 秒；目标 4 分钟左右就是 20~30 镜。

## 反 PPT 语汇清单

这条通道做的是**科普片**。下面这些是产品宣传片 / PPT 的语汇，观众一看到就会觉得「这是一场发布会」：

- **产品界面**：侧栏 / 顶栏 / 看板 / Dock / 命令面板 / 通知气泡 / 设置面板 / 标签页
- **发布与版本**：Changelog / Release notes / 版本号时间轴
- **增长与运营**：价格表 / 套餐卡 / 用户数看板 / 评分星条
- **卡片套路**：卡片堆叠 / 轮播 / 九宫格功能墙 / 特性列表打勾 / 一排圆角色块

同一件事，换成科普片自己的说法：

| 不要 | 改用 |
|------|------|
| 侧栏 / 看板 | **剖面**、**分层示意图**（把结构切开看内部） |
| 版本时间轴 | **真实历史时间轴**（有年份、有实物） |
| 增长看板 | **数据曲线**、**对照图**（把量画出来） |
| 卡片堆叠 / 轮播 | **地图**、**流程示意**、**比喻图**（一个东西变成另一个东西） |
| 界面高亮 | **器物特写**、**手绘描线** |

## 视觉手艺：像手绘插画，而不是像 PPT

手艺的第一步不是画线，是**读文案**：这一句里哪一个词能变成画？圈出来，给它尺寸、光、
影和动作，再谈其它。下面这几条决定这一帧能不能看——每一条都能在代码里落实：

1. **三层纵深**。远景（天空/远山/墙）、中景（主体所在的平面）、近景（前景遮挡/光斑/
   颗粒）。三层用不同的明度与锐度：远景淡、中景实、近景只露一角。`<Scene>` 给了现成的
   三层槽位，不强制使用。
2. **主体占 40%~70%**。主体缩在角落、其余全是留白的「小图标 + 大标题」就是 PPT。
   先定主体外接盒，再摆其余元素；至少有一条边或一个视觉重心压住画面。
3. **一个光源**。整片（至少整镜）只有一处主光：`top-left` / `top-right` / `back` / `side`。
   亮面、暗面、影子都按它来。`<LightPool/>` 给光池，`<SoftShadow/>` 给物件落地影——
   没有影子的物件看起来像贴纸。
4. **2~4 色 + 一个强调色**。底色、墨色、中间调之外，强调色只用在「这一镜要观众看的那一处」，
   别每个元素都染色。颜色从 `resolveFilmStyle(getInputProps())` 或 `TOKENS` 取。
5. **字号阶梯**。标题 / 正文 / 注脚至少差 2.2 倍；同一屏最多三种字号。字号用
   `useVideoConfig()` 的宽高换算，别按某一种画幅写死。
6. **笔触要有呼吸**。等宽带描线是「图标」，手绘线是「笔」。`<BrushStroke/>` 的两端收笔、
   中段压重、固定 seed 的轻微抖动就是这个差别：

   ```tsx
   <svg width={w} height={h} viewBox={`0 0 ${w} ${h}`} style={{position: 'absolute', inset: 0}}>
     <BrushStroke points={[[180, 720], [520, 660], [980, 700]]}
                  width={14} brush="pencil" seed={7} />
     <BrushStroke points={outline} width={10} brush="watercolor" seed={11} closed />
   </svg>
   ```

   三档 `brush`：`pencil`（有颗粒、适合线稿）、`marker`（实心、适合色块轮廓）、
   `watercolor`（多层偏移 + `feTurbulence` 渗染、适合大面积填充）。
7. **材质层**。纸纹 `<PaperTexture/>`、颗粒 `<Grain/>`、暗角 `<Vignette/>` 三者叠上去，
   画面立刻从「矢量图」变成「印刷品/手稿」。整片用同一套强度；`texture` 档已经是
   `film/glow/bleach` 时别再叠一层同类的。
   颗粒直接用 `<Grain opacity={0.5} seed={17} blend="normal" />`。**别自己写一块铺满
   画幅、挂 `feTurbulence` 滤镜的 `<rect>`**：那张噪声每帧都要重算一遍，实测一帧要多
   花两三倍时间（整片就是几十分钟），而颗粒本身一帧都没变；`<Grain/>` 用的是同一种
   噪声贴图，浏览器只栅格化一次。
8. **动效要成组**。同一层元素用同一个 `spring` 参数与 stagger；不同层可以有先后，
   但不要每个元素各用一套缓动。`interpolate` 一定要 `extrapolateLeft/Right: 'clamp'`，
   否则帧数一长数值就飞出画面。

**确定性**：所有随机（抖动、散点、纹理）都必须从固定 seed 来。用 `Math.random` 会让
每一帧重新抖一次，画面像在沸腾；同一份代码渲两遍也不会是同一部片。`feTurbulence` 的
`seed` 同理，写死。

## 画幅、坐标与几条写法纪律

1. **顶层是自包含的 `<AbsoluteFill>`**：底色、边距都由这一镜自己定。母版 `<FilmLayout>` 已下线，
   **不要 import 它**。**这一片写了片壳（`shell`）时**，纸底、顶部色条、左上圆钟、期号与底部字幕
   由片壳统一画：这一层只铺画面带里的主体与场景，画布用 `useBody()`，不要自己画外框和字幕。
2. **坐标按整帧写**：宽高从 `useVideoConfig()` 拿（竖屏 1080×1920、横屏 1920×1080、方屏 1080×1080），
   别按某一种画幅写死数字。
   spec 与 `plan_motion` 顶层的 **`aspect` 就写这三个枚举值之一**：
   **`"landscape"`（横屏 1920×1080）/ `"portrait"`（竖屏 1080×1920）/ `"square"`（方屏）**。
   写成比例（`16:9`）或中文（`横屏`）服务端虽然也认，但**没有理由不按枚举值写**——
   一次写对，就不用把整份分镜为了一个词重交一遍。
3. **three 镜的单位**：`@react-three/fiber` 默认相机在 `z=5`。几何体取 **0.2~1.0** 单位，并在
   `<ThreeCanvas>` 上**显式给相机**（`camera={{ position: [0, 0, 3], fov: 45 }}`）；标准材质要点光
   `intensity` 到几十才看得见。
4. **末行默认导出**：每一镜要有一个默认导出（`export default Shot;`），否则闸① 判 `dg/needs-shot-export`。

## 8 套主题色板（整片挑一档，个别镜可覆盖）

每套 7 键：`page`/`surface`/`field`/`text`/`muted`/`accent`/`border`。

| 色板 | page | accent | 风格 |
|------|------|--------|------|
| `vintage-kraft` | `#c8aa7d` | `#8b4937` | 复古牛皮纸 |
| `deep-ocean` | `#0b1620` | `#7cc8b4` | 深海科技 |
| `obsidian-violet` | `#14121b` | `#bca0e8` | 黑曜紫 |
| `modern-light` | `#f4f7fb` | `#2563eb` | 现代浅色 |
| `midnight` | `#090f1a` | `#61d9ef` | 午夜蓝 |
| `solar-pop` | `#f9faf6` | `#527434` | 阳光活泼 |
| `coral-burst` | `#fffffe` | `#d94e59` | 珊瑚迸发 |
| `color-play` | `#f7f5fb` | `#7354b5` | 色彩游乐 |

科普视频推荐主题：`deep-ocean`（科技感）、`midnight`（数据感）、`obsidian-violet`（概念感）。

**整片的底色与字幕配色由计划卡上一个字段定**：`palette`（八套之一；写 `none` = 不指定，
落回 `TOKENS` 的米白）。用户挑了哪一套，那一套就是**这条片子二十镜的默认底色**——
引擎把它换算成 `bg`/`paper`/`ink`/`accent` 四色注入每一镜，代码里用
`resolveFilmStyle(getInputProps())` 取（起手模板就是这么写的）：
`const film = resolveFilmStyle(getInputProps()); const bg = film.bg || TOKENS.bg;`。
**不要写死颜色**——写死了用户在卡上换色板，你这一镜不动，整片就它一个色。

**个别镜要另调就在那一镜覆盖**。三档优先级，从高到低：

1. 这一镜的代码里绑了 `const palette = palettes["…"];`（`@dg/themes/palettes.json`）；
2. 这一镜自己申报的 `bg`；
3. 整片那一档 `palette`。

所以「整片一套底色，某几镜另有理由（比如闪回/数据页）才换」是可以的、也是被鼓励的形状；
**逐镜八套轮着配不是**——2026-10-17 起闸⑲ **不再**数色板种数，那一条是反方向的。

## 色温弧线与光源色：底色可以统一，光不能

跨时代、跨场景的片子（历史演进、技术变迁、一天从早到晚）有一件事比「整片一套底色」更重要：
**光的颜色要跟着场景走**。篝火是橙、油灯是琥珀、舞台脚灯是暖黄、CRT 是青绿、手机屏是冷蓝——
把这些全画成同一个 `accent`，二十镜看起来就是同一间黑屋子。

- **`palette` 管的是页面底色、字色与高亮色，不负责光源色。** 镜头代码里给光源单独一个变量
  （`const light = "#ffb15c"` / 从这一镜自己的色板取），不要所有光都拿 `film.accent`。
- **允许逐镜换底色来表达时代与时段**：每镜自己申报 `bg`，或绑 `palettes["…"]`。
  这是「闪回/数据页」之外另一条正当理由——**它换的是色温，不是版式**。
- **整片一致的应该是**：版式与字阶、笔触语言、光位方向、构图节奏、字幕形态。
  底色和光色可以一段一段变；变的是色温，不是画风。
- 历史/文明/器物/传记类选题默认走 `ink-archive`（`vintage-kraft` + `film`/`bleach` +
  `paper`/`ink`）；`midnight` / `deep-ocean` 是数据与科幻的冷调，别拿它配烟火气的内容。
- **先看得清，再谈气氛**（2026-10-20 真机片整体近黑，用户原话「根本看不清」）：
  背景的平均亮度要明显高于主体剪影（牛皮纸浅底 + 深剪影是最稳的一档）；暗场戏也必须
  留一块亮区（火光、灯池、屏幕），不要整幅压到近黑。主体与背景**至少差两档明度**，
  差不够时加边光或压深剪影，不要靠暗角遮。`film` 那档自带的暗角是轻的，不要再用
  代码叠一层更重的 vignette。
- 逐个时代的色温写进 `art.palette_note`（如「火光橙 → 油灯琥珀 → 霓虹粉 → 屏幕冷蓝」），
  它和 `style_grammar` 会一起喂给每一镜的写手。

## 整片美术方向 `art`（有风格要求时必写）

`art` 是整片一处、管所有镜的画法约定。**用户给了参考片、参考图，或明确说了「手绘/剪影/
纸感/水彩/某种光」时，必须写**——不写的话写手只能从风格那句话里猜，最后每镜各画各的。

```json
"art": {
  "look": "单色剪影 + 暖光池……（自己组合的一句话，≤160 字）",
  "brush": "graphite", "light": "left", "texture": "paper",
  "type": "serif-display", "motion": "spring",
  "palette_note": "火光橙 → 油灯琥珀 → 霓虹粉 → 屏幕冷蓝"
}
```

枚举栏不确定就省略，别写枚举外的值；`look` 与 `palette_note` 是自由文本。它不影响计划卡，
也不进缓存键以外的任何判据——它是写给写手与调色那一趟看的。

## 贯穿全片的同一主体：`protagonist`

有一类片子的力量不在任何一镜的细节，而在**同一个东西**从洞穴走到蒸汽、火箭与手机时代：
轮廓、比例、朝向、底缘那条线始终是同一个，只有背景与材质在换。这个「东西」可以是人，
也可以是一头鹿、一辆车、一只箱子、一块发光的矩形。

**同一个人/同一件东西在三个以上的镜里出现，就写这一栏。** 这不是「有参考片才写」的
可选装饰：不写，每一镜的写手会各自发明一个「大概这么高」的主体，切点一过身高、
肩宽、步幅全换一套——观众看到的是几十个人，不是一个人走过几十个时代。

```json
"protagonist": {
  "look": "瘦高、侧面轮廓的剪影：额头、鼻梁、下巴有转折，头发/帽子随时代；手里那盏灯跟着时代换",
  "kind": "人",
  "render": "silhouette",
  "wardrobe": "岩洞：兽皮斗篷 → 蒸汽：工装帽与长外套 → 现代：连帽衫（手里有手机）",
  "height": 0.48, "foot_y": 0.86, "facing": "right",
  "stride_sec": 1.0, "light": "火光橙 → 车窗暖黄 → 路灯 → 手机屏冷蓝"
}
```

人用 `@dg/lib/walk` 的 `<WalkingFigure/>` 时，衣服与随身物由 `outfit` 一组参数给，
**不是每镜另画一套骨架**。整片只选一次 `build`，逐镜只换 `outfit` 里这几项
（写 brief 时就按时代写清「穿什么、戴什么、手里拿什么」）：

| 参数 | 可选值 |
|---|---|
| `garment` | `none` / `tunic` / `robe` / `toga` / `coat` / `dress` / `suit` / `hoodie` / `armor` / `pelt` |
| `sleeve` | `none` / `fitted` / `wide` / `bell` / `puffed` |
| `length` | `hip` / `knee` / `calf` / `ankle` / `floor` |
| `flare` | 0~1，下摆外扩 |
| `headwear` | `none` / `cap` / `futou` / `tricorn` / `top` / `brim` / `helmet` / `hood` / `straw` / `crown` |
| `hair` | `short` / `bun` / `ponytail` / `long` / `bald` |
| `prop` | `none` / `cup` / `book` / `staff` / `cane` / `umbrella` / `lantern` / `torch` / `phone` / `bag` / `scroll` / `tool` |
| `build` | `male` / `female` / `neutral`（整片只选一档） |

```tsx
<WalkingFigure x={x} footY={H * 0.86} height={H * 0.48}
  facing="right" strideSec={1.0} phase={phase}
  outfit={{ garment: 'robe', sleeve: 'wide', length: 'ankle',
            headwear: 'futou', hair: 'bun', prop: 'scroll', build: 'male' }}
  rim="#ffb15c" />
```

用户说「明代读书人，青衫、乌纱帽、手里一卷书」，就翻成上面这一组；说「18 世纪欧洲
学者」就换 `coat` + `tricorn` + `book`。翻不到最近的版型时选最近的一档，别自己发明
新枚举值——认不出的值会落回缺省，画面就变成「没穿那件衣服」。

一块贯穿全片的发光矩形就是这样写：

```json
"protagonist": {
  "look": "一块竖立的矩形，边缘一圈暖光，表面有细密的扫描线",
  "kind": "发光的矩形",
  "render": "lit",
  "height": 0.34, "foot_y": 0.72, "facing": "right",
  "light": "火光橙 → 煤气灯青 → 屏幕冷蓝"
}
```

这栏一写，**每一镜的写手都会把这个主体放进去**，包括文案没提到它的镜。所以反过来也成立：
没有贯穿主体（纯器物轮换、纯数据、纯概念）就**别写**——写了等于让二十几镜硬塞同一个东西。

`render` 是画法方向：`silhouette` 剪影 / `flat` 平涂上色 / `lit` 受光面与背光面两档
（要「不是阴影、是真实的样子」就选它）/ `line` 线稿。

具体怎么画（姿势、骨架、比例、服饰、动作）由写手按 brief 自己决定；这一栏只给连续性：
每一镜用同一组 `height` / `foot_y` / `facing` / `stride_sec`。运动相位接**全片时钟**，
不能每镜从 0 起算（否则切点处换脚、重新起步）：

```tsx
import { getInputProps, useCurrentFrame, useVideoConfig } from 'remotion';
const { filmStartSec = 0 } = getInputProps();
const frame = useCurrentFrame();
const { fps } = useVideoConfig();
const phase = ((filmStartSec + frame / fps) / 1.0) % 1; // 0~1 周期相位，不是秒
```

x 随时间朝 `facing` 方向推进，真的往前走，别整镜钉在一个点上踏步。

要写实/有体积时选 `render: lit`（上面那行），不要默认纯黑剪影；材质用高光与反射
区分，而不是一圈黑边。代码能做到的是「有体积的插画」，不是照片——选题要照片级
实拍时，先跟用户说清楚这一层边界。

有了贯穿主体，背景要**按它的行进方向往后掠**（近层快、远层慢），主体在画面里**真的
往前走**（x 朝 `facing` 方向推进，别整镜钉在一个点上踏步）；每镜换的是时代的那一层
（洞穴壁、车窗、发射架、办公室玻璃），不是换一个主体。人是剪影时可以不画五官——
要指一个人就配一句名字标注。

## 3 档风格组合（整片默认，不是逐镜配额）

`remotion/src/themes/palettes.json` 的 `preset` 段定义三档**推荐组合**（色板 + 质感 + 字幕两维 + 主体来源）。
这三档是**整片默认这一份怎么填**的参照：挑定一档，把它的 `palette` / `texture` /
`caption_style` / `highlight_style` 一并写进 spec 顶层——**整片就统一到那一套**，
这是用户一眼看得出来的那种一致（底色与字幕）。

| 档 | 色板 | texture | 字幕（样式 + 高亮） | 主体来源 | 适用选题 |
|----|------|---------|--------|----------|----------|
| `ink-archive` | `vintage-kraft` / `modern-light` | `film` 或 `bleach` | `paper` + `ink` | 手绘纸感优先：纸纹、线条插画、档案图纸 | 历史、器物、人物传记 |
| `tech-data` | `modern-light` / `color-play` | `none` | `on_picture` + `color` | 代码优先：矢量图、公式、数据卡、图标 | 概念解释、数据对比、流程 |
| `night-concept` | `deep-ocean` / `midnight` / `obsidian-violet` | `glow` | `film_line` + `color` | 3D/光优先：三维、光效、人物剪影 | 科学、宇宙、抽象概念 |

**逐镜覆盖**写在那一镜上：底色改那一镜代码里的 `const palette = palettes["…"];` 或它申报的
`bg`；质感与字幕两维在这一镜单独申报（只有那一镜确有理由才换）。跨镜一致性的账由 ⑩（字色对
底色的对比度）与 ⑨（跨镜同构）来记；闸⑲ 管的是**构图**那一侧——满幅镜数、质感种数、
`bg` 申报率，**不管色板种数**：「二十镜共用一个调子」不再是错，那正是用户要的东西。

## 代码模板

`remotion/src/user-shots/shot.tsx` 就是这份形状的活样例（每次渲染前被覆写，改它就是改起手模板）。

```tsx
import React from "react";
import { AbsoluteFill, getInputProps, interpolate, random, useCurrentFrame, useVideoConfig } from "remotion";
import { CaptionText, resolveFilmStyle } from "@dg/film";
import { TOKENS } from "@dg/tokens";
import { E } from "@dg/motion";

const Shot = () => {
  const frame = useCurrentFrame();
  const { width, height, durationInFrames } = useVideoConfig();   // 整帧；坐标就是设备像素
  const t = frame / Math.max(1, durationInFrames - 1);
  // 整片那一档：底色 + 墨色 + 强调色。缺了就落 TOKENS 的米白
  const film = resolveFilmStyle(getInputProps());
  const bg = film.bg || TOKENS.bg;
  const ink = film.ink || TOKENS.ink;
  const accent = film.accent || TOKENS.accent;

  return (
    <AbsoluteFill style={{ backgroundColor: bg, fontFamily: TOKENS.fontStack }}>
      {/* === 这一镜的画面：照整片 style 写，自己铺满整帧 === */}
      {/* === 底色/墨色/强调色别写死：用户在卡上换色板，你这一镜要跟着走 === */}

      {/* === 字幕排进构图：位置与画面里某件东西对齐，这里示例挂在画面下缘留白 === */}
      <div style={{
        position: "absolute", left: width * 0.08, top: height * 0.72,
        width: width * 0.84, color: ink, lineHeight: 1.38, fontWeight: 600,
      }}>
        <CaptionText fitWidth={width * 0.84} />
      </div>
    </AbsoluteFill>
  );
};
export default Shot;
```

**这一镜要另配色板**（个别镜覆盖）就在这一镜里绑一套，别改整片那一档：

```tsx
import palettes from "@dg/themes/palettes.json";
const palette = palettes["deep-ocean"];        // 只对**这一镜**生效
// 此后底色用 palette.page、强调色用 palette.accent
```

## 禁止事项

- **禁止 Math.random / Date.now / new Date**：用 `rand(seed)` 或 remotion 的 `random(seed)`。seed 必须给固定值。
- **禁止裸写颜色字面量**：底色、字色、描边一律从 `palettes.json` 取（`const palette =
  palettes["…"];`，键 `page`/`surface`/`field`/`text`/`muted`/`accent`/`border`）。
  闸⑩ 逐镜量字色对底色的对比度，写死的色值没有色板可对账。
  （`DesignStage` 按**整帧宽度**缩放——别让它与你自己的画布各放大一次。）
- **禁止外链**：镜头代码里不许出现 http/https 地址取图、取字体、取脚本——渲染容器不联网。
  `staticFile` 只用来取**字体**（`@remotion/fonts` 的 `loadFont` 要 `staticFile('fonts/…')`）。
- **字体必须用白名单字族**：`Noto Sans CJK SC`、`Noto Serif CJK SC`、`Noto Sans Mono CJK SC`、
  `DejaVu Sans`、`DejaVu Sans Mono`、`DejaVu Serif` 等 18 个镜像内已装字族。
  lint 规则 `dg/font-family-whitelist` 逐属性检查，非白名单字族逐镜打回。
  用 `fitText` 时默认走 `TOKENS.fontStack`，不用手写字族名。

## 写法纪律（lint 规则在渲染前判）

- **字段标注**：用 `<F name="字段名" value={fields.字段名}>` 标注可调旋钮的位置，
  `F` 从 `@dg/film` 导入。旋钮先在 `fields` 那一栏声明，每项 `{name, type, value, label?}`：
  `type` 只能取 `number`/`color`/`text`/`bool`/`select` **五种**，声明的值落 `fields.<name>`
  （代码里就认这一个名字）。lint 规则 `dg/field-drift` 检查：
  声明了却没人读（fields 里有但代码没引）、读了却没声明（代码引了但 fields 里没有）、
  不是这个字段自己的值（`<F name="x">` 里读的不是 `fields.x`）。
- **随机种子**：`rough.generator` 等 API 要传 seed，`seed 必须给`固定值，保证逐帧可复现。
- **音频时长**：长样本（>5s）要显式给 `durationInFrames`，否则会拖到动作结束后还在响。

## 官方写法（六条，只此六条）

1. 动效全由 `useCurrentFrame()`+`interpolate()` 承载——CSS `transition`/`animation` 逐帧渲不对。
2. 默认缓动取 `@dg/motion` 的共享件 `E.standard`（`Easing.bezier(0.16,1,0.3,1)`）与 `E.spring200`（`damping:200`），别自选曲线。
3. 观感线性给 `output:'perceptual-scale'`；台阶感给 `posterize:3`。
4. 位移/缩放/旋转用独立属性（`scale`/`translate`/`rotate`），不拼 `transform` 串。
5. `interpolate()` 写在 `style` 内联里（闸⑥ 靠它读字段标记）。
6. 秒→帧用 `useVideoConfig().fps` 换，不许写死 30。

# 一镜有哪些栏

`shots[]` 每一项：**id**（如 `s01`）、**text**（必填）、**brief**（必填，画面描述）、
**entities**（可省，这一镜要画进画面的实体清单，≤5 个）、
**code**（可省，省了由系统按 brief 写）、**highlight**、**fields**、**min_duration_sec**、
**texture**（省略=跟整片默认）、**source**。

另有两个**版式档** **bleed** 与 **bg**（满幅与底色，省略=常规版式，见下面「版式档」那一节）。

- `text` 容量按画幅：竖屏与方屏 ≤ 60 字、横屏 ≤ 110 字。这句话是这一镜的**字幕**，由这一镜
  的代码用 `<CaptionText/>` 排进构图；画面里不必再画一行同样的字。
- `brief` 不超过 400 字，写「画什么、怎么构图、怎么分几拍动」（见「这一镜画什么」开头的三步）。
- `highlight` 里每个词**必须是该镜文案的子串**，每镜 ≤ 4 个。不是子串的词、以及第 5 个起的词，
  系统会直接丢掉（这一镜照常入库，那几个词只是不亮）；确认卡的逐镜账列的是实际生效的词。
- **有旁白时不要写每镜时长**。镜头长度归真实语音时长。
- **无旁白时必须给每镜 `min_duration_sec`**：画面要给观众时间读字幕+看画面，每镜 8~12 秒。
- 首尾各留一镜：开场与收尾的呼吸镜（`min_duration_sec` 给 1.5~2.5）。
- `source` 如实填。没查到的不要写上去。数字型事实注明**数据期**（`{"标题": …, "链接": …, "数据期": "2025 年"}`）——出处对账只对「查没查过」记账，查的是哪一期要你自己写清。
  写成「查证过」却对不上本会话检索账的出处，系统会**就地改成「未核实：…」再入库**（不退回重交）；
  要它算查证过，下一版把检索结果里的标题/链接原样填上即可。

# 时长与镜数

- 「X 分钟以内」是**上限**不是**目标**——90 秒也是「4 分钟以内」；「X 分钟左右」才是目标。
- **`target_duration_sec` 每一次调 plan_motion 都要带**，也可写在 spec 顶层。
  时长在 plan_motion **入库前**就对齐与把关，过了这一关，出片时不会再因时长被拦。
- **没旁白**：每镜时长＝`max(min_duration_sec, 2.6 + 0.16×字数)`，是确定值不是估算。总长对不上目标时
  **系统会按比例自动调各镜驻留**（拉长时每镜最多到原长的 1.25 倍），你不用为几秒的差去重写分镜。
  一镜驻留超过 15 秒会显得拖：长片优先**加镜**，经验值是 4 分钟 ≈ 20~30 镜。
- **有旁白**：时长归真实语音，估算是「每字 0.2~0.3 秒 + 每镜 0.6~1.2 秒」；偏离太多会在 plan_motion 打回，
  按回执里的镜数建议加镜或加长文案。
- **镜多时用 `code_from` 复用版式**：一镜写 `"code_from": "s03"`、不写 `code`，就复用 s03 的代码，只换
  `text` / `fields` / 色板。十几种版式撑几十镜，一次调用装得下；别为凑镜数把同一段代码抄几十遍。
- 用户给的时长/画幅/帧率是约束条件，约束之间有冲突时你自己判断怎么处理，在答复里说明。

# 文案合同（每镜那句话要撑起整条片子）

- **每镜至少落一个具体项**：数字、年份、地名、人名、器物名、专名、比例、因果链上的一环。
- **不要写引子镜**。开场那一镜也要给东西。
- **一句话只说一件事**。字幕条放不下第二件事——拆成两镜。
- **文案与画面互为注解，不是互相复述**。文案说「人口从 1 亿涨到 4 亿」，画面就该把曲线画出来。
- **术语第一次出现要给一句白话**。
- 相邻两镜**不要同一主语的两种说法**。

# 查资料：后端链与出处账

- web_search 的每条结果都带标题与网址（第一行是标题，其下是该页 URL），调 plan_motion 时把这些原样填进 `source`。
- 查不到就说查不到，不要编。`source` 留空比编一个强。
- 出处不进画面（除非用户要求），但进分镜卡和逐镜账。

## 会过期的数字：先查「最新一期」再取数

有些事实会过期——用户规模、使用时长、份额、价格、排名、人口、政策口径、某个东西
「现在」的状态。**写进文案之前先问「最新一期是什么」，再问「数字是多少」**；顺序反了，
拿到的就是训练数据里那一版。讲历史、讲原理的旧年份没关系，这种统计值不行。

- 检索词带上当前年份或「最新 / 第 N 次报告 / 年度报告」，例如
  「短视频 人均 每日 使用时长 2026 报告」。搜到年度报告先看**数据期**：2026 年出版的
  报告，统计的往往还是 2025 年（甚至 2024 年）。
- 文案里写数据期，不写「目前 / 如今 / 现在」：「2025 年，中国短视频用户人均每天…」。
  观众读到年份，才知道这个数有多新。
- 一句话里的数只取**同一期**的口径，别把 2024 年的人均时长和 2025 年的用户规模拼在一起。
- 最新一期查不到，就用能拿到的最新一版，并在 `source` 里加一行 `数据期：<年/月>`；
  两期都拿不到就不写这个数——换一句不需要它的说法，别凭记忆填。
- 分镜卡回执里有 `freshness_warnings`：点名哪几镜的数字标的是两年前的年份（或没填出处）。
  看到就先按上面几条处理，再交版。

# 字自己排：字幕是画面的一部分

**每一镜的整句字幕由这一镜的代码排进画面**——站哪儿、多大、什么字族与颜色、和图形怎么
对齐，都是这一镜的构图决定。母版已下线：画面上没有「系统叠上去的那条字幕」，你在代码里
把字放在哪，观众就在哪看到它。

**这一片写了片壳（`shell`）时，这一节换成片壳的做法**：底部字幕由片壳统一排，全片同一个
位置和字号。这一镜不再排旁白字幕，也不要用 `<CaptionText/>`、`<CaptionLayer/>`、
`<CaptionFrame/>` 去排它；画面下沿照样留出相对干净的一带，给片壳的字幕。

**缺省写法是 `<CaptionText/>` 叠在画面上**：套一个定位盒子放在下沿（`bottom` 约画面高
3%~5%），`fitWidth` 取画面宽的 **0.58~0.66**。参考片里那条中文字幕只占画面高约 4%——
**不要用 0.84~0.88 的满宽**，那会把字放大成一条横幅；也不要在画面下方单切一条黑带。
字压在图上，所以画面下沿约 12% 要留出相对干净的一带（渐隐、暗部、地面），别把主体或
高对比花纹塞在那里。

**画/字分带（`<CaptionFrame>`）是可选项，不是缺省**：只有这一镜确实需要一条独立字幕带
（图解、表格、竖屏信息页）时才用。它**自己就会画这条字幕**——用了它就不要再在里外另摆
`<CaptionText/>` 或 `<CaptionLayer/>`，否则同屏两条字会叠成重影（真机上出现过）。用分带时
按 `art.w × art.h` 排画面，底色写在 `<CaptionFrame style=…>` 上。

要**咬合**（字当图注、贴着图表或物体摆）时，用 `<CaptionText/>` 套定位盒子——这时位置与
主体的不撞由你保证。
**不要每一镜都往底部丢一个裸 `<CaptionLayer/>`**——那是一条「底部两行大字」的整条预设，
与这一镜的构图无关；二十镜都这么丢，就是「字幕和画面违和」本身。

## 字站哪：按这一镜的构图挑一处

| 这一镜是什么 | 字站哪 | 怎么排 |
|------|-----------|--------|
| 数据页 / 图表 / 版式页 | 图表正下方，或右侧栏的下缘 | 与图表/栏的左缘对齐、同一套字阶；比图注重一级、比大数字轻一级 |
| 杂志页 / 海报页 | 页边的留白（下缘或侧边） | 衬线体左对齐、行距松；与色块边缘对齐，像印刷图注 |
| 满幅插画 / 场景 | 叠在画面下沿（或顶部留白） | 用 `<CaptionText/>` 套盒子，`fitWidth≈0.62×宽`；与主体的地平线或视线对齐，下沿留出干净的一带 |
| 数据卡 / 竖排 | 卡片内底部的说明位 | 与卡片内衬对齐，不跨出卡片边界 |

字的**缺省处理**：白字黑边（`outline="#000000"`），整条字同色；**不写 `emphasis`**，
让它跟整片那一档的高亮样式走。只有用户点名要「关键词换色 / 高亮」时，才写
`emphasis="color"`。同片别一镜换色一镜描边、也别逐镜各写一份高亮——观众读到的
不是两种风格，是两种字幕。

## 硬约束（闸会逐条判）

- **整句只画一处**：`text` 是注入的整句，别在别处再写一份（重影）。
  **`<CaptionFrame>` 已经画了这条字幕**——用了它就不要再摆第二份
  `<CaptionText/>` / `<CaptionLayer/>`。
- **别手搓第二份字幕**：自己 `splitByHighlights` + 自己乘字号，两次求出来的字号与断行
  迟早对不上。要摆字就用这几件元件。
- **最多两行**：用 `fitWidth` 让 `<CaptionText/>` 自己求字号；要与画面元素精确对齐
  才改用 `fontSize` 直接给。
- **不压主体、不出安全区**：闸⑧ 判「字被图形盖住 ≥30%」，出画也报。
  整帧一个场景时用 `<CaptionFrame>` 分带——这一条由结构保证（画面被裁在字幕带外）。
  只有自排字（`<CaptionText/>` 套盒子）时才要自己算：字盒先按行数估高——两行 ≈
  字号 × 行高 × 2（横屏满字号时约画面高的 1/4）：`top` 写到
  画高 0.72 以下就要连着两行一起算，拿不准就写 `bottom: …` 兜住底边；`left + width` 也
  别越过两边边距。`<CaptionText/>` 渲染时会把越界的字平移回画内，但挪回来的字多半压住主体，
  构图一开始就算对。
- **字色对底色过闸⑩**（正文 3:1）。
- **同一片子的字要是一套**：各镜可以摆在不同位置，但字族/字重/描边/高亮的处理一致。

## 四件字幕元件

`@dg/film` 导出四件，与母版当年画的那条字幕**是同一份实现**（同样逐词点亮、同样按可用宽度
求字号、同样跟着色板配色）。所以「字自己排」不等于「自己重写一套字幕」：

| 元件 | 是什么 | 什么时候用 |
|------|--------|-----------|
| `<CaptionFrame>` | **画/字分带**：字幕带 + 画面区（画面被裁在带外），**内部已经画了字幕**，`children` 可以是函数拿到 `art` | 只有确实要一条独立字幕带（图解/表格/信息页）时用；**不是缺省** |
| `<CaptionText />` | **只有字**：逐词点亮 / 关键词换色 / 底色块 / 撕纸笔触 / 黑描边 / 自动字号 | **缺省用它**：套一个定位盒子叠在画面上（下沿/顶部/图注位），`fitWidth≈0.62×宽` |
| `<CaptionLayer />` | **整条**：底 + 字 + 入场动画，位置/字号/安全区全按「字幕样式」那一档排 | 只在「整屏都是画面、找不到能排字的干净区域，确实要底部一条」时用；**不是缺省** |
| `useCaptionTiming()` | 这一镜的**词时间轴**：`{ timed, reached(i), charFrames, pieces }` | 让画面里别的东西跟着念到的词动 |

```tsx
import { CaptionFrame, CaptionText, CaptionLayer, useCaptionTiming } from '@dg/film';

// ① 缺省：叠在画面下沿。字小、居中，下沿 12% 不要塞主体或高对比花纹
<AbsoluteFill style={{ background: bg }}>
  <svg viewBox={`0 0 ${width} ${height}`} style={{ position: 'absolute', inset: 0 }}>
    {/* 满幅场景：主体占画面 40%~70%，下沿留出相对干净的一带 */}
  </svg>
  <div style={{
    position: 'absolute', left: width * 0.19, width: width * 0.62,
    bottom: height * 0.04, textAlign: 'center', color: ink, lineHeight: 1.35,
  }}>
    <CaptionText fitWidth={width * 0.62} outline="#000000" />
  </div>
</AbsoluteFill>

// ①-b 可选：确实需要独立字幕带时用（它内部已经画了字，不要再叠 CaptionText）
<CaptionFrame style={{ background: paper }} band={height * 0.14}>
  {(art) => (
    <svg viewBox={`0 0 ${art.w} ${art.h}`} style={{ width: '100%', height: '100%' }}>
      {/* 按 art.w × art.h 构图：主体占这一格的 40%~70% */}
    </svg>
  )}
</CaptionFrame>

// ② 咬合：把整句排进自己的构图（这里是一张数据页的图注位，与图表左缘对齐）
<div style={{ position: 'absolute', left: chartX, top: chartY + chartH + height * 0.05,
              width: chartW, fontFamily: serif, lineHeight: 1.42,
              fontWeight: 700, color: ink }}>
  <CaptionText text={text} highlight={highlight} words={words}
               outline="#000000" fitWidth={chartW} />
</div>
//    `emphasis` / `outline` 省掉就跟着整片那一档走；缺省是白字黑边、整条同色

// ③ 整屏都是画面、没有能排字的干净区域：这时才用整条预设
<CaptionLayer />

// ④ 让图形跟着念到的词动——不必自己再实现一遍逐字时间
const { reached, charFrames } = useCaptionTiming();
<div style={{ transform: `translateY(${reached(0) ? 0 : 40}px)` }}>…</div>
```

`<CaptionFrame>` 的 `art` 就是这一镜的坐标：`art.w × art.h`，原点在画面区左上角。它还
收 `side`（字幕带在顶/底）、`band`（带高，缺省按字幕档算）、`align`、`inset`。

四件的 props **全部可省**：省了就取注入的那一份（这一镜的整句、高亮词、词时间轴、
色板），所以 `<CaptionText/>` 就是「这一镜的字，摆在这儿」。`fitWidth` 是给它求字号的可用
宽度（设备像素）；**描边与下划线的宽度要按像素算，别用 `em`**（字号是元件求的，`em` 会在
外层先解析成外层那个字号）。

### 字进画里

`<CaptionText/>` 是普通 HTML，摆在哪儿就在哪儿：招牌上、卡片里、图注位、物体旁边都行。
要跟着 SVG 的坐标走（贴着一条弧线、跟着物体旋转、嵌进版画里），把它放进
`<foreignObject x y width height>`——图的 `viewBox` 与设备像素 1:1 时字号不用换算。

**仍然用这一件，别手写 `<text>` 当字幕**：逐词点亮、断行、字号、描边、高亮色都是它一处
算的；手写一份，等于每镜各实现一遍用户选的那一档，三十镜就有三十份会走样的样式
（上一版「白字黑边」渲成黑字就是这么来的）。用户没选过时，缺省是「白字黑边 +
关键词换色」；你可以用 `emphasis` / `outline` / `accent` / `fontSize` 逐镜自由发挥。

- **申报 `caption_style: "none"`（不上字幕）的镜别再摆 `<CaptionLayer/>`**：它自守不画，
  闸㉜ 会把那种自相矛盾的代码打回。摆 `<CaptionText/>`（画面里的字）不受这条限制。
- **缺省别用起手模板的底部整条**：起手模板只是一个能跑的最小骨架；把字排进这一镜的
  构图，才是「字幕是画面的一部分」。

## 字幕两维：字幕样式 × 高亮样式（整片默认 + 逐镜覆盖）

分镜表里与字幕有关的是**两栏**，它们是**正交**的两件事：

| 栏 | 取值 | 说的是 |
|----|------|--------|
| `caption_style` | `by_shot` 交给这一镜自己设计（缺省，2026-10-23）/ `outlined` 白字黑边 / `on_picture` 贴画面无底 / `paper` 纸条底 / `film_line` 整句电影感 / `big_center` 大字压屏 / `top_banner` 顶部横幅 / `none` 不上字幕 | **整条预设**长什么样、站哪（用 `<CaptionLayer/>` 时生效）；你自排 `<CaptionText/>` 时，它只提示字的**处理**该往哪边靠 |
| `highlight_style` | `color` 关键词换色（缺省）/ `karaoke` 逐词点亮 / `block` 底色块 / `ink` 撕纸高亮 / `plain` 不强化 | 被点名的词**怎么被点出来** |

两维相乘＝35 种组合都说得出口：要「关键词换色但不要纸条」就写
`caption_style: "outlined"` + `highlight_style: "color"`（白字黑边，换色的词照样换色）。
**别把它们想成一排档**——没有哪一档同时锁死这两件事，所以也没有「选了这个就必须接受那个」
的时候。

**整片只写一档**：顶层写 `by_shot`（缺省，字幕归这一镜的代码设计），逐镜**不要**再写
`caption_style` 覆盖。真机片里一半镜写 `on_picture`、一半不写，成片里同一部片的字幕
一会儿有描边一会儿没有，读起来像三个人的片子——这一栏是整片级的缺省，不是逐镜画法。

**`by_shot` 档下字幕是你的活**（2026-10-23）：母版那条不画、`<CaptionLayer/>` 不会被
自动补上、你画在字幕带里的字也**不会**被删。文案从 `getInputProps().text` 读，要高亮的
词在 `highlight` 里。**别用 `<CaptionText/>` / `<CaptionLayer/>` 的缺省形态**——它们的
字号与描边来自母版的 `CAPTION_LOOK`（0.44 系数 + 黑描边白字），换位置也换不掉那张脸，
**那正是「所有片子的字幕长得一模一样」的原因**。自己排就用裸 `<div>`/`<span>` 写全样式
（fontFamily / fontSize / color / textShadow）；确实想复用那两件，就必须显式传
`sizeScale` / `outline` / `bottom` / `tone`，不要留空。

想回到「母版统一排」的老路，就把整片写成 `outlined`（或别的固定档）——那一档下母版会
自动补一条字幕，你只管画面，别在字幕带里再放字。

这两维说的是「**怎么**点出来」，还有一个整片级的 `highlight_color`（`#rrggbb`，空＝跟这一镜
的色板）说的是「**用哪个色**」——它由用户在「文字库」钉，钉住时**盖过高亮词那一色**，连你在
`accent` 那一栏写的那一色也盖过。所以你照常写 `palette.accent` 即可，不必去读它、也不必为它
改构图：那一栏写的是「没有用户偏好时该长什么样」。

整片那一档写在 spec 顶层当默认（用户在「文字库」里挑的就是它），某一镜要换就写在**那一镜里**
（逐镜那一份赢）。两栏是**注入进来的值**：`captionStyle` / `highlightStyle` 就在 props 里，
接不接是你的决定：

- **自排一条字**（缺省写法）：位置就是你那个盒子的位置，入场就是你自己的 `interpolate`；
  高亮与字幕样式两维都交给元件——`<CaptionText/>` 不传 `emphasis`/`outline` 就跟着注入
  走（用户选了「白字黑边」，它自己就上描边、把字换成浅色；外层盒子写的 `color` 不再决定
  字色）。`captionStyle` 仍然告诉你**字的处理**该往哪边靠：`on_picture` ⇒ 无底换色、
  `paper` ⇒ 可以自己铺一条纸色带。**位置永远由这一镜的构图定。**
- **整条预设**只在整屏都是画面、没有干净区域时用：摆 `<CaptionLayer/>`，位置/底/入场
  按那一档照排。
- 自排的字若要**精确对齐画面里别的元素**，用 `fontSize` 直接给字号；`fitWidth` 给的是
  「按两行求」的可用宽度。

字号由元件按「最多两行」自动排（夹在几何表字号的 0.62~1.25 倍之间，再乘这一档自己的系数），
不会再出现长句缩成蚊子字、短句撑破纸条。**自排时（给了 `fitWidth`）两行总高再夹在画面高
的 20% 以内**：盒子给得再宽，字也不会一路长到吃掉画面；要更大或更小就自己给 `fontSize`。**逐词点亮**要有词时间轴才动得起来，没旁白时它
退化成整句常亮——要做卡拉 OK 就同时给 `words`；没旁白就别假装逐词。

`none` 那一档是「这一镜不上字幕」：`<CaptionLayer/>` 在这一档自守不画（摆着也不会出字）。
要摆的是**画面里的
字**（`<CaptionText/>`）就不必改成 `none`——闸㉜ 只管整条那件。

## 字不许压在图上

**判据**：一块字被**画出来的图形**盖住**这块字自己的 30% 以上** ⇒ 这一镜被打回重看（闸⑧ 的
第四类命中 `overlap_subject`）。

「画出来的图形」＝ SVG 图元（`path` / `rect` / `circle` / `ellipse` / `polygon` / `polyline` /
`line`）、`<canvas>`、`<img>`、`<video>`。**涂了底色的 `<div>` 不算**（那是卡片自身，不算主体，
口径同 ⑲-a）。两条剔除，不剔除就会满屏误报：

- **铺满整帧的图形件不算主体，算底色**（占画面带 **≥85%** 的按底色放过）。你每一镜都铺着一层
  底纹 `<rect>`，字当然压在底色上——不放过它，**每一条字幕**都会报。
- **与这块字有祖孙关系的图形件跳过**（字自己的底板就是这一种）。

**怎么排才不报**：

1. **给字留一块空地**。主体（人/物/图）画在一侧，字幕带在另一侧——这是每个镜都该先想的一步，
   不是排完再挪。
2. **要用衬底就用 `div`，别用 SVG 图形件**。SVG `<rect>` 在账上算「画出来的图形」：它压在
   你的字上（或你的字压在它上）就会报，哪怕它本来只是块底纹。做纸条/底板一律写成
   `div` + `background: linear-gradient(...)`（lint 也要求纯色底板写成渐变）。
3. **要压在图上当标注**，就把这块字的盒子**缩到图的一角**——被盖住的面积占比自然就下去了。
   判据判的是「这块字还读不读得出来」，不是「字和图形有没有碰过」。

读数在回执与预览静帧那一栏都能看到（`layout_warnings`；`layout_unscanned` 单独一栏，
「没扫」与「扫了且干净」是两件事）。预览静帧带上读数意味着**还没烧整镜就能看见这条**——
那是最便宜的改法。

# 版式档：满幅 bleed 与底色 bg

这两栏**每镜可选**，它们申报的是**构图**（画面铺多大、底色是什么），不是滤镜——
`texture` 那一档改的才是画面上的颗粒与暗角。母版下线后**没有「常规版式」这个缺省**：
省略＝没有额外要求，构图怎么排是你的事，这两栏是**你做完了报给闸听的**。

| 栏 | 取值 | 省略时 |
|----|------|--------|
| `bleed` | `true`（布尔，**不是字符串**）| 你自己定（闸⑲ 也就不把这一镜算作满幅） |
| `bg` | `#rgb` / `#rrggbb` | 闸④ 判空的基准色退到 `TOKENS.bg`（回读也拿不到时） |

**这两栏是申报，实现归你**：`bleed: true` 的实际含义是「**这一镜的画面铺满整帧**」，
而铺满靠你在代码里铺
（`<AbsoluteFill>` 顶到底、不留边距）。**申报与代码必须对得上**：闸⑲ 按这一栏数满幅镜、
回执也按它报，申报了却没铺满就是「账上写满幅、成片上看到留边」。
`bg` 同理，是这一镜的**底色宣言**：闸④ 判空拿它当基准色（母版回读拿不到时退到它，
再退到 `TOKENS.bg`），所以代码里的底色要与它一致——不一致时判空比的是另一个颜色，
`空壳` 与 `小气` 两条的读数都会歪。

**`bleed` 是纪律，不是「想写才写」的可选项**——闸⑲ 会数它，两条下限：

- **用深色板的镜必须写**：`midnight` / `deep-ocean` / `obsidian-violet` 这三套的 `page` 都是
  深底，配一个四周留边的居中构图就是「页边一圈奶油、中间一块深色」。这几镜写
  `bleed: true` 并同时给 `bg`（用该镜色板的 `page` 值）。
- **整片每 5 镜至少 1 镜满幅**：满幅镜数 ≥ `ceil(镜数/5)`（20 镜 → 4 镜、10 镜 → 2 镜、
  6 镜 → 2 镜）。画**整屏插画、满版描线、大场景、背景要铺满**的镜头一定写它；
  常规图文镜可以留省略，但上面这两条下限照样要满足。

两条要注意的：
- **满幅镜的字幕会贴到画面底部**（你自己摆的那条字也一样）：构图主体别压在最底下那一带
  （竖屏约底部 120px、横屏约 72px）——你摆字的地方就是观众视线最后的落点。
- **`bleed` 写成 `"true"` / `1` 一律不生效**（判的是严格的布尔 `true`），而且校验期就会
  被打回——别用字符串。

**`bg` 只收十六进制**：闸④ 拿它当「这一镜画了东西没有」的基准色，
写 `rgb()`/命名色/渐变会被打回（收了等于让闸④ 在这一镜上闭嘴）。深底镜给了 `bg`，
`texture` 那档就**别再加 `film`**（`film` 自带暗角与颗粒，压深底会糊成一片）。

**最有用的两个组合**：
- `bleed: true` ＝**整屏插画 / 白板板书**，文字与图一起构图（字用 `<CaptionText/>` 摆，
  别手搓——见「字自己排」那一节）。
- `bg` + 一点留边的居中构图 ＝ 在一支浅底片子里给某几镜**换底色**（夜里的一镜、切场景的一镜）。

```tsx
// 满幅镜：整帧都是你的画布，坐标从 0 到整帧尺寸
const { width, height } = useVideoConfig();   // 竖屏 1080×1920、横屏 1920×1080、方屏 1080×1080
```

# 转场与进出场（转场可逐接缝，进出场整片一档）

这两件**默认都在计划卡上勾**（整片的观感决定，让二十份模型现写的代码各自插一小段动画，
等于交给二十次掷骰子）。但**只有转场是「一行都不用写」**——它落在合成成片那一步，
逐镜切片一个字节都不动；**进出场落在每一镜的画面里**，所以它只能是「注入给你的两个数、
你自己画」（见本节末段）。逐镜覆盖那一档也只属于转场：覆盖写在分镜里、不进镜头代码，
掷骰子的问题不存在。

**转场**（`transition`，镜与镜之间怎么接）：

| 档 | 观众看到什么 |
|----|-------------|
| `none` | 硬切，镜镜直接接（默认） |
| `fade` | 淡叠·前一镜淡出后一镜淡入 |
| `dissolve` | 溶解·两边互相化开 |
| `wipeleft` | 左擦·新画面从右往左推过来 |
| `wiperight` | 右擦·新画面从左往右推过去 |
| `slideup` | 上滑·新画面自下而上顶入 |
| `circleopen` | 圆开·从中心扩开 |

**叠多久**（`transition_sec`，只给四个档位）：0.2 / 0.4 / 0.6 / 0.9 秒。
转场是拿相邻两镜的**重叠区**做混合的，所以叠的时长必须短于相邻较短那一镜的一半——
3 秒的镜头配 0.9 秒已经接近上限，短镜（开场呼吸镜那种）要配更短的一档。
给了配不上短镜的档位，会在**拼接之前**被打回并指出是哪一处接缝。

**这一档决定拼接要多久**：整片 `none` 时逐镜切片的编码参数一致，拼接是纯字节拷贝，
几秒完事；只要有一处叠化/擦除，整片就要重新编码一遍——四五分钟、五十来镜的片子，
这一趟约多花八到十分钟，而且是整条链里最重的一步（几十路输入同时解码）。
没有非叠不可的理由，留在 `none`。

**逐接缝覆盖**（`transition` 写在**某一镜**上，表示**它之后**那一处接缝用什么）：
专业动效里转场本来就是逐接缝的——整片统一淡叠，但「结论那一镜」用圆开推上去，
是常见做法。写法：把 `transition` 写在那一镜里（`{"id": "s07", "transition": "circleopen"}`），
它只改 s07 之后那一处接缝，其余各处照旧跟整片那一档；时长沿用整片 `transition_sec`。
**末镜写这一栏无效**（它后面没有接缝了）。
整片压根不转场（`none`）时，被覆盖的那一处取默认时长——所以「整片硬接、只有一处圆开」
是写得出来的。**成本优势在这一栏上兑现**：换它照样 0 镜重烧，改十次只多跑十次拼接。

**进出场**（`entrance` / `exit`，这一镜自己怎么开始、怎么结束）：
各 5 档——`none` / `fade`（淡入 / 淡出）/ `rise`（自下浮入 / 向上浮出）/
`drop`（自上落入 / 向下落出）/ `zoom`（轻推近 / 轻拉远）。
同一档名在入场是「进来」、在出场是「出去」，方向刚好相反。
窗口很短（每镜帧数的 10%、封顶 15 帧），是给整片定调用的，不是让观众盯着看的效果。
**那些注入项都不用你转交**：`text` / `highlight` / `words` 与各档档位都由渲染侧
**注入成这一镜的 props**——自包含的镜直接从自己的入参里取，不用声明、不用透传。

**代价差在哪**（这条决定你什么时候可以随便改）：**换转场不重烧任何一镜**——
转场落在合成成片那一步，逐镜的切片一个字节都不动，改十次也只多跑十次拼接；
**进出场则要进缓存键**，因为它改的是每一镜切片的像素（`entranceFrames` 那一对数注入给
镜头代码），改一次就是整片重烧。
所以「先定进出场、再调转场」比反过来便宜得多。

**进出场也是「申报，实现归你」**：整片那一档只是被算成两个数——`entranceFrames` /
`exitFrames`（上限 15 帧或这一镜帧数的 10%，取小）——注入进这一镜的 props，
**没有人替你画**。要淡入就用 `interpolate(frame, [0, entranceFrames], …)` 自己乘进整体
`opacity`；不画就是硬切。镜头级那两栏在自包含的镜上**没有**任何自动效果。

# 局部改

出片后要改几个字或几镜，**不要重跑整条流程**：

1. **改文案/高亮词** → patch_motion_code（只改指定镜的 text/highlight，不重渲结构）
2. **改一镜的画面** → 重写那一段代码 → patch_motion_code
3. **改整体风格** → 换主题色板 → patch_motion_code（改 palette 引用）
4. **改某几镜的构图/字幕/接缝** → patch_motion_code 的 `shot_sets`（整镜改写，一条
   `{shot, set}`）。可改的栏以工具 schema 列出的名单为准，`bleed` / `bg` /
   `caption_style` / `highlight_style` / `transition` / `texture` 都在里面。两处容易写错：`transition`
   写的是**这一镜之后**那处接缝（末镜写了不生效）；`bleed` 必须真是布尔。
   改 `transition` / `texture` **不重烧这一镜**，改 `caption_style` / `highlight_style` /
   `bleed` / `bg` **要重烧**。

# 闸表（模型看得到的全部闸）

## 质检档 `qc`：预览档（缺省）与严格档

- **`preview`（缺省，有人在看）**：主流做法——`plan_motion` 过了契约闸后会给**每镜渲一张预览静帧**，
  渲染前的计划确认卡上把这些图摆给用户看；人眼替掉了机器的品味判断。所以这一档里：
  - 契约层的 ⑨ ⑯ 只出「（建议）」不打回；**⑦「每镜必画」在这一档照旧打回**（见下）；
  - 渲染时的像素闸（④ ⑥ ⑭ ㉑，以及拼接前的 ⑤ ⑰ ⑲-a ⑳(c) ㉕、转场生效复核）**只记进 `qc_warnings`，照常出片**。
  - 交付时把 `qc_warnings` 里要紧的几条照实转告用户；**不要**自己据此改码重渲——要不要改由用户看过成片再说。
- **`strict`（无人值守）**：spec 顶层写 `"qc": "strict"`（或服务端设 `MOTION_QC=strict`），所有机器判据照旧硬拦，
  换「没人看也敢出片」的保证。定时任务、批量出片用这一档。
- 两档都硬拦的：lint、帧账、对比度⑩、转场会吃掉话尾。

**⑲ 多样性配额只提醒、不打回**（回执里带「（建议）」前缀，渲染前计划确认卡上会列给用户看）：
整片有意统一色调或统一构图时可以不满足它，但要在答复里说一句为什么。
**⑦「每镜必画」是质量底线，两档都是硬闸**——它拦的不是品味，是「这一镜画面上根本没有东西」，
那件事没有「人眼替机器判」的余地；其余各闸也都是硬闸。

判点分四档，按**烧不烧像素**排：契约闸（一帧不烧，改十遍只花几秒）→ 容器 lint →
逐镜渲染 → 拼接之前。能在前一档修好的错别留到后一档——后一档每改一次都是十几秒的真渲染。

## 契约层：`plan_motion` 入库前、烧像素前、`patch_motion_code` 落盘前，三处读同一份判据

# 画面丰富度合同（五类母题怎么选画法）

一条片子要有画面，靠的是**每一镜都真的画了东西**，而画面只有一条路：**你逐镜写 TSX 代码把它画出来**。
各类母题各有最顺手的那条画法，先照这张表想：

| 母题 | 会被认成哪条痕迹（只是识别，不是限制） | 怎么写（画法自由） |
|------|------|------|
| 器物、材质、草图、手绘感的形状 | `rough`（`roughjs`）或 `@dg/lib/brush` | roughjs 的每个形状都要给 `seed`；笔刷用 `<BrushStroke/>` 的固定 seed |
| 立体体、场景、空间关系 | `three` + `@react-three/fiber` + `@remotion/three` | 真 3D，最慢的一档，只在真要立体感时用 |
| 公式、推导 | `katex` | 必须 `import "katex/dist/katex.min.css"`，不然渲出来是没上下标的纯文本 |
| 流程、曲线、几何、图示、白板描线 | `vector`（裸 `<svg>`/`<path>`/`<rect>`）或 `@remotion/shapes` | 白板描线那套见「白板 / 简笔描线族」；渐变/滤镜/mask 都归这一条 |
| 粒子、逐帧笔触、复杂路径、大量小元素 | `canvas`（`<canvas>` + `getContext('2d')`） | 在 `useEffect` 里按 `frame` 重画；坐标从 `useVideoConfig()` 拿 |

**上面五类没有一类是「摆一张图」**：这条链没有取材通道——不检索素材库、不出图、用户上传的图也不上屏
（上传件那一栏因此在图形片里没有读者）。要写实观感的器物也是**画**出来的，不是找来的。

**每一镜都得用上面五条里至少一条画出东西来**（闸⑦「每镜必画」，逐镜判、**打回**）。
「左边一张卡片 + 右边一段文字」那种只有文字与色块的镜，**没有配额可摊**——落在哪一镜，
那一镜就点名打回，镜数多少都判（三镜片也判）。画法怎么选由你按题材定，不重样更好，
但那是你自己的取舍，没有闸在数字号。

**只 import 不调用那一行不算通道**——判据读的是代码体里真用得上的那个名字。
`@dg/lib/brush` 画出来的东西落在 `vector` 上（它输出的是 `<path>`）；`<canvas>` 要真调
`getContext(...)` 才算，空标签不算。

# 通道表（闸⑦）

**这张表不是画法菜单，也不是模板库。** 它是机器从代码里认出「你真的画了东西」的五种
**痕迹**：写了 `<svg>`/`<path>` 就是 `vector`，调了 `roughjs` 就是 `rough`，如此而已。
画什么、用什么 API、什么风格、一笔怎么走，全部由你按这一镜的题材自己决定——
同一条 `vector` 里可以是铅笔、水彩、版画、渐变叠色、涂改痕迹里的任何一种。
没有任何一档在限制你的画法；这张表只回答「机器凭什么确认这一镜不是空的」。

5 条画法痕迹 + 1 条文字通道：

| 通道 | 标记 | 用途 |
|------|------------|------|
| `rough` | `roughjs` / `@dg/lib/draw/*` | 手绘斜纹、草图质感 |
| `three` | `three`/`@react-three/fiber`/`@remotion/three` | 真 3D 场景、WebGL 渲染 |
| `katex` | `katex` | 数学公式 |
| `vector` | `<svg>`/`<path>`/`<rect>` 等（含 `@dg/lib/brush`、`@dg/lib/scene`、`@dg/lib/walk`） | 矢量图形、手绘笔触、材质层、贯穿主体 |
| `canvas` | `<canvas>` + `getContext(...)` | 逐帧手写绘制、粒子、复杂路径 |
| `text` | （fallback） | 一条画法通道都没命中：只有文字与色块 |

**「每镜必画」的判据就是这张表**：一镜落在 `text` 那一档＝打回，点名到镜号。
用了几条、哪几条由**代码字节里的 import 与标记**自动识别，不看自报的字段。
`staticFile` 照样能用，但它只用来取**字体**（`@remotion/fonts` 的 `loadFont` 要求
`staticFile('fonts/…')`）——它不是画法通道，**摆一张图不叫画**。

另有一条文字约束（只提醒，不打回）：
- `CONCRETE_SHARE_TARGET = 0.40`（40%）：整片里含具体项（数字/引号术语/拉丁缩写）的镜占比目标 40%。这条只出提醒——地名人名器物名机器认不出，拦它会误伤一整轮重规划。

# 白板 / 简笔描线族（**用代码画，不出图**）

「白板动画」那种**一支笔把东西当场画出来**的观感，这条链**不需要出图**——`vector` 通道的
虚线偏移（`pathLength={1}` + `strokeDasharray="1"` + `dashoffset` 从 1 走到 0）就是白板描线
本身。三件套：

- **免测周长**：路径设 `pathLength={1}`、`strokeDasharray="1"`，让 `dashoffset` 1→0 跑一遍，
  线就长出来了——不用量真实周长，也不用 `getTotalLength()`。
- **笔头**：同一条路径再叠**三段渐细短虚线**跑在最前 + 一颗按弧长定位的实心笔尖。
  **没有笔头就只是「边框在变长」，有笔头才是「有人在画」**——这一颗是白板感的关键。
- **闭合闪**：描完那 2 帧把线冲深、加粗再回落，给「画完了」一个句号。

两条纪律：① **描边路径必须与元素真实轮廓吻合**（圆角 `rx` 要一致）——线画的是 14px 圆角、
元素是 8px，交棒瞬间错型穿帮；② **一次点名画一个主体**，同屏多元素各画一圈读作加载动画。

**这一族配上 `bleed: true` 才是它该有的样子**：常规版式下画面被裁进中间一条带子里，满版描线
只能缩着画。三个开关合起来就是「白板讲解」那种观感——`bleed: true`（铺满整帧）+
`caption_style: outlined`（白字黑边，字自己摆 `<CaptionText/>`，逐词点亮与撕纸高亮
照旧可用）+ 上面这套描线手法。这一族也不要为了「白板感」把字幕改成无描边：白底黑边
同样是白板的一部分，字在任何底色上都读得出来。

# 主体具名（闸⑯）

**每镜两个字段**（缺 `subject` 会被 schema 直接拒）：

- `subject`：这一镜画面上**能被认出的那个东西**（名词短语，2~24 字）。写成
  「活字盘」「三条等高线」「一张 1900 年的地图」这种**器物/图形**的名字。
  建议别写抽象词（理念/趋势/意义/文化/效率…——画不出形状）；写了只提醒，不打回。
  这一格是给人看的：用户扫一眼卡面就知道每镜到底画了什么，视觉评审也拿它当参照。

  `roughjs` 都没有 → 打回）；没填只提醒。
- 这一镜只有文字与色块 → **不要填**（自报无证据）；这一档今天不存在：
  闸⑦「每镜必画」已经把它逐镜打回了，⑯ 这一支是安全网。

# 主体具名（闸⑯）：每一镜的那个「能被认出的东西」怎么写

- `subject` **建议每镜都写**（回执与视觉评审都读它），2~24 字，写**画面上那个东西**的名词
  短语（`活字盘`、`三条等高线`、`一张 1900 年的地图`），不要写主题词（`印刷术`）。
  `理念`/`趋势`/`文化` 这类抽象词画不出形状；写了只会提醒一句，不会打回——但视觉评审
  会按画面判，抽象词那一镜照样过不了。
- `subject_channel` **可选**：填了就必须是**这一镜代码里真用上的那条**（import 了还得真调用），
  闸⑯ 拿代码逐镜核；写着 `rough` 而代码里一个 `roughjs` 都没有，等于自报，仍然打回。
  没填只提醒一句——`subject` 与画法的关系，已经由代码本身说明了。
- 可选值：`rough` / `three` / `katex` / `vector` / `canvas`。自己画的 SVG 填 `vector`，
  用 `<canvas>` 手写的填 `canvas`。
- 纯文字/纯色块镜到不了这一步：闸⑦「每镜必画」已经逐镜打回了（⑯ 这一支留着当安全网）。
- `subject_terms`（有人以为 ⑲-b 要的词族）**不在 schema 里，别写它**，写了会被退回来。
  ⑲-b 落地时走的是**盲描述**：先让一个看不见答案的观察员说「你看见的是什么」，再拿你申报的
  `subject` 去比。它一个词族也不需要——**`subject` 写准写具体，就是你对 ⑲-b 唯一要做的事**。

# 每一镜都要画出文案点到的那件东西

**这一节治的是「画得不像」。** 画面只有代码一路，而代码画不出照片——它能画的是**物件**：
一个人、一台机器、一栋厂房、一个齿轮、一条曲线、一架天平。用户要的「像」在这条路上
具体就是这句话：**这一镜的文案提到了什么，画面上就要有那个东西的图形，而且看得出是它。**

真机上被点名的反面例子：一镜讲「19 世纪富态」，画面上是 180 个点拼成的一个椭圆，
标注「19 世纪·富态」——形状随意、认不出是什么。那就是这一节要拦的东西。

**画法是自由的**：裸 SVG、`<canvas>`、`three`、`roughjs`、`katex`、`@dg/lib/brush`
的笔刷、下面零件库里的件——怎么画得像就怎么画。**没有任何闸要求你必须用零件库**；
它只是「这类东西大概长这样」的一份现成参考。

## 三步：先认东西，再拆形状，最后落笔

1. **认东西**。从这一镜的文案里挑出**每一件能被画出来的具体事物**——`蒸汽机`、`厂房`、
   `一张曲线`、`一顶王冠`、`一个正在扛东西的工人`。其中最重要的一件就是你填的 `subject`；
   其余的在 `entities` 或 brief 里。**别拿抽象形状顶替**：「一团表示压力的椭圆」
   「富态轮廓的点阵图」都不是东西。
2. **逐件拆形状**。**外轮廓 → 标志物 → 2~4 个部件**：
   - **外轮廓**：这东西的整体形状（机器 = 一个长条 + 一个圆；厂房 = 方块 + 锯齿屋顶）；
   - **标志物**：**少了它就不像**的那一件（蒸汽机的烟囱、天平的横梁、钟的指针、
     钱包的拉链齿、骨架的肋骨）；
   - **2~4 个部件**：剩下的细节。**别贪多**——简笔画的力气全在前两步。
   - **体积**：外轮廓里填实，分出受光面与背光面，落地给影。只剩一圈描边、
     里面和背景一个明度，就是「空心图形」，看上去仍是个图标，不像这东西。
3. **落笔**。可以照下面的零件库拼，也可以自己用 `<path>`/`<canvas>` 画。
   自己画时同样按「外轮廓 → 标志物 → 部件 → 体积」来；再给一笔粗细变化与一层材质，
   它就从「图标」变成「手绘」。像素风也一样：用几档像素色块堆体积，不是只用亮线勾边。

## 零件库 `@dg/lib/draw/*`（可选参考件：一件＝一个能被认出的东西）

| 件 | 画的是什么 | 主要 props（都对得上 `useVideoConfig()` 的设备像素） |
|----|-----------|-----------|
| `<Figure/>` | 简笔人：站 / 走 / 指 / 举手 / 扛东西 / 坐着 | `x`（脚底中点）`y` `h`（身高）`pose="stand\|walk\|point\|raise\|carry\|sit"` `facing={1}`（右）`facing={-1}`（左）`hold="none\|tool\|banner\|book\|bag"`（扛东西用 `pose="carry" hold="bag"`） |
| `<Face/>` | 极简头像（**指代**一个人，不是写实） | `x` `y`（头心）`size` `mood` `hat` `glasses` `beard` |
| `<Machine/>` | 蒸汽机 / 冲床 / 机械臂 / 涡轮 | `x` `y`（落地点）`w` `kind="steam\|press\|arm\|turbine"` `smoke`（0~1）。**整机高约 1.5×w**（烟囱顶到落地点）——`y` 给地面时把这一点算进去，别让烟囱顶出画面上沿 |
| `<Building/>` | 厂房 / 塔 / 民居 / 天际线 | `x` `y`（地面）`w` `kind="factory\|tower\|house\|skyline"` `smoke`（0~1）。主体约 1.4×w；**`factory` 带烟时烟囱 + 烟球到约 2×w**。16:9 横屏、地面在 0.72~0.74h 时，`factory` 的 `w` 取 **≤0.22×画面宽**——2026-10-18 真机 s01 给了 0.30，烟囱顶直接被上沿切掉；要更大就把 `y` 往下挪或把 `smoke` 压到 0 |
| `<Vehicle/>` | 手推车 / 汽车 / 火车头 / 船 | `x` `y` `w` `kind` `facing={1\|-1}` |
| `<Gear/>` | 齿轮（可咬合成一对） | `x` `y`（圆心）`r` `teeth` `spin`（**角度**，不是 0~1） |
| `<Chart/>` | 坐标轴 + 曲线或柱 | `x` `y`（绘图区左上）`w` `h` `kind="line\|bar"` `values`（0~1 序列）`upto`（0~1，长到几成） |
| `<Arrow/>` | 箭头：指、连、推、变 | `x1` `y1` `x2` `y2` `bend`（-1~1）`upto`（0~1） |
| `<Coin/>` | 钱：单枚 / 一摞 | `x` `y` `r` `kind="plain\|ring\|stack"` `count` |
| `<Book/>` | 书：合着 / 摊开（可翻页） | `x` `y`（下缘中点）`w` `open`（`true` 摊开）`flip`（0~1） |
| `<Scale/>` | 天平（可倾斜） | `x` `y`（底座）`w` `tilt`（**-1 左沉 / 0 平 / 1 右沉**，不是角度；给角度也认） |
| `<Clock/>` | 钟（指针按你给的角度） | `x` `y` `r` `hour` `minute` |
| `<Crown/>` | 王冠 | `x` `y`（下缘中点）`w` `points` `gems` |

**取值照表写**：`facing` 只写 `1`/`-1`（写 `"left"` 现在也认，但表里这两个数是准的），
`tilt`/`smoke`/`upto`/`open`/`flip` 都是 **0~1 的比例**，只有 `spin` 与模板角度是**度**。
`kind`/`pose` 只认表里列出的那些字符串——写别的会在画面上变成默认款。
**站位**：前景的人与主体分开站——`Figure` 的 `x` 至少离主体包围盒边缘 `0.05×画宽`，
走过的人的**终点**也别压在主体上（2026-10-18 真机 s01：工人停在飞轮正前方，人和机器糊成一团）。
主体比 `w` 宽时按**画出来的轮廓**算（飞轮、烟囱、托盘都算进去）。
**入场要真的从无到有**：给 `<g opacity={seg(...)}>`，或让起点在画外再走进来；
已经站在画面里的人只「移动」不算入场（真机 s01 的工人第 0 帧就站在左边，brief 要的是
「最后走进来」）。

三件事它们**已经替你办好**，不要再各写一遍：

- **颜色**：不传 `ink` 就取整片那一档（字色 / 强调色 / 纸色），与画面里别的东西同色；
  要**强调**某一件才传 `ink={{ accent: … }}`。
- **画在深色块面上要换笔**：零件缺省用整片的**字色**（深墨）。把它摆在同样深的大色块
  上，线条就没了——2026-10-18 真机 s07 正是「深棕斜切块 + 深棕小人」，画面上只剩一团影子。
  两种改法任选：把主体挪到浅底那边；或这一件传 `ink={{ stroke: film.paper }}`
  （`resolveFilmStyle(getInputProps())` 已经拿到这一镜的纸色）要强调就传
  `ink={{ accent: film.accent }}`。**主体与它身后的块面至少差一档明暗**，否则等于没画。
- **线要够粗**：缺省 **3 px**（成片像素）在 1920×1080 上是发丝。主体与人物传
  `ink={{ strokeWidth: 6 }}`（约画高的 0.3~0.5%），预览图与成片才读得清；小图标可回到 4。
- **手绘感**：底下是 roughjs 的手绘线，同一个 `seed` 渲两次逐像素相同（不会逐帧抖）。
- **坐标**：就是成片设备像素，与你的 `<svg viewBox={`0 0 ${width} ${height}`}>` 同一套。

零件**不读帧**：要让齿轮转、天平斜、曲线一点点长出来，由你把帧算成 props 传进去
（`spin` / `tilt` / `upto` / `smoke` / `flip`）。这样「这一镜动的是什么」永远写在
你的代码里，一眼看得见。

```tsx
import { Machine } from '@dg/lib/draw/Machine';
import { Building } from '@dg/lib/draw/Building';
import { Figure } from '@dg/lib/draw/Figure';
import { Gear } from '@dg/lib/draw/Gear';

const spin = interpolate(frame, [0, 90], [0, 120]);
const puff = interpolate(frame, [0, 60], [0, 1]);

<svg viewBox={`0 0 ${width} ${height}`} width={width} height={height}>
  <Building x={width * 0.26} y={height * 0.78} w={width * 0.34} kind="factory" smoke={puff} />
  <Machine x={width * 0.66} y={height * 0.78} w={width * 0.28} kind="steam" smoke={puff} />
  <Figure x={width * 0.44} y={height * 0.78} h={height * 0.22} pose="carry" />
  <Gear x={width * 0.87} y={height * 0.26} r={width * 0.045} spin={spin} />
</svg>
```

## 真人：`<Face/>` 是**指代**，不是写实

「马斯克」「牛顿」这种具体的人，**几笔线画不出那张脸**——真实长相得有现成像素，而取材
那三条路（检索素材 / 出图 / 上传件上屏）已经从产品里删掉了，不在这条链的能力范围内。
这一类镜头的正确画法是 `<Face/>`（或 `<Figure/>`）+ **名字标注**：观众读到的应该是
「画面上这个人在讲」，不是「这头像长得像他」。**不要**为了「像」去堆五官细节——
那既不像，又把画面弄脏。

## 用不用零件库：一条建议

- **用上了**：`subject_channel` 填 `rough`（那些件底下就是 roughjs）；仍按上一节自己补
  构图、光影、材质——零件只提供「形」，不提供「画」。
- **没用**：没有任何闸会因此打回。你自己画的 SVG / canvas 落在 `vector` 或 `canvas` 通道上，
  闸⑦ 一样认。
- **别为了凑数摆一件**：角落放一支 `<Arrow/>` 而主体仍是一团点阵，视觉评审会照样判红。
  这一条现在由**看画面**来判（下一节的 ⑲-b 与整片静帧评审），不再由 import 名判。
- **它判不出「像不像」**：零件库只保证「有一件具名件」，不保证「画对了」；
  别把「用了零件」当成「画对了」。

## ⑲-b：还有一只眼在问「画面上那个东西，是它吗」

「像不像」落在判据上的那一格叫 **⑲-b**（`judge_identity`）。它的问法值得你知道，因为你
正是照它写代码的：**先有一个看不见你申报内容的观察员，只看画面回答「我看见了什么」**，
再拿你填的 `subject` 去比。所以：

- **`subject` 写的是画面上真出现了的那件东西**（「蒸汽机」），不是这一镜的主题（「工业化」）。
  观察员说出「一台带烟囱的机器」，就对得上；他说不出画的是什么，就直接算**不像**。
- 它**认形状与类别，不认写实**：「工业革命」那一镜画出厂房 + 工人 + 冒烟的烟囱，
  这是对得上的；画成一团「富态轮廓的点阵」是对不上的——**这一点是这一条最容易踩的地方**。
- 它**不认人脸**。具体真人的那几镜，用 `<Face/>` + 名字标注（见上一节），
  别指望画出长相。
- 这条判据**默认不开**（每镜一次带图调用是真钱）。开着的片子，红了的镜会回给你：
  「它看见的是 X，你写的是 Y」——照那句话改画面，不要改 `subject` 去迁就画面
  （改申报去迁就画面＝把判据关掉，闸⑯ 也会拦）。

# 动效密度（闸⑭）：这一镜得在像素上数得出「先后动」

判据读的是**成片像素**，不是你写了几个 `interpolate()`：容器把切片按 **8 Hz** 抽帧、每帧
缩到 **64 px 宽**的灰度图，逐帧算平均绝对差（0–255），把连续高于门槛的采样点并成
「变化段」——**入场 1.5、驻留 0.6**；要数得出 **≥2 段**，且相邻两段的起点相差 **≥0.4 s**
（30fps 就是 12 帧）。三条写码纪律，不按它们来读数会和你眼睛看到的不一样：

1. **两段要真的隔开**。一整段匀速动效（从 0 动到末）只数得出 1 段，必红。把动效排成
   **先后来**：揭示/入场占前 40% 左右，第二段排在它之后 ≥0.4 s——位移、切换、收束都算。
   同一时刻一起动的五件事，在 8 Hz 下仍是一段。
2. **「淡入替你过关」这层兜底没有了**。2026-10-14 真机实测的是**套母版**的镜：`entrance: fade`
   在头 15 帧给出全片最大的峰值（多镜峰值 50–80 全落在第 0–15 帧），于是细线、低对比的动效
   被它盖过去也能过。母版下线后**没有人再替你画这一层**——`entrance` 只是注入的两个数
   （见「转场与进出场」），你不写 `interpolate` 就没有那一段。所以「两段都要由**画面内容**
   自己贡献」这条比从前更硬：连第一段都别指望默认动画。
3. **变化要够大**。采样量的是**整帧**的平均差，分母永远是整帧：动效只占画面一小块时，
   同样的位移平摊到整帧就被稀释（16:9 的构图等比缩进竖屏后只占三成面积，稀释约 3 倍）。
   描线、1 px 位移、缓慢色相变化都过不了 1.5 的入场门槛。要么把动效做在主体上（位移、
   缩放、明暗块面切换），要么按整帧重排这一镜的版面（别用裁切换过闸：裁掉的是内容）。
4. **满幅底板能救闸④，但会从两个方向把画面读空**（这两条是 2026-10-14 一条 12 镜整片
   实测出来的，不是推的）：
   - 底板或遮罩**不透明地盖在会动的像素上面**，逐帧差直接归零。回执写「数得出 0 个变化段
     ……内容峰 0.00」就是被盖住了——**不是**"你没写动画"。底板要么 `fill="none"`，
     要么放在动内容**之下**，别让它在 z 序上压住主体。
   - 「先入场、后逐段揭开」那种节奏（前四成时间底板上还没东西）会让闸④ 的 **0.15 那个
     采样点读到空底**。这一镜照样能过④——它的判据是「最低帧 <2% **且** 最满帧 <45%」
     两条同时成立才打回，底板把后一条顶住了。于是账上会出现 `非底色 0.0%` 而闸是绿的。
     **过闸不等于画面不空**：观众实打实看到前四成时间是一张空卡。要满幅就在入场那一刻
     把内容铺进带子，不要靠"揭开"填时间。
5. **闸⑲-a 的主体读数取的是片尾那一帧**（探针落在 `durationInFrames - FIELD_PROBE_TAIL`），
   所以主体得**撑到结尾仍在场**；中途出现又撤走的主体，在账上等于没有。**自包含的镜没有
   这一份读数**（扫读数的是母版），⑲-a 对它们记未判——「主体撑到结尾」得你自己保证。
   另外只有可画图元进主体计数（`path/rect/circle/ellipse/polygon/polyline/line/img/canvas/video`），
   **div 铺的色块条算 0 主体**——用 div 画的卡片配满幅公式，正好落在「卡片+文字」那条
   联合判据上被打回（同一镜的图元只有 2 个时，折到成片上不足带的 1%）。
<!-- bands-only -->
6. **细线零件过不了这道闸——每一镜都要有「块面级」的动**。2026-10-18 真机实测（9 s 横屏、
   0.4 倍草稿档、8 Hz 采样）：齿轮转 + 人走 + 曲线慢慢长，整帧平均差只有 **0.05–0.3**；
   一块满宽强调色带擦入是 **4.6**，一块 36% 宽 × 30% 高的色块长出来是 **3.8**。门槛是 1.5，
   所以只靠细线，这一闸必红。**宽度比高度更要紧**：同日另一批实测里，满宽色带是 **14**，
   同一镜里 34% 宽 × 56% 高的面板只有 **1.23**——面积差不多，读数差一个数量级，
   因为 64 px 采样先把宽度缩没了。所以两处都用**满宽**，只改高度与进出方向。
   每一镜安排**两处块面级**的动，分在两段时间：
   ```tsx
   const bandIn  = seg(t, 0.05, 0.12, E.standard);   // ① 前段：满宽色带擦入
   const panelIn = seg(t, 0.50, 0.57, E.standard);   // ② 后段：大色块长出来
   <svg …>
     <rect x={0} y={height * 0.22} width={width * bandIn}
           height={height * 0.05} fill={accent} opacity={0.9} />
     <rect x={0} y={height * 0.34} width={width * 0.36 * panelIn}
           height={height * 0.28} fill={accent} opacity={0.85} />
     {/* 细线零件照旧：齿轮、人、曲线，它们是第二层，不能指望它们顶过门槛 */}
     <Gear x={…} y={…} r={…} spin={spin} />
   </svg>
   ```
   色块要当**版式的一部分**用：压在留白或半边、托着大字/数字。**别放进字幕安全区**
   （横屏是画面底部 300 px），也别盖住主体——闸⑧ 会把「字压图」记成一条。
   **块面一律写在主体之前**（SVG 里先写 `<rect>`，再写零件）：它在 z 序下层当底板，
   永远盖不住主体；写在主体之后就是一条彩色带横穿画面（真机 s01 的 0.60h 满宽色带
   横穿蒸汽机和厂房窗户，把两台机器都切断了）。
   **满宽色带优先放在画面最上沿（0~6%）**，或主体上方那条整幅留白里；
   横梁、折线、人物头顶、烟囱这类主体**一律不许穿过色带**——它画在 z 序上层时会把主体
   切成两截（2026-10-18 真机 s03：0.14~0.20 的色带横穿天平横梁，横梁中间断了一截）。
   不确定主体多高时，色带就贴最上沿，别放在 0.10~0.25 这一带。
   两段的起点至少隔 0.4 s；两块挨在一起会让整段动效被读成一次跳变。
   **三维/写实的镜不适用这一段**：风格包关掉了满宽色带时（manifest 里带这一位），块面级的动
   由相机与光来做（推近、横移、主光扫过整幅、雾与粒子的浓度变化），**不要再加色带**——
   写实场景里横贯一条纯色带，观众第一眼就出戏。
   2026-10-22 真机：23 镜照着旧规则全都加了贴顶色带，预览里 23 镜顶部都有一条彩条。

`exit` 与**代表帧**的取舍：缓存里那张代表帧取的是 `durationInFrames-2`，落款淡出会把这一帧
扫成接近空底；闸④ 的采样点又正好在 0.15/0.5/0.85。所以整片用 `"exit": "none"`、
结尾交给转场，不要靠逐镜淡出收尾。

<!-- section: motion-anchors -->
# 动效锚定（闸㉑）：每一条动效为**哪个数据**动

镜级 `motion` 是一张清单，每条 `{kind, anchors}`：

- `kind` 必填且非空（说不出是什么动效，就没法说它服务谁）。
- `anchors` **必填、不能空、最多 3 个**。空锚＝这条动效不为任何数据服务（历史上被驳回过的
  形态）；挂超过 3 个上限就退——判据是「**每一个**锚都得落在窗口内」，挂满了等于没锚。
- 只认三种写法（**白名单**，写错一个字符当场退）：`fields.<本镜声明过的字段名>`、
  `subtitle:<本镜第几个词>`、`beat:<第几个节拍>`。序号从 **1** 起，不写零、不写小数。
  锚到这一镜没声明过的字段，与没锚是同一件事。
- **窗口**：这条动效的触发帧要落在它锚的数据「首次可读」的 ±k 帧内，k = fps ÷ 3
  （30fps 就是 10 帧 ≈ 0.33 秒）——人对齐的精度是按时间走的，所以容差跟着帧率走。
- **今天真判得动的只有 `subtitle:` 那一档**：`fields.` 锚落「未判」（「这个字段什么时候
  在画面上变得可读」要人判，不是这一层能反推的），`beat:` 锚也落「未判」（这条链没做
  节拍检测，节拍表不存在）。**未判不是通过**——别把「挂到必然存在的字段上」当成过闸的
  写法；该申报就如实申报，别指望把锚全挂到 `fields.` 上就能过。

# 每镜必画（闸⑦）：每一镜都得有画出来的东西

- 判据**逐镜**走：这一镜的代码里得真用上 `rough` / `three` / `katex` / `vector` /
  `canvas` 五条画法通道里至少一条（判据见「通道表（闸⑦）」）。一条都没命中＝只有文字与色块＝
  **打回**，回执点名是哪几镜。**没有配额可摊**：不存在「几镜可以纯文字」这一档。
- 判据只看「有没有画」，**不看画法**：裸 SVG、`<canvas>` 手写、笔刷、三维、公式都行；
  没有任何一条要求你必须用某个组件库。
- **首尾镜也在内**。开场与收尾常常是标题与落款，那也要画——标题本身可以是一笔画出来的字形
  轮廓、一块有质感的底纹、一条描线勾出的框。**没有任何一镜豁免**。
- **镜数多少都判**：这条没有最低镜数（旧版那个「≥6 镜才判配额」的口子已经关掉），
  三镜片也逐镜判。
- 「纯文字镜**不得连续 3 镜**」这句**今天没有判据**，而且也不需要了——一镜纯文字都不许有。
- 与这条**成对**的是闸⑲（构图侧：满幅 / 质感 / `bg` 申报率）：⑦ 管地板（每一镜都有画面），
  ⑲ 管构图上的多样。④ 的像素判据（画面非空）是它在成片像素上的一次复核。
  **底色不归 ⑲ 管**：整片一套是缺省。

# 声音：旁白与配乐

- **配乐**：用户随消息附了配乐，就把那条附件的 material_id 直接填进 `render_motion_code`
  的 `bgm`，不用再选、也不用问。没附配乐时从曲库选一条（曲库歌曲的 material_id 同样能直接
  填 `bgm`）；曲库里也没有合适的就出纯人声片并在答复里说一句，**不要停下来问**。绝不去网上
  下载（`fetch_media` / `web_search` / `fetch_url` 都不许用来找音乐）。配乐比成片短时会自动
  循环，不会打回。
- **卡拍是自动的**：有配乐时渲染会先检测拍点，把每镜的切点往后补到最近的拍上（只补不裁，
  最多约半拍）。不想卡拍就在 spec 顶层写 `"beat_sync": false`。出片回执的 `beat_sync` 栏
  会报检到的速度与补过的镜。
- **有旁白**（`narration=true`）：人声由 TTS 合成、逐词时间轴随 props 注入（`words`），
  **不要写每镜时长**（镜头长度归真实语音时长）。第几个词可用 `subtitle:<i>` 锚动效
  ——那是今天唯一真判得动的一档锚。
- **没旁白**（`narration=false`）：没有语音时长可依，**每镜必须给 `min_duration_sec`**
  （5~15 秒，给观众读字幕的时间），全片总长就是各镜 `min_duration_sec` 之和。
- **声音设计的细节不在这份正文里**（响度、BGM 压低、停顿、语气）：要动它们就
  `load_skill(name="motion_explainer_skill", path="sound-design.md")` 取附件全文再动手。
