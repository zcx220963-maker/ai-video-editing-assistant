# 何时用这条通道（与常规剪辑的分界）

只有一条判据：**这条片子的画面是不是排版就能画出来。**

- 用户随消息给了素材、或素材库里检索得到要剪的影像 → 走 default_editing_workflow_skill
  （load_media → … → plan_timeline → render_video）。
- 用户给的是一个**选题**（「讲讲活字印刷怎么来的」「用 60 秒解释什么是 RPC」），
  没有任何素材 → 走本通道：**plan_motion → render_motion_video**。
- 两条路是两个终点，不要混着排：一条片子只出一个成片通道。

# 流程

1. **查资料**：web_search / fetch_url，可以多轮。后端怎么选的、查不到该怎么收口，见下面
   「查资料：后端链与出处账」那一节。每条要点记下出处（标题 + 链接）。
2. **写分镜** plan_motion：每镜一句文案 + 版式组件 + 高亮词 + 出处。这一步是**校验闸**，
   返回的错误清单照抄着改，改完重调本工具——它不烧像素，改十遍也只花几秒。
   带病的 spec 不会入库，所以永远不会「渲了二十分钟才发现高亮词写错了」。
3. **对账**：读返回里的 `estimated_sec`（按字数估的秒数区间）与 `target_warnings`。
   有偏差就先改分镜（删镜 / 缩短每镜文案 / 调语速），别留着让渲染去揭晓。
4. **出片** render_motion_video：分钟级到十分钟级。返回 `status=queued/running` 时
   **继续调 render_status**（同 artifact_id）直到 done/failed，不要在这一轮就宣布成片。
5. **出片之后还要改** → 看下面那一节「局部改」。**不要**为了改几个字重跑整条流程：
   重新 plan_motion 会把分镜换成新版，旧成片与新命中表就对不上了；而局部改改的正是
   那一版片子自己的分镜。

# 查资料：后端链与出处账

**后端按这三层选，每次调用现读**：① 用户在「设置」页配的搜索 API（brave / tavily /
serpapi / 自建 SearXNG，配了只走那一路）→ ② 环境变量 `SEARCH_PROVIDER` 那三个同名项 →
③ 免 key 回落链。回执首行 `[检索后端：…]` 会老实告诉你是哪一路出的。

免 key 链按查询文字路由，是**真机探出来的**，不是随手排的：中文走维基百科 API，拉丁文字走
Bing RSS（英文维基随后），DuckDuckGo 垫底。这台机器上 DDG 两个端点都回人机验证壳，换 UA、
改 POST 都一样——那是**出口 IP 的信誉问题**，不是「网上没有这条内容」。

由此有两条硬规矩：

- **查不到 ≠ 不存在**。免 key 链的覆盖面只有百科与通用网页，新近数字、长尾中文网页本来就不在
  里面。换关键词再试、用 `fetch_url` 直接打开你已知的页面，或让用户去设置页配一把搜索 key；
  都不许把「0 条」写成「没有相关记载」这类结论。
- **出处只对账，不判真伪**。`web_search` 命中的链接和 `fetch_url` 真打开过的页面会记进本会话的
  检索账。分镜 `source` 里的链接只有能对上一笔账才算查证过，对不上会被出处闸
  退回。自己编一个看着像真的 URL 是最坏的写法——它骗得过排版，骗不过账本；查不到就老老实实写
  「未核实」，或在文案里说明这是通行说法。

# 每镜怎么写（这几条错了画面必坏）

- `text` 容量按画幅：竖屏 ≤ 60 字、横屏 ≤ 110 字。超了裁镜，不要裁句子。
- `highlight` 里的每个词**必须是该镜文案的子串**，每镜 ≤ 4 个。差一个字就是画面上
  永远不亮——校验会拦，但拦下来等于白跑一轮。
- `card` 只能从清单里选，分四族：
  - **档案系**（纸质竖构图）：plain / archive / dict_entry / stamp / book / print /
    theatre / webpage / silhouette / title。
  - **图示系**（SVG，横竖都自适应）：flow 流程链 / compare 左右对照 / timeline 时间线 /
    levels 层级台阶 / chart 柱状折线 / scatter 散点 / orbit 环绕。数据填进 `visual`，
    时值由组件自己排——你不用写毫秒。
  - **绘制系**（SVG，参数展开，横竖都自适应）：pixel 像素网格（`rows` 逐行字符画 +
    `palette` 配色，`poses` 就是逐帧角色动画）/ burst 粒子群（`count` `dist` `dir`
    `spread` `shape` `colors` `seed`，`twinkle` 让粒子持续闪）/ net 节点连线网
    （`nodes` `edges` `mode`=ring 环形·layers 分层·mesh 网·star 辐射）/
    brush 手绘笔触（`strokes` 每笔 `shape`=line·circle·rect·poly + `color` `width`
    `passes` `jitter`）。**这一族同样是声明式的**：你交参数，服务端展开成 SVG 再过净化闸——
    没有画笔代码可写，也就没有「只有渲完才知道画歪了」。
  - **custom**：上面都盖不住的那张图，自己画（见下面那份合同）。
  清单外的版式是不存在的排版，别编。
- **`text` 只进字幕条，不进版式画面**：卡片上看得见的字全在 `visual` 里。
  `title` 的片名是 `visual.zh`（不是 `text`），`stamp` 的印章文字是 `visual.zh`，
  `dict_entry` 的大字是 `visual.word`，`archive` 的挂签是 `visual.line1~line3`，
  `compare` 两栏是 `visual.left/right = {title, points}`，
  `flow/timeline/levels/chart/scatter/orbit` 的数据是 `visual.steps/marks/levels/series/points/parts`，
  `pixel/burst/net/brush` 的数据是 `visual.rows|poses / count|dist|colors / nodes|edges|mode / strokes`
  （这四族也认 `visual.title` 图题、`visual.note` 小注、`visual.caption` 题注）。
  缺了这些字段，模板不会报错——它会画一张只有边框的空壳，而 `ok=True` 的回包看不见这一点。
  所以服务端把这一关拦在分镜校验里，带镜号退回，改完再调。
  **反过来也一样**：往 `visual` 里写这张卡不读的键（例如给 `archive` 写 `kind`/`rows`），
  模板同样不报错，红框里只剩它自己的默认编号——所以清单外的键也带镜号退回。
  图示里的 `value`/`x`/`y` **只给数字**（单位写进各项的 `label`，`chart` 另有 `unit` 一行；
  `levels`/`scatter` 不读 `unit`，写上去会被退回）：
  写成「极高」会被按 0 画，条子缩成零、滚动数字停在 0。
- **跨量级的数字写原数，别自己先除以一万**。`levels` / `chart` 的读数 ≥ 1 万会自动收成
  万 / 亿 / 万亿后缀（1e12 显示成「1.00万亿」而不是 13 位数糊在单位行上）；同一组里最大最小
  差到 100 倍以上会自动换**对数刻度**，并在题注补一句「对数刻度：每格 10 倍」——这时条长不再
  等比，但读数仍是原数。为什么必须自动换：一座山（1e12 千克）和一茶匙中子星物质（1e9）跟
  一个人（70）同框时，等比刻度下后两根只剩几个像素，观众看到的是一个也读不出来。
  想强制等比写 `scale: "linear"`，差得不远也想用对数写 `scale: "log"`。
- 有旁白时**不要写每镜 duration_sec**。镜头长度归真实语音时长（话没说完画面不切走），
  你写的秒数只会被当下限参考。想控制节奏请改文案长度与语速。
- 首尾各留一镜：开场 title，收尾 title 或 plain（呼吸镜）。
- `source` 如实填。机器不判史实真伪，它只会如实出现在**分镜卡与逐镜账**上——版式不会自动把
  出处排进画面，要让观众看到，就写进该镜的 `visual`（档案卡的 `line3` 就是给这行留的弱色位）。
  没查到的就不要写上去，也不许在答复里替它背书说「已核实」。

# 横屏（landscape）什么时候真值得用

横屏有**独立的第二套版式**：状态面板与时间地点标签收到上沿，字幕变成中间一条居中大字，
中间那条画面带宽 1760×658。两套版式按卡的种类各有落法：

- **档案系卡片按自身尺寸落在画面带里**（红框卡、词条卡、封面卡、版画卡都占满带高），
  两侧留纸。它们在竖屏是「一屏一张卡」，在横屏是「一张卡横躺在纸上」——都成立，
  只是横屏时卡的左右两侧会空出带宽，别指望一张 640 宽的卡铺满 1920。
- **图示系与 custom 按 viewBox 缩放**：内置七种图示的坐标是 1000×560（1.79:1），横屏的带是
  2.67:1，于是按带高缩放——实得 1175×658，**两侧各留 292 纸**（竖屏的带宽正好 1080，那边才吃满宽度）。
  真要做 16:9 的解说片，主体镜头仍排 flow / compare / timeline / levels / chart / scatter / custom
  最划算——图比卡片撑得住这条带；要把带宽真吃满，就自己画一张宽幅的（`card=custom` +
  `viewBox="0 0 1600 600"`）。开场与收尾用 title/archive 点题也撑得住。
- 竖屏（portrait）仍是默认档：参考片那一族纸感排版本来就是竖着长的，别为了新鲜而横。

# 自己画一张示意图（card=custom）

`visual.svg` 内联一整段 SVG，服务端只当闸、不当作者。合同：

- 一个 `<svg>` 根，**必须带 viewBox**（横竖共用一套坐标全靠它；建议 `viewBox="0 0 1000 560"`，
  横屏要铺满 1760 的画面带就写宽幅，如 `viewBox="0 0 1600 600"`），
  整段 ≤ 20000 字、≤ 400 个元素。
- 只放行绘图元素与绘图属性：`<script>` / `<foreignObject>` / `<image>` / 指向外部的 `href`
  一律退回；`style` 里的 `url(外链)` 会被整条丢掉。
- **不要写 SMIL 动画**（`<animate>` / `<animateTransform>` / `<set>`）。它们按墙钟走，
  而逐帧截图推不动，画面会冻在起始帧——这类一律直接退回。
- 要动就写 `data-anim`，可选：fade / rise / slide-x / draw / grow-x / grow-y / pop /
  count / wipe / orbit / pulse / pan / pose，配 `data-at`（毫秒）、`data-dur`、`data-dist`（像素，可负）、
  `data-count-to` + `data-dp`（小数位）+ `data-num-unit`（数字后缀，≤8 字，如 `万` / `亿`，
  会拼在滚动到位的数字后面）、`data-period`（一圈毫秒）。
  `pose` 与别的动效不同：它是**关键帧轮播**（`data-at` 起显示，停留 `data-hold` 毫秒后整格隐去；
  省略 `hold` 就一直显示，所以只有最后一格能省）。同一镜要摆几个 `pose` 元素、每个都写自己的
  `data-at` + `data-hold`，靠 `at` 首尾相接才连得起来。
- 带 `data-anim` 的元素**自身不要再写 `transform` 属性**——CSS 会盖掉它，位置就飞了；
  需要位移请外面套一层 `<g transform="…">`。
- **同理，`<text fill="#fff">` 也不生效**：字级样式挂在 `.dg` 的 CSS 规则上，CSS 盖得过呈现属性。
  深色形状上要压浅色字，写 `style='fill:#f3ecd9'`。可用的字级类只有四个：
  `h` 图题 / `t` 正文 / `s` 小注 / `num` 等宽数字，别的类名没有样式。
- 退回原因会带镜号，照抄改完重调 plan_motion 即可。净化不过不会有「画到一半少了块」
  的成片，只会有一次几秒钟的返工。

# 用户在计划卡上能改的那几件事

`aspect`（画幅）/ `fps`（帧率）/ `narration`（要不要人声）/ `voice`（音色）/
`rate`（语速）/ `subtitle_mode`（字幕形态）/ `texture`（整片质感）是**整部片子的属性**，
不是每步各设一个。
**只在 plan_motion 的 param_options 里出现一次**；render_motion_video 自动继承
plan_motion 的值，**不要在 render_motion_video 上再列这些 param_options**——
否则计划卡上同一组选项弹两遍，用户选两次同样的值。

把它们写进 plan_motion 该步的 param_options，用户就会在计划卡上看到并自己勾选。
勾选的值**覆盖**你写在 spec 里的同名字段——那是用户的决定，不要在 spec 里再写一份旧值去"提醒"。

建议的默认档：portrait + 15fps + narration=true + zh-CN-YunjianNeural + rate=+0% +
torn_highlight + texture=none。用户没表态就按这套，但**开关要照常给**，让他有机会改。

`texture` 是**整片那一层**的观感滤镜，不是某一镜的版式：film 老胶片（颗粒+暗角+暖偏）/
tv 老电视（扫描线+色偏）/ glow 柔光（高光泛开）/ bleach 漂白（硬对比低饱和）/ none 不加。
题材真要那层旧片子味才开——它是母带上多走一趟 x264（二代编码，画质略降、出片多花几十秒），
但**不会让任何一镜重烧**：这一档不进按镜缓存键，换档只重过一遍母带。
模型选了非 none 时，出片回执的 `evidence` 会带上实际消费的滤镜串；串为空而档位非 none，
就说明这趟根本没跑（而不是「跑了但看不出来」）。

**只有卡面那排按钮受枚举约束**：param_options 的每个候选值都要能从节点枚举表里反查得到，
用户手打的「+8%」这类非档位值会被第四重校验整张卡退回。而 spec 本体收任意 ±50% 的百分比
（校验器只过正则）。所以用户点了个精确百分比时：**写进 spec 顶层的 rate**，
该开关的 param_options 照常给（他会看到 +10% 那一档，勾了就以他的为准）。

配乐（BGM）给 `bgm` 参数两种写法都收：随消息附上的曲库歌曲的 **material_id**（用户从「音乐库」
点「导入并做配乐」挂上来的那条，直接原样传，别自己拼对象键），或一个 ``obj:`` 对象引用。
传了就取不到字节会直接失败，不会静默出成无声片；不传就是纯人声。
**这条路上不要调 select_BGM**：它绑在 ``generate_script`` 上，零素材片子里调它，
计划门会连 ASR、片段理解一串上游一起补齐——那串步骤对一条没有素材的片子毫无意义。
``materials.resolve`` 判归属，别人曲库里的 id 一律算不存在。
**也别把歌曲塞进 load_media**——它不是画面素材，会被当成"纯音频"丢掉。

# 出片之后要改哪里：局部改（patch_motion_video）

片已经出来了，用户说的是「第 3 镜那个数字错了」「这句字幕换个说法」「把最后那镜删掉」
「BGM 换一首」「加一层老胶片味」——这些都不该重做整片。**只有**要换画幅/帧率/音色/语速/
字幕形态，或者要加镜、换叙事结构时，才重走 plan_motion → render_motion_video（那几件是整部
片子的属性，改它们等于每一镜都要重烧，那不叫局部改）。

四种改法一次调用可以同时给：

- `edits`：逐格改值。每条 `{pointer, value, shot}`。**pointer 必须原样取自那一版成片
  命中表条目的 `field`**（形如 `/shots/1/visual/levels/2/value`）——不要自己拼字段名，
  也不要拿另一版的表来读。命中表按 `GET /motion/hitmap?artifact_id=<那一版>` 取。
  带上 `shot`（该条目的镜号）后，指针与镜号对不上就直接退你；不报错地改到别的格上，
  是这条链路最贵的失败。
- `shot_sets`：整镜改写 `{shot, set}`。`set` 里给要改的那几栏，可改字段是归一后的镜头键
  （card / text / highlight / label / panel / stamp / visual / source / min_duration_sec）。
  与 `edits` 的区别：这里**允许新增**这张卡认识的键——给 archive 卡补一行 `visual.line3`
  得走这条。镜号 `id` 在哪一种里都不许改（它是命中表、按镜缓存与对比帧共同的锚点）。
- `remove_shots`：按镜号删镜，不许删光。
- `reorder`：重排后的**完整**镜号清单，必须与现有镜号成套（漏一个就当错误——要删请写
  `remove_shots`）。重排只动顺序，一镜都不重烧。

另有 `bgm`（换配乐：素材 id 或 `obj:` 引用；配乐不进按镜缓存键，所以只重走混音）、
`texture`（换整片质感档：与配乐同挂母带，也不进按镜缓存键，所以一镜都不重烧）和
`target_duration_sec`（缺省沿用那一版当初的承诺值，显式传了才算改口）。

要知道的三件事：

1. **它改的是「那一版自己的分镜」**，不是会话里最新的 `plan_motion`。所以 base_artifact_id
   要传那一版返回体顶层的 `artifact_id`；指纹对不上会被拒收（那是「拿着旧表改新片」），
   此时唯一出路是重新出片，重新量表。
2. **它产出一条新版本**：新的 `artifact_id`、新的成片，旧版一个字节都不动，可以直接播回去、
   也可以逐镜比对（返回里的 `patch.before_frames` 是改前的代表帧）。改动会同步进会话当前
   分镜，所以你下一次重渲不会把用户的这几处编辑丢掉。
3. 与出片一样是分钟级任务：返回 `status=queued/running` 就继续调 `render_status`，
   别在提交那一轮就宣布改完了。返回里的 `evidence` 会写明这次真烧了哪几镜、
   哪几镜复用了切片——那句话是给用户看的账，照它说，别替它加「已全面复核」。

# 成本口径（为什么省着写）

画面是 headless 浏览器**逐帧截图**出来的，帧数是这条链路唯一的成本项：
15fps 是流畅下限，一条 2 分钟的片子约 1800 帧。用户嫌长请删镜或缩文案，
不要靠抬帧率（30fps 等于截图时间翻倍，画面并不会更"满"）。

省帧的机制只有一条：**动画停止之后的帧直接复用末帧**。所以成本是「会动的时长」，
不是片子总长——档案卡、图示卡入场完就冻住，一镜几帧而已。

例外是**连续动效**：`orbit` / `pulse` / `pan` 永不停止，那一个镜头的每一帧都是活帧。
`orbit` 卡尤其贵，别把它放在长镜头上，也别整条片都用。
`burst` 的 `twinkle: true` 给粒子挂的就是 `pulse`，所以一开闪，那一镜同样每帧都要截——
想要「散开之后停住」的迸发就别开它。
`pixel` 的 `poses` 属轮播：它播到「最后一格的 at+hold」才冻住，所以逐帧动画的代价是按那句
算的，把姿势排到镜头末尾等于整镜活帧——三两套姿势足够讲完一个动作。
`texture` 不在这本账上：质感档不动逐帧截图，它只在母带上多编一次。
全片帧预算上限 4000 帧，超了直接报错（要求降 fps 或删镜），不会静默截断成半条片子。
