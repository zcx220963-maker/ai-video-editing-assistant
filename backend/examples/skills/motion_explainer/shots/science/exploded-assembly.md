---
name: exploded-assembly
一句话: 拆解合体——整体先合体呈现，各构件沿半径方向撑开（轨道半径 ×1.45、核 ×1.18），每一件的引线标签在它到位时画入，电子始终绕核旋转，合回后末 30f 真静止
适用: 讲"一个东西由哪些部分组成、各部分在哪"：原子结构、细胞器、引擎拆解、心脏四腔、机械传动
时长: 180f（6s）；合体 24f + 炸开 34f + 悬停 62f + 合回 30f + 静止 30f
能量: 中高（构件逐个到位即剧情）
---

## 意图

科普片第四高频的句子是「**它里面有什么**」。现有 128 张卡里
`camera/space-camera-moves` 有一条 exploded-view，但那是产品片的 UI 构件
沿 Z 轴炸开——卡片式、二维平面、为炫技——而科普母题的拆解要的是
**同心结构沿半径撑开 + 每一件叫得出名字**。

这一张的立意：**拆解不是特效，是每一件都指名道姓。**

## 机制

| 件 | 做法 | 为什么这么做 |
|----|------|--------------|
| 合体先行 | 构件先全部出现在合体位置，静止可读 | 观众先看到「完整的东西」，再拆，才知道拆了谁 |
| 径向撑开 | 轨道半径 ×1.45、核 ×1.18 | 轴对称结构（原子/细胞/发动机）沿半径撑开才读得出层次 |
| 引线标签 | 炸开进度 0.55 之后才画入 | 标签在构件没到位时就出现，引线会指空 |
| 电子旋转 | 角度 = 帧 × 角速度，炸开不停 | 拆解中的静止是"停下来看"，不是"画面卡住" |
| 合回 | 从炸开态反插值回合体态 | 有拆无合读作"散架了"；合回后才收尾静止 |

## 参数表

| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| 构件数 | 4（核 + 三条轨道 + 三电子） | ≤2 撑不起"拆解"，≥6 时引线会互相交叉 |
| 炸开倍率 | 轨道 1.45× / 核 1.18× | 核倍率太大读作"核在膨胀"；轨道倍率太小标签挤不出去 |
| 炸开时长 | 34f | 短于 24f 构件挤在一起读不出层次，长于 50f 观众会以为片卡了 |
| 悬停时长 | 62f | 必须够读完所有标签 + 看电子转至少一圈 |

## 选型

| 什么时候用这一张 | 什么时候别用 |
|------------------|--------------|
| 结构是**同心/同轴**的（原子、细胞、发动机、手表） | 结构是**并列**的（器官各自独立）→ 用 `science/cross-section-reveal` |
| 各构件能叫出名字（电子/线粒体/活塞） | 各构件无名 → 那是色块，不是拆解 |
| 要讲"组成"而不是"过程" | 要讲"怎么变成这样" → 用 `science/growth-morph` |

## 已知坑

- **卡面必须注明模型局限**（示意模子：玻尔模型是经典模型、不是现代电子云图）。
  科普片拿过时模型当现状讲，是比没有图更坏的错。
- **轨道一律画完整圆**：椭圆读作"轨道是压扁的"，量子轨道没有这个意思。
- 电子颜色与构件颜色要有区分：电子如果和核同色，观众会以为电子是核的一部分。
- 引线**不要斜拉**：斜拉引线会穿过其他构件，读作"这条线指错了"；一律用折线
  （先水平/垂直出一段，再折到标签）。
- 核的放大不能带阴影位移：带阴影位移会读作"核在移动"，而不是"核在变大"。
- 不用 `ShotcraftMark`、不摆功能导航、不用产品截图——这一族的画面里只有这颗原子和它的标签。
