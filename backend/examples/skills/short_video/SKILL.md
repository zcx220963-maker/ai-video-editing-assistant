# 何时用这条通道

只有一条判据：**这条片子的画面是不是代码画得出来的（不需要现成影像）。**

- 用户随消息给了素材（要剪的影像/音频） → 走 `default_editing_workflow_skill`
  （load_media → … → plan_timeline → render_video）。
- 用户给的是一个**选题**（「讲讲活字印刷怎么来的」「用 60 秒解释什么是 RPC」），
  没有任何素材 → 走本通道：**`make_short_video` 一次调用出片**。
- 两条路是两个终点，不要混着排：一条片子只出一个成片通道。

**不要自己写 TSX。** 画面由 `make_short_video` 内部逐镜生成并逐帧质检；
你在外面手写组件既过不了它的设计系统，也没人给它做质检。

# 流程（四步，只有第 1 步花钱多）

0. **要不要联网，你判断；但查完必须停。** 这不是固定步骤，是决策：

   - **用户只给了一个选题、没给数字**（"讲讲 XX""为什么 XX"）→ **要查**。
     不查就只能写空话，那是这条通道最容易出的废片。至少查清：关键事实、具体数字、谁做的。
   - **用户已经给了数字和出处** → **数字直接用，不要为了核对去查**（重做一遍容易查出冲突值）。
     但**为了"怎么讲、画什么"可以查 1~2 次**：那个实验装置长什么样、有没有现成的示意图、
     别人是怎么讲这一段的。这类查询有明确终点，不是上面说的那种无底洞。
     判据：你查完能不能立刻画出来。能，就够。
   - 用户说"你帮我查一下 X" → 查，优先满足他点名的那件事。

   **先列清单，再查，答完就停。** 不要按"搜了几轮"想，按"有几个待答项"想：

   1. 从要讲的点里抽出**待核实的事实**，一句话一条，通常 4~8 条：
      "闪光滞后的原始实验参数"、"Libet 准备电位的平均值"、"缩手反射的脊髓通路时间"……
   2. **每条事实只搜 1 次**，搜完就把值记下来，哪怕不完美。
   3. 两条来源不一致 → **两个值都记下**，正片里写区间或说"有争议"。
      **不要为了找一个裁判再搜一次**——那是这类任务里最典型的无底洞。
   4. 清单答完就停。整片最多 8 次 `web_search`（清单最长 8 条，不是 8 轮）。

   判据是"清单答完了没有"，不是"搜了几次"。清单答完还在搜，就是没有终点的那种行为。
   查不到的项：用定性表述（"几十毫秒""大约三百毫秒"），或者干脆不提这个数。

   为什么写成这样（2026-10-26 真机踩过）：原来这一步叫「查资料，可以多轮」，模型为了确认
   「闪光滞后的经典实验参数」这一个数，连查 3 分钟、翻了法文维基和论文 PDF，**片子一个字都还没写**。
   搜索 API 是好的，坏的是"一个模糊问题反复换关键词"——那种问法没有终点。
   **把问题拆成一条条具体事实，每条就有了终点。**

1. **默认先出分镜**（10 秒、1 次调用）：调 `plan_short_film(prompt, seconds, aspect)`，
   把返回的 `angle`（它自己选的角度）、`hook`（开场钩子）、每镜一句字幕列给用户看。
   用户说「可以」「出吧」之后，再调 `make_short_video(scenes=<那份 plan>)` 出片。
   **只有用户明确说「直接出」「不用给我看」时才跳过这一步**。

2. **出片（一次调用）**：

   ```
   make_short_video(prompt="…", seconds=60, aspect="portrait", scenes=<plan 或省略>)
   ```

   - `prompt` 里把**讲法**写进去（「从瑞利散射讲到日落变红」），不要只写名词。
     查到的关键数字也写进去（「散射强度与波长四次方成反比」），它会进分镜。
     **用户只给了一个话题（「0」「敦煌」）也够**：分镜那一步会自己想三个角度、
     挑钩子最硬的那个，把选中的角度写进 `angle`。你不用替他定方向。
   - `seconds`：8~300。**镜数由内容定**（叙事每镜 4.5~12 秒、动效每镜 ≤5.2 秒），
     不由公式定——同样 165 秒，15 镜和 22 镜都可能对。
   - `style`：**默认 `auto`，不用你选**。系统按「这条片子有没有主角和时间」自己判。
     只有用户明确说「要动效那种」「要纪录片那种」时才填 `explainer` / `story`。
   - `bgm`：**配乐只在点名时才加，不填就不配乐**（2026-10-26 改）。
     用户把一首歌挂成附件 → 把那个附件的 `material_id` 填进来（不是文件名）；
     用户说「用曲库里那首 X」→ 填曲名 `X`。两者都搜不到就不配乐，**不要随便挑一首顶上**。
     点的那首短于片长会**循环铺满**（不换歌），所以 90 秒的歌配 165 秒的片子是正常的。
   - 这一调用要 **5~30 分钟**（时长越长越久），期间没有中间反馈。**调用前先跟用户确认
     主题、时长与画法**，别让用户盯着转圈等半小时才发现主题写错了。
   - 返回里有 `film_id`（后面改镜要用，**记住它**）、`style`、`shots`、`calls`、
     `coverage`（组件覆盖率）、`audit.ratio`（质检合格率）、`bgm`（用了哪首配乐）、
     `mp4_url`。

3. **把成片发给用户**：`mp4_url` 是一条能直接播的链接，原样贴出来。
   同时说清三条读数：几镜、质检合格率、几处转场。**不要只说「已生成」。**
   - 返回里还有 `sources`（出处）与 `sources_note`。**如果 `numbers_without_source`
     非空，就如实说一句「第 N 镜这几个数字没标出处」**，不要替用户补一个来源。
     片子已经出完，这时候补不进去了——**该查的在第 0 步就该查完**。
     这是这条链唯一一条像素判据碰不到的质量线：画面看不出 47% 是不是编的。

4. **改一镜（用户提意见时）**：

   ```
   reshoot_shot(film_id="…", shot=7, note="太阳太大、挡住字了")
   ```

   - `note` **原样填用户的话**，不要翻译成术语——模型对用户原话的理解比转述准。
   - 1 次调用、几十秒，返回 2 张这一镜的静帧链接。
   - 把静帧用 markdown 图片语法（`![s07](链接)`）发给用户看，问一句「这样对吗」。
   - **绝对不要用 `make_short_video` 重做整条**：重做既贵（24 次调用）
     又不会更接近用户想要的样子——它会把已经对的那 14 镜也换掉。

5. **认可后重渲**：`render_short_film(film_id="…")`。
   不再调模型（不花钱），但要 5~15 分钟（纯 CPU 逐帧渲）。
   改完一镜**必须**走这一步，`reshoot_shot` 只更新工程、不重渲整片。

# 文案纪律（它会直接变成画面上的字）

- 每镜字幕**≤14 字**，是画面上唯一的字，不是解说词。60 秒 15 镜就是 15 句话。
- 一句话一个意思。不要把两件事塞进一镜——那一镜的画会两边都不像。
- 不写「视频显示」「如图所示」「接下来我们看」这类说明书语言。
- 数字必须能追溯到第 1 步查到的出处；查不到就把数字删掉，改成定性描述。
  查到的出处写进 `prompt`（「据 CNNIC 2024 年报告，47%……」）——分镜导演会把它
  记进 `sources`；没写进去的数字，报告里会被点成"没有出处"。
- 全片要有递进：开场抓人 → 中段讲机制 → 收束给一句题眼。

# 常见错误（真机上踩过的）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 用户说「第 7 镜不好」 | — | `reshoot_shot`，**不是** `make_short_video` |
| 想改时长 | 时长决定镜数，改时长=改整条 | 重新 `make_short_video`，先问用户 |
| 成片有几镜偏平 | 质检打回两轮后仍不合格 | 如实说「第 N 镜我重画了两次还是偏平」，别假装完美 |
| `reshoot_shot` 报找不到工程 | `film_id` 抄错 | 先 `list_short_films()` 拿 id |
| 用户要 4 分钟以上 | 结构上限 288 秒（叙事 24 镜 × 12 秒）/ 291 秒（动效 56 镜 × 5.2 秒） | 直接说做不到，问能不能拆成两条 |
| 出来的片子像 PPT | `style` 选了 `explainer`，但内容是故事 | 换成 `style="story"` 重做一条 |
| 没有背景音乐 | ① 用户没点名配乐（不填 `bgm` 就不配乐，这是设计）② 点名了但曲库里没这首 ③ 曲库是空的 | 如实说「这条没配乐，因为你没指定」或「曲库里没有 X」；**不要假装配了**，也不要自己挑一首顶上 |
