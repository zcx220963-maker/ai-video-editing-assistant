# 视频生成链路的画风总表 + 全风格测试提示词

> 选题：**大水 / 大睡 / 薄肌 —— 极简健康三部曲**（2026 年 10 月网络热论）
> 配乐：用户自备《we never》（导入后再挂，不要从曲库挑）
> 所有数字均从代码里核出，出处标在每一条后面。

## 一、先回答那个问题：一条片子能不能装下「所有风格」

**装不下全部，但能装下全部「逐镜级」风格——而那正是画风差异的主要来源。**

链路的风格轴分两类，判据是**由谁决定**：

| 类别 | 条数 | 一条片子能装几个值 | 例子 |
|------|------|------------------|------|
| **逐镜级**（每镜自己带一栏） | **10 条** | **全部**（20 镜就能铺满） | 色板、质感、卡片、画法通道、满幅/底色 |
| **整片级**（写进 spec 顶层） | **9 条** | **只 1 个值** | 画幅、字幕档、转场、进出场 |

**为什么整片级只能一个值**——不是设计偷懒，是它们由母版/拼接层统一排班：

- `subtitle_mode`（字幕档）：`code_render.py:854` 是 `str(spec.get("subtitle_mode"))`，从 **spec** 取，不从 shot 取。
- `entrance` / `exit`：`code_render.py:858-859`，同样从 spec 取。
- `transition`：跑在**拼接**那一趟（ffmpeg `xfade`），逐镜切片一个字节都不动。
- `aspect`：`code_spec.py:783`，一个 spec 一个画幅。

所以 4 档字幕、7 种转场、5×5 进出场、3 种画幅，**一条片子各只能测一个值**。

**好消息**：这 9 条轴的测试成本**极不对等**（见第五节），补齐它们比你想象的便宜得多。

**理论上界**（朴素相乘，未扣闸约束）：
- 逐镜级：8 × 5 × 2 × 124 × 6 = **59,520 种/镜**

- 合起来 ≈ **20 亿种**。实际可用的是其中受闸约束的子集（同族≤2、纯文字镜≤1/3、通道种数、对比度≥3:1）。

### 转场 7 档怎么全测（最便宜的一条路）

**换转场不重烧任何一镜**——转场跑在拼接那一趟（`mediaops.concat` → ffmpeg `xfade`），
逐镜切片一个字节都不动。所以：

> 拿主片那 20 镜的分镜，把 `transition` 依次换成 fade / dissolve / wipeleft /
> wiperight / slideup / circleopen / none，**重出 7 条**。
> 代价只是 7 次拼接，不是 7 次重渲。

反过来**进出场要进缓存键**（母版逐帧画进切片里），改一次就是整片重烧。
所以顺序永远是「**先定进出场、再调转场**」。

## 五、配乐与旁白怎么处理（用户自备《we never》）

| 事项 | 怎么做 |
|------|--------|
| **配乐** | 提示词里写明 `bgm` 留空、**不要调 `select_BGM`**。曲库只给 4 条 BGM（`materials` 里 `origin='bgm'` 只有 4 行），你自己导入的《we never》会落进 `materials`。导入后再挂。 |
| **旁白** | 主片 `narration=true`：镜头长度归真实语音时长，**每镜不要写 `min_duration_sec`**，逐词字幕才会真的亮。 |
| **想要节奏可控** | 把主片改成 `narration=false` + `subtitle_mode=full`，每镜给固定 `min_duration_sec`——片子完全可复现，代价是失去逐词点亮。 |
| **节拍锚** | `motion.anchors` 支持 `beat:<i>`，但这条链**没做节拍检测**，`beat:` 锚今天落「未判」。**别拿它跟《we never》对齐**，那件事现在没人替你判。真判得动的只有 `subtitle:<i>` 一档。 |

## 六、三个必须知道的坑

1. **`bleed` 写成 `"true"` / `1` 会静默失效**。母版判的是严格 `=== true`，
   但校验期就会被打回（`code_spec.py:705`），所以不会静默——前提是你别绕过校验。
2. **深色板 + 不申报 `bg` = 奶油页边包着深色正文带**。这是合法观感（「暗卡纸」），
   主片里 s01/s05/s12/s19 故意这么做来测它；但如果你不想看到，就给这几镜也申报 `bg`。
3. **`imagegen` 今天不可用**。`app_secrets` 里 `image_*` 有 0 条 → 出图必降级。

# 附录：整片级算不算「死板模板」？以及 Opus 5.5 的原理对照

## A1 结论先给

**一半对。**

- **对的那一半**：整片级确实是这条链里**唯一「一刀切」的层**，而且它的僵硬是**结构性**的
  ——它跑在母版/拼接层，逐镜变化要付整片重烧的代价。
- **不对的那一半**：它不是「模板」，它是**一致性合同**；Opus 5.5 那条路线上有**同一个东西**
  （只是形态不同）。而且它**不是**「PPT 感」的来源。

**PPT 感的真正来源是逐镜级被写死**——每一镜都被 force-wrap 进同一个 `FilmLayout`、
同一个居中带子、同一个奶油底、同一条底部白圆角字幕条。这一层 R14 已经用
`bleed` / `bg` / `inline` 拆开了。

## A2 为什么整片级不是「模板」而是「合同」

如果不固定画幅、字幕档、转场，20 镜就会各自为政，**不成为一支片子**。
Opus 5.5 那条路线上做同一件事的做法是**让模型自己写一份分镜规范**。

公开源码的 MV 项目 PDoomVideo（156.6 秒）里，模型第一轮产出后自己写了 `STORYBOARD.md`，
约束了整片一致性：

- 角色设计固定，全片不变
- 配色从暖奶油色过渡到太空紫，再到警报红，最后回归
- 每个镜头里都必须有东西在动，画面不放文字
- 角色表情渐变，不允许突然跳变
- 每次切镜都由动作带出

**这就是「整片级」的野生形态。** 区别只在两处：

| | Opus 5.5 野生做法 | 本项目 |
|---|---|---|
| 形态 | `STORYBOARD.md` 自由文本 | spec 顶层结构化字段 |
| 谁保证 | 模型自觉遵守 | 机器逐镜对账（闸⑤ 等） |

## A3 你的直觉对：Opus 5.5 就是「逐镜」的

五步流水线：**规划 → 画面 → 动作 → 声音 → 拍摄与合成**。原文证据：

1. **第一步就是分镜**：「模型并不会立刻写渲染代码，而是先写脚本，再把脚本拆成一个个镜头
   （分镜）。每个镜头都要回答三个问题：**画什么、持续多久、配什么话**。」
2. **并行子智能体**：「模型按章节分工，**并行派出多个子智能体（subagent）**，
   每个子智能体负责时间轴上的一段，**各写一个 JavaScript 文件**。」
3. **逐镜渲染 + 拼接**：「几千帧可以**分发给多个浏览器进程并行渲染**，最后再按顺序拼接。」
4. **避坑经验原文**：「**长片务必分段渲染**。先按镜头渲染、确认，再整片合成，
   避免一次性长任务中途失败导致全部重来。」
5. **三条禁令**：不读系统时间、不用无种子随机、渲染中不联网
   —— 与本项目 lint 的「禁止 `Math.random` / `Date.now`」完全同源。
6. **自检方式**：「渲染出若干张静态关键帧，逐张检查**排版、重叠、可读性**，
   发现问题就回去改代码」—— 这就是闸④（画面非空/带内填充）与闸⑧（版面铺满、无叠字裁字）。
7. **局部改**：「修改一处细节**改一行代码，别处不动**」（对比视频模型「通常要整段重新生成」）
   —— 这就是 `patch_motion_code` + 逐镜缓存。

**所以「逐镜」不是某一家的专利，是这条路线（代码视频）的必然工程形态**，原因有三：

- 单文件整片会撞输出长度上限（原文：有人「3D 项目写到一半就撞上了单次输出长度上限」）；
- 逐镜才能并行渲染；
- 逐镜才能局部改 + 缓存。

## A4 本项目比「野生」Opus 5.5 多出来的，以及多花的那份代价

| | 野生 Opus 5.5 | 本项目 |
|---|---|---|
| 一致性 | `STORYBOARD.md` 自由文本，靠模型自觉 | `TOKENS` 表 + 母版 + 闸⑤ 逐镜对账 |
| 分镜 | 模型自己写 | 124 张卡 + **取材轮**（先读 demo 全文再写码） |
| 自检 | 看静帧 | 16 道闸 |
| 局部改 | 改代码重渲 | `patch_motion_code` + 逐镜缓存 |

**但代价是真的，而且 HeyGen 踩过这个坑。** 原文：

> 他们早期尝试过 Remotion，发现**框架约束加得越多，智能体的产出越保守、越雷同**，
> 换回纯 HTML 后创意才回来。

这正是「PPT 式」的另一半原因。本项目的约束密度比 HeyGen 试的还高
（16 道闸 + 强制母版包裹 + token 表 + 124 张卡）。

**但要说公道话**：闸里其实**有一半是反雷同的**——

| 意图 | 闸 |
|---|---|
| **反雷同**（逼你换画法） | ⑦ 通道配额 · ⑨ 跨镜同构 · ⑮ 版式族配额 · ⑯ 主体具名 |
| **保一致**（让 20 镜像一支片） | ⑤ token 跨镜一致 · ⑩ 字色对比度 · 母版 `FilmLayout` |
| **保可用**（不崩不空） | ①②③④⑥⑧⑪⑰㉑㉗㉕㉘ |

闸⑨ 的报错原文就是：「**只换了字与色相，没换画法。这不叫多风格，叫拼贴**」。
所以这套闸**不是在设计模板，它在主动抵抗拼贴**。真正的张力在
**母版的强制包裹**与**卡库的复用**上，不在闸的意图上。

## A5 还剩三处真实的僵硬（都在整片级，值得下一步处理）

| 僵硬 | 证据 | 后果 |
|---|---|---|
| **转场整片只有一档** | `transition_plan(spec)` 返回单个 `{style, duration}` | 不能「这一处圆开、那一处擦除」。专业动效里转场是**逐接缝**的——这是当前最像模板的一条 |
| **字幕档整片只有一档** | `code_render.py:854` 从 spec 取 | `full` 档下**每一镜都被画上字幕带**，无法逐镜免掉（`text` 是必填，母版见到就画） |
| **进出场整片只有一档** | `code_render.py:858-859` | 不能「这一镜自下浮入、那一镜轻推近」 |

三条的成因是同一个：它们都由**母版/拼接层统一排班**，而逐镜变化意味着
**进缓存键 → 整片重烧**。所以这不只是「设计得懒」，是**代价结构**决定的。

**顺带一个反直觉的成本事实**：三条里**转场最便宜**——它跑在拼接那一趟，
逐镜切片一个字节都不动，改十次也只多跑十次拼接。所以「转场逐接缝化」是
这三条里**性价比最高的一个改造**：既拿掉最像模板的一条，又几乎不增加渲染成本。

# 附录 B：为什么出片总是「PPT 式」——诊断与优化方案

## B1 诊断：四个压制机制，按压制力排序

### M1 · 闸（derived_from）要求「必须像 demo」——结构性堵死原创

```python
# code_spec.py:2661
if best < DERIVED_MIN_SIM:          # DERIVED_MIN_SIM = 0.61
    errors.append(f"闸（derived_from）{sid}：代码与声明的 demo 源文件骨架相似度 "
                  f"最高 {best:.3f} … < {DERIVED_MIN_SIM}。声明 derived_from 但代码与该 demo 无结构关联")
```

而且 `derived_from` 是**必填**：

```python
# code_spec.py:619-620
if not derived_from:
    _err(errors, f"{sid}：derived_from 为空——每一镜必须声明代码来自哪些 demo")
```

**没有「原创」这条路。** 实测数（`code_spec.py:2633-2636` 记的语料事实）：
负样本（两份不同 demo）的相似度 p98 = 0.605、max = 0.736，
**在 0.61 这一档上的通过率只有 1.690%**。

→ 写一段「不像任何 demo」的原创长代码，**几乎必然被打回**。
SKILL 也直说了：「**你不写渲染代码，你选 shot 配方卡 + 适配参数。**」

### M2 · 卡库是 video-shotcraft 自家的产品宣传片语汇库

demo 源码里的注释是直接证据：

| demo | 注释原文 |
|---|---|
| `data/timeline-travel/TimelineTravel.tsx` | 「**video-shotcraft 的版本史**（2026 年 7 月起，按月一个大版本）」 |
| `data/scroll-brake-moves/ChangelogScrollBrake.tsx` | 「假内容：**video-shotcraft 一整年的发布记录**」 |
| `effects/spotlight-sweep-moves/SlideSpotlightPan.tsx` | 「侧栏（顶部 **video-shotcraft 标志** + 字标）」 |
| `effects/icon-performance-moves/AttentionBounce.tsx` | 「主角是 360px 的 **video-shotcraft app 图标**……结尾帧是一张完整的『New in Shotcraft』海报」 |
| `effects/spotlight-sweep-moves/CornerSpotlightReveal.tsx` | 「把白色 **video-shotcraft 镜头库界面**逐步『点亮』」 |

数量上：`<ShotcraftMark`（Shotcraft 自家 logo）出现在 **约 85 / 158 份 demo** 里。

### M1 × M2 复合 —— 这才是「PPT 式」的机械原因

> 闸逼你**保留 demo 的画法骨架** ＋ demo 骨架是**产品宣传片** = 一支科普片画面上
> 全是**侧栏、看板、Changelog、Dock、⌘K 面板、卡片堆叠、carousel**。

**不是母版造成的。** 母版只决定「框多大、底色是什么」；决定「画的是什么语汇」的是卡库。

### M3 · 默认值全在保守档——能力有了但不会被用

| 常量 | 默认值 | 出处 |
|---|---|---|
| `FILM_STYLE_DEFAULT` | `{ bleed: false, bg: '' }` | `tokens.ts:182` |
| `transition` | `none` | `code_spec.py:825` |
| `entrance` / `exit` | `none` | `code_spec.py:851` |
| `texture` | `none` | `code_spec.py:817` |

R14 加了 `bleed`/`bg`/`inline`，但**默认一个都没动**。SKILL 里 `bleed` 的措辞是
「画整屏插画的镜头就写它；**常规图文镜留省略**」——默认偏向保守。
→ 模型不主动写，20 镜还是 20 个居中带子。

### M4 · 多样性没有闸在判——只有「反雷同」，没有「逼丰富」

| 已有（反雷同） | 缺失 |
|---|---|
| ⑦ 通道种数 ≥3/4 | **色板种数** |
| ⑨ 跨镜同构 ≥0.88 打回 | **质感种数** |
| ⑮ 版式族配额（同族≤2） | **满幅镜占比** |
| ⑯ 主体具名 | **`bg` 申报率 / 母版两态** |

→ 一条 20 镜片可以**全用一套色板 + 一种质感 + 全常规版式**而照样过闸。

**好消息：基础设施已经有了。** `shot_colors(code)` 已经能认出每镜绑的是哪套色板：

```python
# code_spec.py:3088-3089
return {"surfaces": surfaces, "inks": inks, "unresolved": unresolved,
        "palette": palette_name}      # ← 已经在了
```

## B2 优化方案：四层，按性价比排序

### 层 A · 改文档与默认倾向（零渲染成本，改完重烤即生效）

- **A1** SKILL：`bleed` 从「可选」改成「**深色板必须写** + 每 5 镜至少 1 镜满幅」。
- **A2** SKILL：把「模型只选档，不自由搭配」改成「**逐镜自由配色板，8 套都要用上**」。
- **A3** SKILL 新增「**反 PPT 语汇清单**」：明确禁止「侧栏 / 看板 / Changelog / Dock /
  ⌘K 面板 / 卡片堆叠 / carousel / 光标协作」这类**产品宣传片语汇**出现在科普片里，
  并要求改用曲线 / 剖面 / 地图 / 示意图 / 时间轴 / 比喻。
  → 这条**直接打 M2**，成本几乎为零。

### 层 B · 新增「风格配额」闸（最高杠杆）

**闸⑱ 风格配额**，判据候选：

| 判据 | 建议阈值 | 可行性 |
|---|---|---|
| 色板种数 | ≥ `ceil(n/4)` | `shot_colors()["palette"]` 已能认出 |
| 质感种数 | ≥ 3 | `texture` 是归一后的字段，直接数 |
| 满幅镜数 | ≥ `n/5` | `bleed` 直接数 |
| `bg` 申报率 | ≥ `n/4` | `bg` 直接数 |
| 母版两态 | 满幅与常规都要出现 | 同上 |

建议**先只出提醒**，跑一批片子观察误报率再升打回——与闸⑨ 的「宁可漏报，不许误报」同一条纪律。

### 层 C · 给「原创」开一条路（打开上限，但要防漂）

- **不能简单降 `DERIVED_MIN_SIM`**：负样本 p98=0.605 / max=0.736，
  降到 0.61 以下会让「两份不同 demo」也通过（假阳性）。
- **正确做法是加哨兵**：允许 `derived_from: ["<original>"]`，闸跳过相似度比对，
  但**要求这一镜的代码过全部 lint + 闸④⑧⑩**（即「原创」不等于「免检」）。
- 配一个**配额**：一条片子最多 20% 的镜走原创，既放创意又不让整片漂。

### 层 D · 补内容（最治本，工程量最大）

- **D1 补科普向卡库**：曲线 / 剖面 / 地图 / 时间轴 / 示意图 / 比喻族——
  脱离产品宣传片语汇。**这是唯一能真正抬高上限的一条**（因为 M1+M2 意味着
  「风格上限 = 卡库上限」）。
- **D2 静帧审美评审**：项目已有 `judge_*` 密钥（`judge_model=jev-latest`），
  出片后拿代表帧给 judge 打分，把闸④ 从「有没有画东西」抬到「画得好不好」。
  —— 这正是 Opus 5.5 那条路线上的「渲染静帧逐张自检」。

### 层 E · 整片级解绑（成本最低）

- **E1 转场逐接缝化**（0 镜重烧）。
- **E2 字幕档逐镜覆盖**。

## B3 一句话总结

> 「死板」的**框**（母版）R14 已经拆了；「死板」的**语汇**（卡库 + 必须像 demo 的闸）还在。
> **框决定它像不像 PPT，语汇决定它像不像产品发布会。** 现在缺的是后者。
