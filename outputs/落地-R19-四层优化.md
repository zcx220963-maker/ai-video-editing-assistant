### 层 B —— 闸⑲ 风格配额（`code_spec.check_style_variety`）

```
色板种数 ≥ ceil(镜数/4)     结构判据 → 打回（20 镜 → 5 套；「1 套色板」直接点名）
满幅镜数 ≥ ceil(镜数/5)     结构判据 → 打回（20 镜 → 4 镜；报「只有 0 镜满幅…像 PPT」）
质感种数 ≥ 3                程度判据 → 只提醒
bg 申报率 ≥ 25%             程度判据 → 只提醒（满幅镜不给 bg 也在这里）
一镜都认不出色板            → 第三出口「未判」，不与「通过」同格
镜数 < 6 不判               三镜片用三套色板是常态，不是纪律
```

`style_facts` 新增四栏供计划卡与出片回执读：`palettes`（逐镜色板）/ `bleed_shots` /
`textures` / `original_shots`。白名单口径沿用闸⑨「宁可漏报，不许误报」那条纪律。

### 层 C —— 闸⑳ 原创哨兵 `<original>`

- `derived_from: ["<original>"]` 跳过闸⑫ 的骨架相似度比对（声明里没有 demo，无从比起）。
- **哨兵必须单独出现**：与真 demo 混在一个列表里当场打回（否则「每镜都挂哨兵」只差一步）。
- **配额 ≤ 20%**（`max(1, int(n*0.2))`；6 镜片的上限是 1 镜）——卡库仍必须占多数。
- **原创不等于免检**：照旧过闸①④⑧⑩。
- 取材轮遇到纯哨兵行不报「读不到」、也不回字节。

> 为什么不直接把 `DERIVED_MIN_SIM` 从 0.61 降下来：语料实测负样本（两份不同 demo）
> 相似度 p98 = 0.605、max = 0.736，**在 0.61 上通过率只有 1.690%**——降了会假阳性。

### 层 E1 —— 转场逐接缝（0 镜重烧）

`transition_plan` 重写成 `{"style", "duration", "seams"}`，`seams` **只列被覆盖过的那几处**
（`{"after": 镜号, "style", "duration"}`，只遍历 `shots[:-1]`）。为什么是「只列覆盖」而不是
「逐接缝铺平」：铺平之后「整片 fade、这一处没覆盖」与「整片 none、这一处 fade」在账面上
长得一样，而它们在画面上是两件事。

`seams_to_per_index` 负责摊平（未覆盖记 `("", 0.0)`——**空串是「没覆盖」不是「硬接」**）；
`mediaops._seams_of` 归一，`_concat_xfade` 支持**硬接与叠化混在同一条链上**。

### 层 E2 —— 字幕档逐镜覆盖

`shot_input_props` 逐镜优先（`shot.get("subtitle_mode") or spec.get(...) or "full"`）。
母版那侧**不用改**——它读的还是同一个 `subtitleMode` 键，「整片一档」与「逐镜覆盖」
在它看来是同一件事，区别只在注入时谁赢。

缓存键：整片那一档本来就在 `FILM_KNOBS` 里；**申报过覆盖时才再加一项**（与 `reveal` /
`film_style` 同一写法——无条件加会让所有既有镜的键全变、整片白烧一次）。
`TOKEN_PER_SHOT_KEYS` 加 `subtitleMode`，否则闸⑤ 会把「这镜 inline、那镜 full」
判成「母版常量漂移」而当场判死。

## 3. 层E1 真渲红过两次（只有「硬接与叠化混在一条链上」才会走到）

| # | ffmpeg 报错原文 | 根因 | 修法 |
|---|---|---|---|
| 1 | `pad 1 (audio) 接到了视频输出` | 硬接分支只喂了两个视频口，`concat` 要「每段先视频再音频」四个口 | `{vprev}{aprev}[vin{k}][ain{k}]concat=n=2:v=1:a=1[v{k}][a{k}]`（与老路那份 `[i:v:0][i:a:0]` 同一顺序） |
| 2 | `First input link main timebase (1/1000000) do not match … xfade timebase (1/10)` | `concat` 吐出来的流时基是滤镜默认的 1/1000000，没经过 concat 的那一路还停在输入文件的 1/10 | `norm_v` 里加 `settb=AVTB` |

**纯叠化（老用例）与纯硬接都碰不到这两条**——这就是为什么层E1 必须真跑 ffmpeg，
只断言账面档名验不出来。

## 4. 收尾时补的两处：新能力差点没有编辑入口

`code_patch.EDITABLE_SHOT_FIELDS` 是整镜改写**唯一**的白名单，不在里面的栏会被答成
「这一镜没有的栏」。层E 加了两个逐镜栏，却没加进白名单——等于**新能力没有入口**：

- 加 `subtitle_mode` / `transition`。
- 顺手纠正了那份白名单的注释：它原先写着「= `validate_code_spec` 归一之后的镜头键」，
  而实际**故意窄**——`card` / `derived_from` / `subject` / `subject_channel` / `assets` /
  `motion` / `reveal` 这七栏是**申报**（闸⑮⑫⑯⑪㉑㉗ 各有一道在读），
  **改申报而不改代码＝让闸读到假的**（把 `card` 从 A 换成 B 而代码还是 A 的形状，
  闸⑮ 会以为这一族又多了一镜）。改它们必须连 `code` 一起重交。
- `SKILL.md` 三节补上逐镜覆盖的写法：转场节（含「末镜写无效」「整片 none 时覆盖取默认时长」）、
  字幕模式节（含「改它要重烧被改的那几镜」的成本提醒）、局部改节新增第 4 条。

## 5. 端到端真渲取证

### 5.1 层E2：整片一档 vs 逐镜覆盖，谁在母版的像素上赢（2×2 矩阵）

同一份镜头代码，只改注入的 `subtitleMode`（走真链 `validate_code_spec` → `shot_input_props`），
四格各真渲一次，量**字幕带矩形里「与底色差得远」的像素占比**
（有字幕条时里面是一块浅底板 + 深墨字 + 一块粉色高亮；没字幕条时是纯底色——
镜头代码画的东西全在画面带里，碰不到这条）：

```
A  整片 full   + 镜上不覆盖  → 注入 full   母版回执 full    3.914%（2046 px）  字幕条在
B  整片 full   + 镜上 inline → 注入 inline 母版回执 inline  0.000%（0 px）     字幕条没   ← 逐镜赢
C  整片 inline + 镜上不覆盖  → 注入 inline 母版回执 inline  0.000%（0 px）     字幕条没
D  整片 inline + 镜上 full   → 注入 full   母版回执 full    3.914%（2046 px）  字幕条在   ← 逐镜赢
```

**15/15 通过**。两条反向对照都成立（不是「inline 一律没字幕」），
且四格两两归到同一个母版取值上。重烤镜像后重跑，读数**逐字相同**。
