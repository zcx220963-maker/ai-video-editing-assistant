## 2. 洞在哪（先摆证据）

`review_loop.py` 把两个名字写死在常量里：

```python
FRAME_CHANNEL_MODULE = "storyline_server.motion.judge_channel"
FRAME_CHANNEL_ENTRY  = "judge_frame"
```

然后 `frame_channel()` 探它：

| 探到什么 | `capability()["available"]` | `run()` 走到哪 |
|---|---|---|
| 模块 + 入口都在 | 取决于裁决通道 | 真回看 |
| **模块不在（R19 之前的今天）** | **恒为 False** | **`raise ReviewBlocked(...)` → 阻断出片** |

而 `code_render.render_code_motion` 早就把回看环接在拼接之前了
（`review_loop.run(...)`，`review_loop.REVIEW_KNOB = "review"`）。
**结果是：`review=true` 的每一片都必红**（前提是有红镜；没红镜时它走「没有目标」那条早退）。

合同侧也对得上：`REMOVIDE_ADDENDUM_R13_IMAGE_SUPPLY.md` 的 **Q163** 原文是

> 回看环与 `judge_channel` 这一卷管不管？—— **管，但只做失败前置**：`review=true` 且
> 看图腿不存在时，在烧像素之前打回并点名（T73）。**不在本卷补 `judge_channel`**
> ——它是 **R11 的账**（§12 第 4 条）

也就是说：R13 明写「帧通道不归我，是 R11 欠的」，而 R11 那一卷也没交。这一次补上。

## 3. 落了什么（三块）

### 3.1 `backend/storyline_server/motion/judge_channel.py`（新建）

**① 帧通道 `judge_frame`（T31 的交付件）**

调用形状按 `review_loop.ask_frame` 写死的那一份，一处声明：

```python
await fn(gate="26", shot=sid, image=frame, columns=五栏,
         reasons=[既有闸判红的原文], shot_spec=该镜 spec（含现有代码）,
         round=i, terms_field=..., subject_terms=...)
→ {"ok": bool, "code": str|None, "reason": str}
```

递过去的三样各有各的用处：`image` 是**画面本身**（这一环存在的全部理由：几何读数
说不清「画面上是一枚徽章还是一张脸」）、`columns` 是母版量到的原始读数、`reasons` 是
既有闸判红/未判的**原文**。返回的是**代码提案**，不是判决——它还要过
`plan_code_patch` → 再归一 → 再渲染 → 再回闸，四道都过了才算数。

三个出口，**不许合并**：

| 出口 | 形状 | 回看环怎么读 |
|---|---|---|
| 真改出了新代码 | `ok=True, code=TSX` | 走补丁腿 |
| 看了，不用改（`NO_CHANGE`） | `ok=True, code=None` | 记 `not_run`（账上没有第二次切片，**不是**通过） |
| 模型没吐东西 / 通道炸了 | `ok=False, code=None` | 记 `not_run` + 一句原因 |

**② 自证 `self_test`**

两支夹具必须被**分得开**：① 单个放大部件（㉕ 的红样形状）② 两部件场景（㉕ 放行的形状）。
用 ffmpeg 现场画两张探针图（不往仓库塞二进制资产），递给帧通道读「有几个彼此分离的部件」：

- 读成 `1 / 2` → `ok=True`
- 读成 `2 / 2` → `ok=False`（**量过、判据不灵**）
- 造不出图 / 调用失败 → `ok=None`（**未判**）

「分不开」与「没做」在回执上是两句话——混成一格就是拿一个假的自证把回看环放行。

**③ 静帧审美评审 `review_still`（层 D2）**

**两段，各用各的零件**：

```
frame.png ──[read_frame：多模态读帧]──▶ 结构化读数（眼）
                                          │
判据正文 Q 组 ─────────────────────────┐  │
                                       ▼  ▼
                        agent_framework.judge.judge()  ← 尺
                                       │
                                       ▼
                        {verdict, confidence, reading, criteria, why}
```

**为什么非要两段**：`judge()` 的输入是文本（`state = {reply, facts}`），**它看不见像素**。
而「画得好不好」离开画面就问不出来——拿一栏几何读数去问审美，得到的只会是模型对着
数字编的一句漂亮话。所以帧通道出「眼」、判断模型出「尺」。

读数里**不许有结论**（不许有 `good` / `score`）——结论归 `judge()`。两段混在一起，
「判据面其实没被用上」这件事就在回执上消失了。

**判据面从技能正文读**：`criteria_ids()` / `criteria_digest()` 抽
`examples/skills/motion_explainer/aesthetic-rules.md` 的 Q 组（Q1–Q11，现得 11 条）。
**不在这里抄第二份**——抄一份的表现是「正文改了条目、评审还在用旧的那几条」。

### 3.2 `backend/storyline_server/motion/code_render.py`（+约 90 行）

- 新常量 `STILL_REVIEW_KNOB = "still_review"`，读法与 `review_loop.REVIEW_KNOB`
  **完全一致**（`spec` 里那一栏），**默认关**。
- 新函数 `_still_review(spec, ledger, files, *, scanned)`：逐镜取 `files[sid]["frame"]`
  （`_render_shots` 已经把它放在那儿了）→ 调 `review_still` → 摊成三出口回执。
- `render_code_motion` 在**母带出好之后**调它，并把回执挂进返回字典的 `"still_review"`。

**默认关的理由与回看环逐字相同**：这一档是**逐镜一次多模态调用**，是这条链上最贵的一类。
它只把闸④ 的射程抬高一档，关着不会让问题片子溜出去；反过来默认开会替所有人花掉这笔钱。
「花钱的能力必须能被人关掉」（BGM / 质感 / 转场 / 回看都是先例）。

**它不拦交付。** 闸④ 的两半（非底色占比 / 填充度）是**机器判据**、红了出不了片；
这一半是**提醒**，永远不打回——「像素上有没有东西」与「好不好看」是两件事，
前者管出不出得去，后者如实报出来给人看。

## 4. 三条不许被弄松的纪律

1. **不另起 judge 客户端**（Q90/Q91）。裁决一律走 `agent_framework.judge`；
   键位/优先级链只在 `secrets.py` 那一处。测试里有一条**结构断言**：
   `judge_channel.py` 源码里不许出现 `urllib.request` / `httpx` / `aiohttp` / `requests.post`。
2. **任何失败＝未判，绝不阻塞交付**（`judge.py` 的纪律逐字照搬）。
   未配置＝完全不启用；调用失败＝`None`；低置信＝`None`。
3. **三出口不许合并**。「没配置」「跑了但失败」「判绿」在回执上是三句话。
   测试对每一组各有一条断言。
